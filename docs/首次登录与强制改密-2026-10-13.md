# 首次登录与管理员重置后的强制改密

本批补齐缺口清单中的强制改密闭环。邮件渠道、忘记密码、个人资料编辑、会话设备管理和多级审批仍是独立待办，整份清单尚未完成。

## 账号规则

- 增加 `User.must_change_password`；迁移 `auth_app.0004` 为已有账号填 `False`，不改变原密码、角色或会话版本。
- 用户管理新建账号默认要求首次改密，创建表单可以明确关闭；API 创建缺省为 `True`。
- `minimal`/`standard` 全新库初始化管理员要求改密；重复初始化只跳过已有账号，保留其当前状态。开发演示初始化维持演示用途；公开注册由用户自行设置密码，不强制再次改密。
- 管理员重置默认要求改密；重置对话框与 API 都允许明确关闭。重置增加会话版本，包含重置成相同密码的情况，立即撤销全部旧 JWT。
- Django 管理后台新建账号和重置密码也要求改密；状态只读，不能从普通资料编辑接口解除。

## 服务端与前端

- 待改密账号可以登录、刷新凭据、读取 `/auth/me/`、修改密码或退出。业务 API 由 JWT 认证层拒绝，返回 HTTP 403 和 `data.reason=password_change_required`；超管也不能绕过。`me` 暂不返回业务权限。
- Django 会话认证也限制待改密账号访问，管理后台仅允许退出，提示从系统登录页改密。匿名品牌、健康检查等公开端点仍保持公开性质，不属于受保护业务访问。
- 改密必须验证当前密码、两次新密码及 Django 当前用户密码策略；拒绝新旧密码相同。失败保持密码与限制不变。
- 改密和管理员重置在事务中锁定用户；自行改密在锁内复核凭据版本和密码声明，避免等待期间重置/撤销导致陈旧请求覆盖密码。成功改密清除限制并增加会话版本，旧 access/refresh 全部失效，需用新密码重新登录。
- 自行改密与管理员重置写入审计，只记录操作与强制改密选择，不记录密码或令牌。
- 独立 `/change-password` 页面不加载业务菜单或模块。路由、API 403 和全局每 30 秒/聚焦权限刷新均识别状态；进入改密页重新读取当前用户，避开旧缓存。
- 改密表单与个人设置复用同一组件：关联标签、当前/新密码自动填充提示、显隐密码、字段校验、可聚焦错误提示、提交期间禁用输入和重复提交保护。成功清理本地 access/refresh 并回登录页；失败保留表单供修正；允许退出。
