# 通知订阅与免打扰深化

本轮交付当前租户下的个人事件订阅、渠道偏好和站外免打扰。沿用既有 Outbox、投递有效期、权限复核和可靠重试；不新增常驻服务，也不启用关闭的邮件、短信或 Webhook 集成。

## 已登记的事件

| 事件 | 当前接入范围 | 个人策略 |
| --- | --- | --- |
| `system.notice` | 既有 `Notification.push` 系统通知；包括管理员按系统类型发送的站内通知 | 站内副本必须接收 |
| `approval.action` | 既有审批待办、审批结果、催办等 `approval` 类型的站内通知 | 站内副本必须接收 |
| `task.result` | 既有任务失败、自动备份失败等 `task` 类型的站内通知；未新增所有任务成功通知 | 站内副本必须接收 |
| `announcement.update` | 通过 `Notification.push` 发送的公告提醒 | 可退订 |
| `template.message` | 模板消息的站内、邮件、Webhook、短信投递 | 可退订，也可单独关闭渠道 |
| `business.update` | 已提供显式 `event_code` 接入入口，尚无新增业务生产者 | 可退订；不会凭订阅获得数据权限 |

必须接收仅保证已登记事件的站内副本，不强制将所有系统、任务和审批事件经所有外部渠道发送。认证验证码邮件继续走独立的认证流程，不受个人订阅和免打扰影响。现有全员公告共享列表不因个人退订隐藏；该事件设置作用于个人通知提醒。

## 操作入口和数据契约

- 通知中心列表页新增“通知偏好”，普通已登录用户可管理本人设置；要求修改初始密码或模块关闭时不可操作。
- `GET /api/v1/notifications/preferences/` 读取本人当前租户的设置，没有记录时返回默认值，且不创建记录。
- `PUT /api/v1/notifications/preferences/` 完整替换个人设置，使用 `revision` 乐观锁；首次写入版本为 `0`，写入后的版本为 `1`，旧版本返回冲突。
- 设置项为可选事件 `subscriptions`、四种渠道 `channels`、`quiet_enabled`、分钟精度的 `quiet_start/quiet_end` 和 IANA `timezone`。未知字段、未知事件/渠道、重复选项、非法时区、相同起止时间均拒绝。
- `available_channels` 表示部署已启用的渠道；个人勾选不会改变服务器开关。默认全部订阅、全部渠道、免打扰关闭，时间为 `22:00–08:00`，时区为 `Asia/Shanghai`。
- 新表 `NotificationPreference` 经迁移 `0010_notification_preferences` 创建；单租户空作用域和各个租户分别保证每位用户只有一条设置。
- 更新本人设置使用既有写授权、用户锁和审计事务；审计失败时回滚设置。响应禁止缓存，前端在用户、会话、租户、模块状态变化时取消请求并丢弃旧响应。

## 投递边界

站内收件箱立即写入；可选事件退订或站内渠道关闭后不写入可选个人通知，系统、审批和任务的必须站内副本仍保留。批量写入显式设置租户归属。

模板消息在发送前先复核发送者、会话、收件人、租户、模板、渠道以及已验证目的地址，之后才应用偏好。租户必须正常，收件人必须仍是有效成员，即使收件人是平台管理员也不能绕过成员检查；平台管理员发送者保留既有发布权限规则。退出、暂停或关闭后的待发消息终止，不能被订阅设置重新授权。

站外模板投递处于免打扰窗口时，准备阶段抛出 `DeliveryDeferred(until)`，不递增投递尝试。主派发器将 Outbox 恢复为待处理、归还本次领取计数，并以“领取次数和租约时间”双重条件更新，避免迟到的旧领取覆盖新的状态。续发时重新复核权限和偏好。退出租户、租户关闭、撤权、禁用渠道及改变目的地址均优先于免打扰。

跨午夜窗口和夏令时转换按真实 UTC 分钟寻找免打扰结束时间，避免构造不存在的本地时间。延期不延长原始 24 小时有效期，超过有效期即终止。免打扰结束前更改设置不主动唤醒已经延期的消息；消息在已登记的下次领取时间复核最新设置。

订阅关闭导致 `recipient_preference_disabled` 终止，不产生实际投递尝试。完成权限快照后已经开始发给供应商的请求无法撤回，沿用既有投递边界。

## 本轮验证

隔离测试使用项目 testing 配置和 SQLite 测试库，不连接运行库；外部邮件仅使用 Django 内存邮件后端，无真实对外发送。证据位于 `.codex-validation/notification-preferences-20261018/`。

- 后端通知偏好、既有通知/模板/外部渠道、多租户、任务可靠性和 Outbox 重试锁定：138 项通过，`backend-final.xml`。
- 补充免打扰延期期间退出租户、租户关闭和租户暂停，再次领取均不发送邮件：3 项通过，`backend-deferred-tenant.xml`。
- 前端通知偏好组件：11 项通过，覆盖加载/错误/重试、保存冲突保留输入、必须通知、关闭渠道提示、身份切换、取消旧请求和重复提交；`frontend.log`。
- 应用 `vue-tsc --noEmit`、测试 `npm run test:typecheck` 和相关前端文件 ESLint 通过。
- `makemigrations notifications --check --dry-run` 通过，没有模型迁移漂移。

没有在此子任务执行全量后端、PostgreSQL 并发、真实浏览器或服务器部署验收；由主任务统一整合验证。未启动开发服务器、watcher 或持久进程，无新增端口需要释放。

## 仍需后续深化

本轮不代表通知中心方向全部完成。后续同日增量已补显式 V2 业务提醒摘要和当前租户运营统计，见[业务通知摘要与运营统计](./业务通知摘要与运营统计-2026-10-18.md)。升级提醒策略、提供商送达/阅读回执仍待后续；业务更新事件需要具体业务模块显式接入。当前个人设置为事件订阅集合与全局渠道集合，不包含“每个事件各选不同渠道”、节假日日历或按星期设置免打扰。
