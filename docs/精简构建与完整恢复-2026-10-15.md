## 使用命令

先按现有文档设置 `.env` 中的强密钥/数据库密码/初始化管理员密码。以下命令不会删除数据卷；不能使用 `down -v` 切换在用项目。

全新精简项目：

```powershell
docker compose -f docker-compose.yml -f compose.minimal.yml -f compose.build-minimal.yml build backend frontend
docker compose -f docker-compose.yml -f compose.minimal.yml -f compose.build-minimal.yml up -d --wait db backend frontend
```

已有标准项目转物理精简时，先备份并验证恢复路径，再停止 `worker`/`beat`，执行上方构建/启动命令，确认核心服务就绪后停止 `redis`。Compose profiles 不会自动停止原来运行的容器。媒体卷和数据库沿用；已配置 S3 或图片处理的项目先按存储迁移文档完成数据/配置切换，不能只覆盖变量。

恢复完整标准项目时，检查 `.env` 中 `ADMINCORE_PRESET=standard` 及完整模块列表，移除两个精简覆盖后同步重建：

```powershell
docker compose build backend worker beat frontend
docker compose up -d --wait
```

原管理员密码不会被初始化密码覆盖，原用户/文件/参数/迁移记录保留。只重建后端会造成精简前端与模块契约不一致，页面会阻止加载并提示同步重建。`check_modules --modules=files` 为只读预检，在精简镜像返回 `requires_full_build: true`；它不会启用模块或改写数据库。

## 构建边界

- Python 精简直接依赖19个、锁定包53个；完整分别31/82个。精简锁必须是完整锁的同版本子集，复用完整锁的 SHA256；离线检查拒绝版本漂移、摘要改变及被裁剪的重依赖。更新依赖时需要同时轮转两套锁。
- 精简镜像不安装 pandas/numpy/openpyxl/pypdf/boto3/botocore/django-storages/nh3、pytest/django-extensions；源码、Django 模型和迁移仍保留。它不是按任意模块组合自动求最小依赖的系统。
- 前端构建阶段仍安装完整 npm 工具链；最终 Nginx 产物排除可选模块页面、PDF 字体/CMap/worker、富文本编辑器及 Excel Worker。仪表盘图表和日志虚拟表格属于核心页面能力，继续按需加载。
- 镜像内写入固定构建标记，运行时同名环境变量不能把精简镜像升级成完整镜像。源码开发默认 full；不要在工作区手工创建镜像标记。
- 导出的项目仍使用现有运行时预设，未自动改成物理精简；本覆盖可以显式用于导出后的项目。精简单进程本地缓存不适用于共享限流的多副本部署。
- 演示模式及演示重置仍待实施；本批不代表演示预设验收。
