# 岗位与人员选择器

状态：已验收，2026-10-14。本批实现清单 P1 的岗位/职位与通用人员选择器，并接入单级审批。

| 验收字段 | 本批约定 |
|---|---|
| 功能范围 | 岗位编码、名称、说明、排序、启停及多人多岗位任职；部门树、姓名/用户名搜索及服务端分页的单选组件；审批按所选用户 ID 提交。岗位不授予角色权限，无职级薪酬、主岗、多级审批或批量任职。 |
| 默认是否启用 | 岗位随 organization 模块，标准/演示默认启用，minimal 默认关闭；人员组件按用途访问接口，审批随 approvals 启用，组织关闭时仍可搜索人员。配置改变需重启，不新增运行进程。 |
| 外部依赖 | 既有数据库、组织模型、权限、审计与审批模块。无需新的第三方服务或依赖包；查询失败展示重试并清除旧结果。 |
| 权限与数据范围 | 岗位及任职延续组织管理的管理员边界并登记 post:read/post:update；沿用本项目 staff/superuser 的权限通配规则。升级只登记新权限，不自动扩充已有角色。目录仅返回 ID、用户名、姓名和当前启用部门；审批目录与最终提交共同执行 user 范围，无范围时沿用原来的启用账号规则。 |
| 关闭后的行为 | organization 关闭，岗位/任职 API、菜单和页面撤下，表和历史保留，迁移仍可执行；审批目录隐藏部门并拒绝部门筛选，但 user 数据范围照常生效。approvals 关闭，审批及专用目录不可访问。 |
| 可重复验收 | 后端 402 项、桌面/375px 浏览器 156 项、独立 PostgreSQL 155 项检查、lint/类型/构建/schema/迁移检查通过；源码提交 9220435 的远端四项 CI 成功，详见下方证据。 |

任职唯一约束为用户与岗位组合；同人可拥有多个岗位。停用岗位或账号不删除任职，但拒绝新任职；有任职的岗位不能删除。删除人员沿用既有用户硬删除策略，关联任职随人员删除。管理写入与删除要求版本，陈旧版本返回 409；更新锁岗位，新增任职按岗位→用户锁定，任职删除按岗位→任职锁定。

目录默认每页 10、上限 100；搜索最长 100 字符。部门只列可见人员实际所属的启用部门，隐藏上级不泄漏名称，最多 1000 并明确标记截断；岗位选项最多 1000，超限明确失败。完整岗位和任职管理列表仍使用标准分页。浏览器取消请求是体验保护，提交时服务端重新检查活跃账号和范围。
