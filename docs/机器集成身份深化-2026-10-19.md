# 机器集成身份深化

下方验收段保留分任务当时的失败与待整合状态。后续整合、全量 CI 及部署结论见 [最终深化验收](功能深化服务器部署验收-2026-10-19.md) 和 [后续修复发布](全系统修复发布验收-2026-10-19.md)；当前发布入口见 [兼容性记录](../COMPATIBILITY.md)。服务器开放平台仍按约定保持关闭，不能把隔离机器身份验收当作服务器已开放该能力。

本批把外部系统的身份与个人账号分开：管理员创建独立机器身份，绑定专用只读角色，再签发只展示一次的 API 密钥。创建人改密、停用、离职或删除不影响该机器；机器自身停用、角色或权限撤回、租户停用会阻止后续请求。继续保持 `api_credentials` 模块默认关闭。

## 使用和权限

1. 启用开放 API 模块，在角色管理创建仅含已开放只读能力的专用角色，配置数据范围及字段策略。
2. 当前管理员进入“开放凭证 → 机器集成身份”，提供当前密码创建身份并授予角色。普通成员即使持有 `api_credential:manage` 也不能进入独立管理入口；管理员只能授予其当前可授范围。租户成员的 `admin` 角色不等于平台管理员。
3. 为身份签发具有明确名称、只读能力及到期时间的密钥。调用方式为 `Authorization: ApiToken ac_…`，只接受独立开放 API 地址；不能访问普通用户、管理、交互登录或写入接口。
4. 轮换密钥立即替换旧摘要，旧密钥失效；并发轮换仅一个版本成功，其余返回 409。撤销不可恢复。停用身份永久撤销此前全部密钥，重新启用须重新签发。

密钥本体不落数据库、不放 URL 或审计；前端关闭弹窗、换身份、切租户、撤权、切会话及离开页面后清空密钥，迟到响应不得重新展示。API 返回 `no-store`。每次变更要求当前密码，事务内复核管理员、会话和授权；请求体不接受未登记字段。

## 身份和租户约束

- 机器由不可交互的 User 和独立 ServiceIdentity 构成，`is_service_account` 创建后不可转换。禁止登录密码、管理员标志及个人联系方式；普通用户 CRUD、批量操作、密码重置、组织成员/任职/岗位、普通租户成员管理及普通角色分配入口均不能维护该主体。
- JWT 会话签发与验证、刷新、SSO 登录/绑定、密码找回、Django admin 登录及公共事务写授权显式拒绝机器。即使数据库被错误写成有密码或 staff，交互边界仍拒绝。通过 QuerySet.update、直接 SQL 或具有数据库权限的维护者不属于应用层可阻止的攻击者。
- 多租户开启时，机器固定属于创建时租户。没有租户请求头时使用固定租户；不同租户请求头、失效成员资格、失效租户、租户模式切换不匹配均拒绝。额外成员关系不能切换机器归属。
- 普通人员搜索、人员候选、通知收件人及组织维护不暴露机器；审批解析及历史重试入口由审批边界同步排除机器。
- 每次开放请求检查当前身份、凭证版本、到期与撤销、当前角色和能力。专用角色后来被加入管理或写入权限时整个机器授权失败，不能借污染角色打开写入或交互能力；行范围与字段读取继续复用显式登记的只读网关。

## 限额和兼容

每租户（单租户模式为全局）最多 100 个身份；停用身份仍计入总量。多租户使用 Tenant 行锁，单租户 PostgreSQL 使用事务 advisory lock 串行化跨管理员配额检查，防止并发突破上限。每身份最多 20 个当前有效凭证，管理列表仅展示最近 100 条凭证。密钥有效期复用已有 5 分钟至 90 天约束；界面提供 1 至 90 天。角色选择接口扫描按名称排序的前 201 个当前活跃角色并筛选可授角色；超过该规模应补分页，不能推断为无限角色目录。

新增迁移 `auth_app.0011_user_is_service_account` 与 `api_credentials.0003_serviceidentity`。存量用户默认仍是普通用户，旧个人开放凭证仍按原账号密码与会话撤销规则运行，机器凭证不依赖创建人的密码摘要。后端 SDK 将机器对象命名为 `ServiceIdentity`，避免与 SSO `Identity` 组件冲突。

这批仅开放已有读取能力及显式登记的业务只读网关；不包含受控业务写入、幂等写入、SCIM 组织同步、真实企业供应商联调及 SaaS 套餐运营。
