# 文档维护与文件保留策略

## 现行手册

[AGENTS.md](../AGENTS.md) 是 AI 入口，[任务导航](ai/README.md) 决定按什么任务读什么，[能力地图](ai/能力地图.md) 定位代码/测试。架构解释职责与调用链；前后端、API、升级和发布指南维护现行约束。专项手册可能含日期，仍可由能力地图链接使用；不能仅凭文件名日期判废。

每种事实只保留一个权威来源：版本在配置/锁文件，接口在代码与生成 OpenAPI，组件参数在组件手册与源码，验收在具体 SHA 的 CI 与报告。根目录快速参考和 VERSION 只做导航，避免重复维护内容。

建议保留于基座 Git 仓库，作为范围、决策和验收依据；它们不再是 AI 默认必读内容。保留原路径以免破坏历史链接，不批量移动或删除。

## 文件盘点与清理边界

本轮检查了 Git 跟踪路径、根目录文件、忽略规则及创建器导出规则：

- 存在已过时或重复的说明入口：旧前后端指南、快速参考、版本页、早期功能清单。已修正或改为指向权威文档；不是删除功能代码。
- design-spec 中 Ant Design/Tailwind 适配、HTML 预览等是跨项目设计参考，并非当前 Vue/Element Plus 运行依赖。保留参考与许可证；日常开发只读当前 CSS 令牌和组件。尚未证明这些文件可以全部删除。
- .codex-validation、pytest-of-*、测试媒体、coverage、debug.log、dist 等是忽略的本地测试/构建产物，不能据其存在认定源码冗余。成功中间产物可按任务归属清理，失败证据及来源不明目录先保留。
- node_modules、venv 和工具链是本地依赖，不当作普通垃圾；如需清理使用对应包管理器，不纳入本轮删除。
- .env、管理员访问文件、媒体、数据库及备份属于凭据/用户数据，即使未跟踪也不自动删除。用户提供的未跟踪审计报告原样保留。
- scripts/validate_*、并发夹具和测试用 URL 文件虽然不由生产入口引用，却被 CI 或隔离验收使用；不能按“运行时没引用”删除。

本轮没有据静态引用扫描宣称所有死代码已排除，也没有删除历史验收目录、用户资料或可疑文件。真正删除源码应逐项证明无导入/动态注册/CI/构建/许可证用途，再运行受影响检查；数据删除另需用户授权。

## fork 与项目导出

fork 保留历史，创建器导出已提交源码及手册并过滤实际凭据/数据/构建缓存。当前继续保留被手册引用的历史证据，避免删掉后产生断链；AI 通过任务导航按需读取，无需遍历全部文件。若未来提供“精简文档导出”，应显式设计文档依赖闭包并验证升级清单，不能简单删除所有带日期的文件。

移动入口或新增能力时更新导航并执行 `python scripts/check_ai_docs.py`；改变生成项目内容时验证创建/升级回归，防止基线文件清单漂移。

## 全量复核与后续门禁（2026-10-19）

本轮扩大到全部 164 份受 Git 管理的 Markdown，扫描本地链接、章节、已记载的 npm 命令和 Python 验收脚本，并对当前接入指南中的关键能力声明逐项对照源码。重点修正如下：

- 字段权限只合并显式策略；租户默认管理器不能替代类级 QuerySet 和批量写入的隔离措施；标准 Redis 与精简 LocMem 的限流范围不同。
- 专项手册补充当前表单、审批、报表、开放 API、外部通知与摘要入口，保留历史失败和待办记录并指向后续验收，避免用旧批次范围判断当前能力。
- 模块安装说明和生成模板统一为先登记及启用，再迁移与初始化；补正 PowerShell 升级命令，架构说明区分模块 key/URL、构建/运行开关和各类版本。
- 隔离导出发现四份历史报告含 79 个本机私有证据链接/图片引用，部分相对路径在原工作区能打开而在干净副本中断链。现保留原标签和文字路径，不改原验收结果、不发布日志或截图；自动检查拒绝再次把 `.codex-validation` 本地证据做成附件链接。
- 另将 64 个指向本机 D 盘的源码/手册链接改为仓库相对路径。历史标签中的行号仍作为当时定位记录，链接只指向文件；检查器不再把 Windows 盘符误认作外网协议。

Git 仓库检查只取受跟踪文档及必需入口，不把用户未跟踪的原始审计稿当现行规范；无 Git 的导出副本检查根目录与文档树，包含创建器生成的 PROJECT.md。门禁检查链接和部分可执行契约，不能自动证明自然语言语义全部正确，也不验证外网链接可用性。新增能力仍须同步对应说明、核对源码并执行行为验收。

验证记录：全库文档检查通过；生成器 v1/v2/已有表定向回归通过，其中两项 PostgreSQL 专属用例因本地 SQLite 环境跳过。实际导出使用受跟踪源码的隔离 Git 提交，不复制用户原始报告或私有环境；导出后的 165 份文档包含 PROJECT.md，检查通过。没有启动服务或访问业务库，本轮未重跑完整产品 CI、前端浏览器及服务器部署；不能沿用 v1.0.0 的 CI 作为本次提交全绿证明。

最终文档、创建器与升级回归共 71 项通过，依赖锁检查及差异格式检查通过。中间曾有一次升级源码应用异常，单项及整套复跑均通过，原因未确定；保留该次失败 XML，不将复跑通过解释为已定位或修复偶发写入问题。安全报告与失败诊断保留在本机 `.codex-validation/docs-full-review-20261019/`，不进入 Git。
