# 文档维护与文件保留策略

## 当前目录保留什么

[AGENTS.md](../AGENTS.md) 是 AI 入口，[任务导航](ai/README.md) 按任务选文档，[能力地图](ai/能力地图.md) 定位实现与测试。架构、功能接入、工程约束和部署升级手册维护当前契约；具体功能、修复和发布验收记录保留当时提交、检查结果及未验证边界。

已关闭的立项规划、缺口清单、深化路线图、原始审计与修复待办从当前目录移除，仅保留于 Git 历史；不再复制到新的归档目录或默认 AI 上下文。原始模型结论不自动成为业务需求。未关闭的真实限制先写入相关现行手册，再清理旧记录。新业务规则单独写 BUSINESS_CONTEXT.md。

日期不是删除依据：有日期的功能手册和验收仍可能有效。验收只证明指定提交和环境，不能覆盖之后的 main。新增功能按[验收记录要求](ai/验证与交付.md#功能验收记录)记录，避免再维护平行的完成百分比或重复待办。

## 历史追溯

完整 fork 保留 Git 历史；创建器导出当前提交，默认不带历史清单。需要调查旧决策时在基座仓库按原路径查询，例如：

```powershell
git log --all -- 'docs/全系统审查与修复清单-2026-10-19.md'
git show '054c89c:docs/全系统审查与修复清单-2026-10-19.md'
```

无需为日常业务开发恢复旧清单。精简导出不包含 Git 历史，可回到基座仓库查询。

## 文件清理边界

- 凭据、媒体、数据库和备份不入 Git，也不作为普通垃圾删除；用户提供的未跟踪审计稿原样保留。
- 本地测试与构建产物按任务归属清理；失败日志、截图及来源不明目录先保留。依赖、缓存和工具链不纳入普通文件清理。
- design-spec 的跨项目设计参考和许可证、CI 验收脚本及并发夹具不能仅因生产入口没有引用而删除。删除源码须核对动态注册、构建、测试和许可证用途。
- 移动或删除文档同时更新引用，执行 `python scripts/check_ai_docs.py`，并验证真实创建器导出的链接与升级清单；不能只检查原工作区。

版本取配置与锁文件，接口取实现及生成 OpenAPI；同一事实只保留一个权威来源。文档门禁检查本地链接、章节和部分可执行契约，不证明全部自然语言、外网链接或产品行为正确。
