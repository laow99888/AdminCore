# 微前端接入

AdminCore 的微前端能力默认关闭。只有在构建时设置 `ADMINCORE_MICRO_FRONTENDS_ENABLED=true`，并在运行环境确认子应用入口后，才会注册 `/micro/:appKey/*` 路由。

## 可信登记

子应用必须登记在 `frontend/src/microfrontends/registry.ts`。登记项固定包含名称、同源入口、宿主路由前缀和权限码；运行时不会接受后端返回的任意 URL，也不会把用户输入拼接成入口地址。当前示例登记为 `/subapps/example/`，部署时应替换为经过审查的同源静态资源入口。

路由守卫同时检查构建开关、登记 key 和权限码。关闭开关、未知 key 或缺少权限时，路由进入 403；关闭开关不会删除已有业务数据。

## 子应用契约

入口页面需要由 qiankun 读取，并导出 `bootstrap`、`mount`、`unmount` 生命周期。`mount` 接收的 `props` 只有以下宿主协作数据：

- `identity`：用户 ID、权限码摘要和当前租户 ID；
- `initialRoute`：进入子应用时的相对路径；
- `onHostNavigate(path)`：请求宿主切换路由的回调。

访问令牌、刷新令牌、Cookie 和完整用户对象不会作为 props 传递。子应用的 API 请求应通过受控的同源会话或后端专用接口完成，并自行遵守权限和租户边界。

宿主在 Vue 组件卸载时调用 qiankun 的 `unmount`。子应用不应持有宿主 DOM 以外的全局状态；需要监听宿主路由变化时使用 `admincore:micro-route` 事件，并在 `unmount` 中移除监听器。子应用 DOM 必须只写入传入的 `container`，不能修改宿主页面其他节点。

## 验收

`frontend/e2e/microfrontends.spec.ts` 用同源生命周期入口验证了实际 qiankun 挂载、身份摘要边界和离开路由后的卸载；`frontend/tests/microfrontends.test.ts` 覆盖登记表、默认关闭和运行时句柄。真实子应用的资源部署、CSP、Tunnel 和容量仍需在目标项目环境单独验收。
