# 在线表单业务关联深化（2026-10-19）

V2 表单新增 `relation` 字段，可放在主表或一层明细内。设计器选择已登记资源，运行页远程搜索业务记录，保存值仅为 UUID。记录历史继续按冻结的字段类型和资源编码解析；发布新版把字段改为普通文本，不改变旧记录。

## 登记与权限边界

复用业务搜索的显式 V2 登记协议：模块必须启用、生成服务与 schema 验证通过，manifest 明确声明 `BUSINESS_SEARCH.fields` 和 `title_field`，并有登记的读取菜单及资源权限。只有允许 `eq` 或 `contains` 查询的字符串字段可作为标题，当前用户还必须拥有该标题字段的读取权限。设计器只列出这些资源，不提供模型名、ORM 路径或自由输入入口。

搜索和解析均通过登记服务的 `visible(actor)` 检查当前行权限，再强制匹配服务端从有权表单或本人历史记录取得的实际租户。平台管理员未选择租户时，也不会跨租户混合选择。接口不接受客户端 `tenant_id`，未知参数、重复参数和无权表单上下文均拒绝。

搜索每页 30 条、最多 1000 页，查询长度最多 100，沿用 `query_budget` 限制查询和锁等待。响应仅含 UUID 和已授权标题，使用 `private, no-store`。失去模块、资源、字段或行权限后，历史解析重新授权；界面显示不可用提示，不返回越权标题。只读记录解析还必须绑定记录中具体字段路径的原 UUID，不能借接口枚举其他记录。

创建、修改、试填和送审均重新校验关联权限；写入时按资源、主键稳定排序锁定目标行。试填优先使用有权表单的租户上下文，不信任提交的租户值。默认值、任意对象、URL、计算式和 ORM lookup 不可作为关联字段配置或值；条件只支持空值/非空值判断。

## 版本、审批与限制

本次无模型、数据库字段或迁移变更。表单快照冻结字段类型、资源与 UUID；展示标题采用当前有权读取的业务标题，因此目标名称更新后，历史页面也显示更新后的名称。当前版本不提供业务名称的不可变审计快照，也不为任意业务模型建立通用外键；目标被删除后显示不可用，不保证业务删除保护。

审批快照和流程输入均排除主表、明细中的关联值，审批参与身份不额外授予业务读取权限。正式业务若要求“审批当时的交易主体名称不可变”或“禁止删除被引用主体”，应在对应业务模块明确建模，不由通用选择器暗中增加权限或约束。

前端提供资源和记录加载、空结果、失败重试、分页、禁用与只读状态；身份、权限、租户、上下文或字段值变化会取消请求并清空旧标题，迟到响应不能恢复旧数据。复用现有 Element Plus 布局，支持手机宽度。

## 接口与验收

- `GET /api/v1/online-forms/relation-resources/`：设计器的当前可用资源。
- `GET /api/v1/online-forms/{code}/relations/`：必须指定 `form_id` 或 `record_id`，以及 `field`；可用 `selected`、`q`、`page`、`resolve`，一层明细路径如 `lines.0.supplier`。
