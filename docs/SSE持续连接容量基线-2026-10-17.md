# SSE 持续连接容量基线

本轮在独立 PostgreSQL/Nginx/Gunicorn 原生 ASGI 中观测真实连接、自然重连、access/refresh 轮换、连接预算及回收。默认部署及现有测试站点不变。结果只覆盖固定夹具和下面的资源配置，不代表公网容量、目标业务 SLA 或数小时稳定性。

后续发现并修正了 Nginx 上游复用与 ASGI 异步收尾的协议竞态，详见文末；下面的首次百连接失败记录保留为历史证据，不代表修复后状态。

## 复现与口径

执行 `python scripts/validate_realtime.py`，需要项目开发锁依赖、Docker Compose 和空闲的 18430/18431。默认执行 24 条连接的六分钟基线；追加 `--include-capacity-edge` 执行按0.1秒间隔到达的百连接阶段，CI现采用该完整命令。脚本先执行真实代理协议、鉴权、数据范围、撤权、并发、模块启停验收，再运行容量阶段；数据库限定为随机项目自己的 `realtime_fixture`。成功清理本项目容器、卷、镜像标签和凭据；失败停止本项目服务并保留诊断证据。首次实现的旧CI配置和失败记录见下文历史段落。

只对隔离 realtime 容器设置 1 CPU、512 MiB，实际核对 cgroup 限额及单 worker。普通 WSGI API、PostgreSQL、Redis 和 Nginx 沿用当前编排，未将这组测试资源写入默认生产配置。cgroup 累计内存峰值包含页缓存和短期观察进程；每十秒左右采样还包含 Docker 命令、Django 启动及数据库查询时间，不是精确十秒周期。数据库连接数来自 `pg_stat_activity` 的当前数据库分组，包含观察连接及普通 API，不能当作每条 SSE 的连接成本。

每阶段创建不同用户、不同设备会话；通过产品原生签发服务登记初始 access/refresh，只将凭据写入隔离临时文件，取回内存后立即删除两端文件。SSE 及后续 refresh 全部经过真实 Nginx/产品鉴权，没有修改五分钟 access 有效期、刷新限流或重放策略。各用户分别拥有一条通知、审批及授权任务，快照必须符合固定夹具的计数和进度，不能包含植入的私有正文。各身份数据相同，容量阶段本身不构成跨用户隔离证明；对象范围另由前置功能正反例验证。

24 条连接持续 360 秒，短流自然结束后重建，临近到期时通过真实 HTTP 轮换 access/refresh。百连接探索另外创建 101 个新身份，按每 0.1 秒建立一条连接，目标是全部准入后继续运行 35 秒、SQL 有效租约为 100、第 101 个身份被拒绝为 429；本轮未通过该阶段，见下表。原有人工填充的百条过期租约保留在基线中，不将其当作实际连接数；收尾要求有效租约为零、总行数回到阶段前，证明新领取的租约已回收。

门槛要求每条流有正确快照、心跳及自然轮换，24 条长阶段每个身份至少实际刷新一次；重新收到首帧的等待小于 10 秒，普通健康 API 小于 3 秒，无 OOM、重启或非预期终止事件。同设备自然结束后的短期 429 只在五秒内重试并记录，不修改浏览器产品对 429 的退避策略。此处是验收客户端，不能将其行为当作网页的完整调度模型。

## 最终结果

证据项目 `admincore-realtime-7d630056`。六分钟基线通过；百连接两次探索失败，原始总 `report.json` 保持失败，不改写为整套通过。随后只针对修改后的百连接到达节奏复跑，没有重复未修改的六分钟阶段；该复跑也失败。新默认入口完整远端结果仍待提交后执行。

| 场景 | 实际结果 |
| --- | --- |
| 24 条，持续 360 秒 | 通过；客户端总耗时 370.78 秒，含准入、收尾及观察；每个身份 14 次自然重连、1 次真实刷新，总计 360 个正确快照、1392 个心跳；零客户端错误、零准入重试 |
| 24 条资源及延迟 | cgroup 累计内存峰值 117.77 MiB，OOM/重启 0；首帧或重连观测最大 1049.49 ms，26 次普通健康 API 观测最大 24.99 ms；采样数据库连接总数最多 4，低频采样不能证明瞬时连接上限 |
| 100 条同时发起 | 失败；一次预算行 `FOR UPDATE` 超过两秒锁等待，原始报告采样 33 条有效租约，没有完成全部准入；该采样值不是最大连接数或生产上限 |
| 100 条，间隔 0.1 秒发起 | 全部真实流准入，SQL 有效租约 100，第 101 条返回 429；自然重连期间一条等待响应头超过 10 秒，Nginx 对应记录客户端取消 499，阶段未完成要求的 35 秒，故失败 |
| 百连接较缓到达的其他观测 | 194 个正确快照、451 个心跳、首帧/重连已成功样本最大 412.32 ms；健康 API 已完成样本最大 20.79 ms，内存累计峰值 109.25 MiB，OOM/重启 0。这些部分成功指标不能抵消一条超时 |
| 三次阶段收尾 | 有效租约均归零；总租约行数均回到先前人工夹具的 100 条过期行，无新增租约残留 |

突发锁超时有数据库日志支持；较缓到达后的单次响应头超时尚未定位到具体服务器内部环节，不能归因于同一个锁问题，也没有据此改动 SQL 超时、扩大权限、增加自动容错或提高客户端超时。24 条是这次已验证的基线，100 是准入预算，不能视为本资源档位已经稳定支持的容量。CI 默认只对已定义的六分钟基线做回归；百连接探索继续保留明确命令、失败退出和证据，不静默变成成功。

证据位于 `.codex-validation/admincore-realtime-7d630056/{report.json,capacity-24-report.json,capacity-100-report.json,docker.log}` 与 `paced/{capacity-100-report.json,recovery-report.json}`，对应命令日志 `r5-realtime-capacity.log`、`r5-realtime-paced-recovery.log`。两个失败进程均已退出，五个隔离服务已停止、18430/18431 已释放；数据库卷、镜像标签及私有夹具环境保留用于诊断，不上传凭据。共享六服务没有停止。

## 工具与安全边界

`scripts/tests/test_realtime_capacity.py` 的 11 项通过，使用本地真实 HTTP 流验证验收器：正常快照/心跳、实际刷新、HTTP 故障、错误刷新对、范围错误、撤销事件、额度拒绝错误、OOM 和重启。这些反例验证工具会拒绝异常，不冒充产品故障恢复或供应商验收。报告只保存计数、延迟、资源和异常类别或固定错误码，未保存 JWT、refresh、原始业务帧或请求异常详情；Docker inspect 仅取运行状态和固定启动参数。CI 只上传明确的报告和命令日志，不上传夹具凭据。

仍需目标项目另外确认：预期并发与数据规模、公网/Tunnel 代理及超时、突发到达速率、数据库竞争、数小时运行、业务性能预算和故障恢复指标。本轮六分钟观测不能替代这些环境验收。

## 后续协议竞态修复

提交 `1e12115` 的[远端项目检查](https://github.com/laow99888/AdminCore/actions/runs/39003836138)为20个作业成功、realtime失败。CI的24条阶段在首次自然重连后出现两个响应头读取超时，只有36.18秒，不是六分钟验收成功；原始报告下载保留于 `.codex-validation/realtime-ci-39003836138/`。

隔离诊断以固定脱敏请求编号记录应用入口、数据库提交/开始/完成和响应头阶段，不记录参数、Authorization或帧。原百连接较缓到达场景再次失败，超时请求没有进入ASGI应用；已进入应用的数据库最大排队68.46ms、执行206.04ms。该证据将此超时与先前预算行锁超时区分开。

随后将复现缩至固定版本Gunicorn原生ASGI和一个不访问数据库的夹具：发送最终响应体后异步等待0.3秒，模拟产品租约清理窗口。客户端复用同一HTTP连接立即请求下一条会超时；改为新连接则200。正式加入的 `protocol_regression()` 通过真实Nginx和同一客户端Session固定worker，旧上游缓存配置下第二次请求两秒超时；对应失败日志 `r5-realtime-protocol-before.log`。该测试覆盖协议已结束、应用仍在收尾的真实模式，不通过修改数据库时间掩盖问题。

项目固定Nginx 1.29.8；从1.29.7起，上游空闲连接缓存默认启用，`keepalive 0`可关闭，见[官方指令说明](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#keepalive)。产品修复只在`admincore_realtime`上游显式设置`keepalive 0`，避免下一条短流复用尚在异步收尾的连接；浏览器到Nginx的连接策略、普通WSGI上游、SQL锁和超时、JWT有效期保持原契约。未修改第三方安装包或增加服务依赖。

单变量诊断复跑中，关闭上游复用后100条真实流/第101条429、自然重连及租约回收通过，总耗时55.36秒、零客户端错误；该阶段使用隔离诊断包装器，不代替后续纯产品镜像完整验收。证据 `admincore-realtime-7d630056/no-reuse/`。正式脚本新增10次协议回归，CI追加`--include-capacity-edge`验证较缓到达的百条阶段；不再仅运行24条。100条瞬时突发的锁等待边界仍保留，不能从按0.1秒间隔到达的通过推断瞬时突发也通过。

最终纯产品镜像项目`admincore-realtime-2d3da791`的完整命令通过，共88项外层断言，含10次协议连续请求和以下两个阶段。没有加载诊断包装器。1 CPU/512 MiB限制、原有权限和模块行为保持原验收。
