# 独立开放凭证与只读 API

## 当前阅读入口

以下记录首版的两类摘要能力及兼容行为。当前另支持显式登记的 V2 业务只读网关和独立机器身份，见 [业务开放接入](功能深化第一批-2026-10-18.md)、[机器集成身份](机器集成身份深化-2026-10-19.md)。凭证能力从签发接口按当前模块、角色、租户和登记表计算，不能用下文两项硬编码推断当前全集；仍不开放任意模型或通用写入接口。

## 首版范围与验收（历史）

首版实现独立于用户 JWT 的只读开放凭证。模块 `api_credentials` 默认关闭，`standard`/`minimal`/`demo` 预设均不会自动启用。打开模块需要把 `api_credentials` 加入部署中原有的显式模块列表，并执行迁移和原有权限初始化流程；不要用单项覆盖其他需要启用的模块。数据库 app 与迁移始终保留，关闭模块只关闭入口和能力。

## 已交付范围

| 入口 | 身份 | 行为 |
|---|---|---|
| `/integrations/credentials` | 已登录用户 JWT | 管理本人凭证、选择能力、有效期、密码确认、展示一次密钥、撤销 |
| `GET /api/v1/api-credentials/credentials/` | JWT + `api_credential:read` | 本人凭证元数据分页，无密钥及散列字段 |
| `GET /api/v1/api-credentials/credentials/scopes/` | JWT + `api_credential:create` | 本人当前可签发的已启用能力 |
| `POST /api/v1/api-credentials/credentials/` | JWT + `api_credential:create` + 当前密码 | 签发本人凭证，201 响应仅展示一次随机密钥 |
| `POST /api/v1/api-credentials/credentials/{id}/revoke/` | JWT + `api_credential:revoke` + 当前密码 | 仅撤销本人凭证，重复撤销幂等 |
| `GET /api/v1/api-credentials/tasks/`、`tasks/{id}/` | ApiToken + `task:read` | 任务摘要，不返回 result/error、内部 Celery ID 或请求追踪信息 |
| `GET /api/v1/api-credentials/work-items/`、`work-items/{id}/` | ApiToken + `example:read` | 示例工单摘要，不返回备注和创建人资料 |

开放 API 请求头格式为 `Authorization: ApiToken <签发响应中的完整 token>`。只允许 GET/HEAD/OPTIONS，普通业务 `/tasks/` 和 `/example/` 入口不接受这种身份；登录、刷新、账号安全、权限管理及凭证管理也不接受 ApiToken。能力不是任意权限字符串，服务器固定登记 `task:read`、`example:read` 两项，分别要求任务/示例模块已启用。

这属于可用的只读开放 API 首版，不代表任意资源或写入 API 已开放；需要后续扩展时，必须单独审查路由、DTO、当前权限、数据范围、事务、审计和幂等契约。

## 安全与兼容边界

- 创建必须使用真实有效的 JWT 设备会话，并通过现有密码确认服务；MFA 仍由原登录链执行，不提供绕过入口。凭证不可用于登录或确认敏感操作。
- 每个随机密钥有 256 bit 熵，数据库只保存 SHA-256 散列，公开 ID 不能用于认证。响应 `private, no-store`，浏览器只在临时对话框保留；关闭、离开页面、换账号或撤权后清空，不写 localStorage/sessionStorage、URL、复制历史或审计内容。
- 创建只能选择当前账户已有权限。每次使用重新读取有效用户、权限、角色和数据范围。账号停用、初始密码待修改、密码变化、全局 session_version 撤销、凭证过期或显式撤销均拒绝。单台 JWT 设备退出不自动撤销独立凭证；需要终止集成时单独撤销凭证，或执行全局下线。
- 管理操作和认证使用“用户行 → 凭证行”的事务锁顺序；一次请求通过身份检查后，不承诺在途只读响应可被另一请求中断，后续请求会重新检查。
- 每个账户最多 20 个未撤销且未过期凭证，有效期 5 分钟至 90 天。SQL 事务锁对每个凭证实施 60 次/分钟计数；认证前按真实 REMOTE_ADDR 180 次/分钟限制尝试，缓存不可用时失败关闭为 503。部署应沿用项目可信代理配置，不信任客户端自填转发头。
- 创建、撤销与首次使用写安全审计，投影只包含 ID、owner ID、scope 和时间。重复使用更新有界计数/活动时间，不按每次请求新增 SQL 审计行。一般请求状态沿用结构化 HTTP 日志，禁止把 Authorization 或密钥写日志。
- 网关复用标准分页、有限过滤/排序、200 字符查询输入上限、主键同值排序和 PostgreSQL 列表 SQL 预算；凭证认证的用户/凭证行锁同样受 SQL 和等锁预算约束。数据范围沿用现有规则，管理员仍具有仓库规定的全范围语义。查询范围没有快照语义，也没有扩大为开放个人资料字段。
- 数据库迁移只新增独立表，不修改既有 JWT/用户数据。凭证不会进入 Django admin；既有全局认证链保持 JWT 专用。

## 维护操作

没有“找回密钥”或原地恢复撤销的入口。丢失密钥后，撤销旧凭证再签发新凭证。轮换时可先签发新凭证、更新调用方配置、确认调用，再撤销旧凭证。表内只保存有限元数据，过期历史暂不自动删除，避免静默破坏审计关联；后续如增加保留计划，需要明确历史保留规则。

签发请求字段为 `name`（1–80 字符）、`scopes`（不重复且来自服务器登记）、`expires_at`（带时区日期）和 `current_password`；提交 owner/user、通配符、账号安全 scope 或其他额外字段会返回 400。没有跨用户签发、访问或撤销入口。
