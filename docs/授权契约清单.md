# AdminCore API 授权契约

这份清单是路由审计的入口。DRF 视图上的 `permission_classes` 负责实际拦截，
`backend/apps/core/authorization_contract.py` 负责登记匿名入口并给审计分类。
每增加一个 API 路由，必须运行 `backend/tests/test_authorization_contract.py`；
如果需要匿名访问，先补充公开入口白名单，再增加对应的行为回归。

## 四类语义

| 类别 | 含义 | 典型实现 | 额外要求 |
| --- | --- | --- | --- |
| `public` | 不依赖 Bearer 会话即可访问 | 登录、恢复、健康、品牌、SSO 跳转 | 必须登记在公开前缀中；不得返回用户或租户私有数据 |
| `self` | 已登录用户的本人能力或按本人/所有者范围过滤 | 个人资料、会话、通知、表单记录 | 查询集必须使用当前用户、所有者或明确的数据范围 |
| `permission` | 已登录且拥有业务权限码 | `IsAuthenticated + HasPermission` | 写入仍需在事务内调用 `authorize_write`，并复核撤权后的身份 |
| `admin` | 管理员专属的系统或组织能力 | `IsAuthenticated + IsAdmin` | 组织、租户、备份、在线用户等操作必须保留审计和对象范围检查 |

`IsAuthenticated` 单独出现时归入 `self`，但这只是路由级分类，不替代对象级
授权。`scope_queryset`、`get_object()` 的所有者检查以及 `authorize_write` 的
锁内复核，分别由各模块专项测试验证。

## 已登记公开入口

- `/api/versions/`
- `/api/v1/health/`、`/api/v1/health/live/`
- `/api/v1/brand/`
- `/api/v1/auth/login/`、`login-captcha/`、`recovery/*`、`refresh/`、`register/`
- SSO 浏览器流程：`config/`、`start/`、`callback/`、`status/`、`complete/`、`cancel/`

认证视图中的 `profile`、`avatar`、`me`、`logout`、`change_password` 等虽然位于
认证模块，仍要求登录；它们不属于公开白名单。

## 验收边界

本契约检查能发现“新路由意外匿名开放”和权限类别缺失，不能穷举每个角色、
租户、数据范围的对象级组合。新增敏感对象或范围时，必须同时添加普通用户
访问他人对象的负例，以及撤权后旧会话/旧幂等键不可重放的回归。
