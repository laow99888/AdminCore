## 更新入口与边界

`.github/dependabot.yml`按生态限制同时打开的PR数量；npm/pip普通minor/patch按生态分组，major留给专项迁移，GitHub Actions单独分组。Django虽可能同主版本跨受支持线，任何minor仍需人工判断维护周期和兼容性。安全更新不承诺受普通版本分组和忽略规则完全相同地控制，收到告警后要单独处理。

SheetJS的本地官方tarball不由npm机器人替换；维护者核实官方发行、许可证、摘要和写出行为后，同步更改原包/引用/校验器及文档。Python使用`requirements.txt`和自定义文件名`requirements.lock`：不依赖机器人自动识别并重新生成uv哈希锁，若PR只修改直接清单，新的CI明确拒绝合并，维护者补锁。传递依赖安全更新也需主动执行uv升级并审核摘要差异，不以没有PR视为无漏洞。

Dockerfile由机器人给出候选；运行时升级须同时更新`.python-version`/`.nvmrc`、npm engines/packageManager、Dockerfile、所有CI运行时和版本文档。PostgreSQL/Redis Compose服务镜像及独立MinIO测试程序、系统软件包、uv工具本身由维护者每月检查，机器人配置不声称已覆盖这些项目。镜像标签不能代替digest；每次正式发布仍记录实际镜像digest及备份/回退边界。

## 维护者轮转命令

先基于干净分支处理同一兼容组，阅读官方发布说明和安全公告，修改精确直接版本。工具使用uv0.12.3、Python3.13.15、Node24.21.0/npm11.19.0；工具升级也要单独复验。根目录执行：

```powershell
# 修改精确版本后同步全部平台哈希锁；未指定升级时尽量保留现有锁
uv pip compile backend/requirements.txt --python-version 3.13.15 --universal --generate-hashes -o backend/requirements.lock
# 要更新指定传递依赖时显式选择；包名替换为本次审核的目标
uv pip compile backend/requirements.txt --python-version 3.13.15 --universal --generate-hashes --upgrade-package 包名 -o backend/requirements.lock
backend/venv/Scripts/python.exe -X utf8 scripts/check_dependency_locks.py
backend/venv/Scripts/python.exe -X utf8 -m pytest -q scripts/tests/test_dependency_locks.py
```

前端在`frontend`执行`npm install 包名@精确版本 --save-exact`（开发依赖另加`--save-dev`），确认package.json/lock完整差异；清洁安装使用`npm ci`。Tiptap三个直接包、Vitest和coverage包分别同步升级。不能删除锁文件、去掉哈希或放松引擎来消除安装错误。后端将锁安装到独立环境并执行`pip check`，前端执行类型/lint/构建/覆盖率/分包/全量浏览器回归；Dockerfile/数据库/队列/存储/解析器升级须重跑对应真实隔离链路，不能仅跑单元测试。

通过全部检查后更新`版本要求.md`、兼容性/迁移说明与清单，并在PR中说明当前版本→候选版本、外部依据、锁差异、测试、恢复与回退限制。数据库大版本必须另做真实备份恢复及升级演练。只自动提出候选，不自动合并、执行迁移或重建正式服务。
