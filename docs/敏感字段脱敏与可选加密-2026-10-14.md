# 敏感字段脱敏与可选加密

本批范围为用户邮箱/手机号的管理展示保护，以及 User.phone、旧 UserProfile.phone 的可选存储加密。脱敏始终执行，默认部署保持手机号明文存储；加密需要管理员为全部写入进程配置同一独立密钥。全量缺口清单仍未完成。

## 展示和权限

用户管理的列表、详情、创建/修改响应、旧资料手机号、当前页打印以及 CSV/XLSX 导出统一返回脱敏值。手机号十一位以上数字保留前三位和后四位，如 `138****3210`；较短非空号码全部隐藏为 `****`。邮箱保留域名及最多一个本地字符，如 `p***@example.test`，单字符本地部分不保留。邮箱域名、用户名、姓名仍可见，这是明确的展示边界。

管理员也不会在普通列表得到原值。单对象 `POST /api/v1/users/{id}/sensitive/` 仅接受 JSON `current_password`，同时需要 `user:read`、`user:sensitive_read`、原有 user 数据范围、有效设备会话和本次密码确认。复用已有密码核验失败限频，缓存故障返回 503，失败不发送原值；成功先记录查看审计，再返回邮箱/手机号，并设置 `Cache-Control: private, no-store`。不会签发可复用的确认凭据或缓存成功响应。

新增权限仅登记，不自动扩大已有角色的授权。staff/superuser 沿用仓库既有全权限规则；其他账号必须显式授予两个权限。Django 后台列表/表单同样仅展示脱敏联系方式和邮箱验证布尔状态，不提供原始联系方式编辑入口。本人登录响应、`auth/me/`、个人中心保留本人原值，支持既有编辑、验证与找回流程。

前端查看窗口独立于列表/编辑数据：本次密码核验成功后最多展示 60 秒，关闭、离开路由、退出、切换设备会话或失去权限会清除并中止请求。超时恢复到前台时再次检查，迟到响应不能恢复已清除的内容。原值不进入浏览器持久存储、页签状态、列表打印或导出；这不能防止已获授权者人工复制或截图。

编辑已有用户时，邮箱/电话输入留空表示保留原值，填入新值才替换，清空电话需明确选择；不能把页面掩码写回。管理搜索和导出搜索仅按用户名、姓名，不按邮箱/手机号查找。导入要求完整有效联系方式，脱敏导出文件不能直接用作用户导入数据。

## 加密配置与转换

复用锁定依赖中的 cryptography Fernet，带手机号用途标识和版本前缀；自定义 Django 字段在 ORM 读写边界转换，数据库列改为 text，输入仍限定为最多 20 字符。模型保存、直接 update、bulk_create、bulk_update 和支持的字面量/Case 写入都在存储前加密；F/RawSQL 等数据库内表达式写手机号被拒绝。迁移只改变列类型，不自动转换现有数据。

```dotenv
ADMINCORE_FIELD_ENCRYPTION_ENABLED=False
ADMINCORE_FIELD_ENCRYPTION_KEY=
```

有有效密钥即加密所有非空新写入，哪怕 ENABLED=False；ENABLED=True 额外要求启动时必须有有效密钥。这样保留密钥而关闭开关不会悄悄降级。密钥须单独生成、单独备份、放在部署秘密配置中，不能使用 JWT、数据库密码或 TOTP 密钥代替，不得提交 Git。

```bash
# 在安全终端本地生成；输出是密钥，不能写入日志或版本库
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
# 默认只统计，不修改数据或显示手机号/记录标识
python manage.py encrypt_phone_fields
# 配置与备份完成后执行，单批最多 1000 行
python manage.py encrypt_phone_fields --apply --batch-size 200
```

首次启用流程：停止写入、备份数据库和媒体、为 backend/worker/beat 及所有命令进程配置同一密钥、部署并检查、执行统计和 --apply、再次统计确认 `plaintext=0`、重新开放业务。转换逐批锁行，重复执行幂等，等待期间的新编辑不会被旧快照覆盖。无效历史号码或无法解密的值会使当前批回滚并报固定错误；已完成的前批保留，可修复后重跑。多个进程配置不一致时，不能靠运行时检查消除首次转换与错误配置进程写入之间的竞争，必须统一配置后再开放写入。

坏密文、错误/丢失密钥返回固定的不可用错误，不能将密文当明文返回。移除密钥后，存在密文的表会拒绝非空 ORM 写入，旧对象保存也拒绝；不会提供自动解密降级命令。空号码仍允许保持/清空。手机号查询不能再依赖数据库明文匹配，后续业务应使用独立经过评估的查询方案。数据库原始 SQL 和拥有主机/数据库权限的操作者不属于 ORM 防护范围。

## 验收和限制

按 Django 自定义字段的数据库/Python 转换契约和 Fernet 认证加密接口实现，参考 [Django 官方文档](https://docs.djangoproject.com/en/5.2/howto/custom-model-fields/) 和 [cryptography 官方文档](https://cryptography.io/en/latest/fernet/)。转换命令统计模式、坏数据批回滚、错误密钥、原值权限、数据范围、撤销会话、导出和后台旁路由自动回归覆盖；隔离 PostgreSQL 使用真实 SQL 校验密文、转换与编辑行锁竞争，以及请求等待期间撤销设备会话的拒绝行为。

本批不声称全部个人信息加密：邮箱为兼容认证查询仍明文存储；上传的原始导入文件、旧备份、日志中既有历史数据及其他业务字段也不被这个字段自动加密。导入文件继续遵守私有文件权限，部署可配合磁盘/对象存储加密和保留期策略。启用加密后数据库备份包含密文，恢复必须同时保留正确密钥；没有完成密钥轮换工具，不要直接换新密钥。加密后不应逆向迁移回 varchar(20)，应先恢复兼容版本和密钥进行故障处理。
