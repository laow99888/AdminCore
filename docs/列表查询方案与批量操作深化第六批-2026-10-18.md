# 列表查询方案与批量操作深化第六批

本批接在前五批之后，深化路线图第5项的生成业务列表。范围是 V2 生成单表、树表和主子表的主记录列表；已有内置用户/岗位等列表不自动获得这些业务动作。全局业务搜索留待独立登记数据源，本批不记为完成。

## 已实现的行为

### 高级条件

- 页面可以增加最多10个条件，选择“全部满足”或“任一满足”；条件与原有基础筛选同时生效。
- 只允许 schema 中 `query != none` 且查看者当前有读取权限的主表字段。通用等于/不等于，contains 字段可用包含，range 字段可用大于等于/小于等于。
- 条件值经过实际 serializer 的类型、枚举、日期、金额和长度校验；每值最多200字符，整份高级条件最多4096字符。
- 不接受 SQL、正则、表达式代码、嵌套分组、明细查询或 `creator__password` 等关系路径；没有自动关联名称解析。关联/文件使用ID、字典使用原值。
- 空条件表示不附加过滤。不等于沿用 Django 的空值语义；当前界面不提供空值条件。
- 既有权限、租户、行范围、稳定排序、分页和 PostgreSQL 查询预算继续生效。生成单表 CSV/XLSX 导出复用相同条件校验和过滤，既有5000行/10MiB上限保留。
- 修复生成列表排序字段带前后空格时的字段权限检查遗漏。

### 服务端查询方案

- 新表 `core.SavedListView`，按用户、租户和模块保存基础筛选、当前高级条件和排序。每用户每模块最多30个个人方案，每租户/平台范围每模块最多30个共享方案。
- 基础筛选使用已点击搜索应用的值；当前高级条件可直接保存。分页、当前树父节点、业务行、权限和凭据不保存在方案中；树表继续在当前父节点内查询。
- 方案定义保存在服务端，换设备登录可选同一方案。当前浏览器只保存按账号/租户/模块隔离的已选方案ID，刷新后恢复；跨设备不自动同步“当前选中哪个方案”。
- 个人方案只归本人管理，管理员也不能读取他人的个人方案。仅平台 staff/superuser 可管理共享方案；业务读取者可以使用共享方案或另存个人副本。共享仅共享查询设置，不授予业务、字段或数据范围权限。
- 保存、读取和实际列表执行都复核当前查询契约；schema摘要变化或字段撤权后，方案停止应用。
- 无权方案不向普通使用者返回条件值；所有者仍可看到失效标记及空定义并删除或重建更新，不会因失效方案永久占满额度。共享方案名称本来就是共享内容，不宜填写业务秘密。
- 版本号保护更新/删除；重复名称返回409，配额和名称在事务锁内检查。
- 创建/修改/删除记录审计，只记录方案标识、归属、共享标记、版本和定义摘要，不复制查询值。

### 跨页选择与批量删除

- 主记录复选框可跨页累计，最多100条，明确保存所选ID及首次选择时版本。更换筛选、排序或父节点时清空；翻页保留。没有“隐式选择所有匹配项”。
- 先预检，逐项显示 `ready / unavailable / conflict / blocked`；预检只检查当前行可见性、版本和审批状态，不执行业务扩展。
- 返回签名预检凭证，有效15分钟，绑定操作者、租户、业务模块、schema摘要和明确通过项；不能挪给另一用户/租户/版本。
- 用户输入 `删除选中记录` 后执行，必须携带幂等键。执行重用原生成模块删除事务，复核当前登录、操作权限、数据范围、记录版本、审批锁、业务扩展、关联保护和审计。
- 逐项预期失败返回 `unavailable / conflict / blocked / forbidden / timeout`，成功返回 `deleted`，不返回其他记录详情或底层异常文本。失败项不妨碍其他通过项在这次事务结束后提交。
- 批请求整体处于一次事务中：不可预期的服务器错误会整体回滚；“逐项结果”不表示进程中断后部分事务已永久提交。响应丢失可用同一幂等键与同一请求重试，24小时内不重复产生成功副作用；凭证本身仍受15分钟有效期约束。
- 同键并发请求在真实 PostgreSQL 中验证结果一致且仅一份删除审计。预检后撤权阻止执行，预检后被修改的行返回冲突。
- 不提供批量修改任意字段、批量审批或主子表明细选择；新增动作需单独定义业务事务和权限。

## 入口与兼容

V2 `GeneratedViewMixin` 接入公共工作台实现，因此已有 V2 后端生成文件不必整体覆盖重生成。已有项目需要同步底座、执行迁移，并同步前端 `GeneratedCrudPage` 与公共组件。手写扩展继续经原服务调用，老列表参数兼容。

新接口均在生成资源 `/api/v1/<module>/records/` 下，默认受模块启停及业务 `read` 权限保护：

| 路径 | 方法 | 额外边界 |
| --- | --- | --- |
| `?advanced=<JSON>` | GET | 当前可读且可查字段，JSON为 `{match,conditions:[{field,op,value}]}` |
| `query-views/` | GET | 只返回本人及本范围共享方案 |
| `query-views/` | POST | 新增或携带 id/version 更新；共享仅管理员 |
| `query-views/` | DELETE | id/version；仅所有者或共享方案管理员 |
| `bulk-preview/` | POST | 额外要求 delete 权限，selection为1至100条 id/version |
| `bulk-delete/` | POST | 额外要求 delete、预检、确认文字和 Idempotency-Key |

迁移 `core.0014_savedlistview` 仅增表，不猜测旧用户偏好，不修改已有组织、配置或业务数据。已验证从0013升级保留旧配置与部门版本，以及新库创建。

## 界面与状态

复用既有 Element Plus、BaseTable、BaseDialog 和 CSS 变量，增加明确标签、键盘焦点、44px手机触达目标、失败重试、输入保留与逐项结果。查询方案和批量对话框在身份或租户变化后重新挂载，迟到响应不落入新上下文。

本批同时修复同一用户资料对象刷新误清业务草稿/查询的问题：比较稳定的会话身份和授权快照；正常后台资料刷新保留草稿，并刷新列表以获取当前字段策略。过滤字段撤权导致403时清空旧筛选，重新取得安全列表；不自动重发受限条件。

### 验证发现及修复

- PostgreSQL首轮功能测试通过，但新增动作的OpenAPI请求声明不能解析；已改成明确serializer并通过严格schema检查。
- 最初前端测试全部通过，但BaseTable分支覆盖率91.11%低于92%门槛；增加非选中行等真实选择场景后，最终93.33%，没有降低门槛。

- 页面变高后原列设置浮层可能覆盖标题，原先点击标题关闭的方式不可靠；增加明确关闭入口、Escape关闭及返回触发按钮的焦点恢复，桌面/手机一起回归。

全局业务搜索、任意嵌套条件、跨表/明细条件、可执行分享链接、按角色共享、服务端默认方案同步、上万条批任务均未实现。内置用户/角色等列表的破坏性批动作不因本批自动开放。方案属于配置数据，包含筛选原值，跟随数据库备份保护；审核管理员共享内容时遵循项目自身业务要求。
