# 报表构建器与大屏模板

AdminCore 的 `reports` 为默认关闭的可选模块（`ADMINCORE_MODULES=reports`）。模块提供报表/大屏定义的草稿、发布、归档和运行入口，数据源固定为用户、任务、文件三类，定义只允许登记的数据源、字段、聚合、筛选和最多 100 行结果。

后端使用静态白名单映射和 Django ORM，禁止任意 SQL、模型路径、表达式和脚本。运行前会再次按当前用户的字段级读取权限复核定义；字段权限撤回后已发布报表会拒绝运行。用户、任务数据复用原资源的数据范围入口，文件数据复用文件 ACL，撤销授权后下一次聚合立即生效。查询包在统一 `query_budget` 中，结果行数和筛选数量均有上限。

不选维度时返回一行总计（count/sum/avg），日期维度按天聚合，返回行键与声明列名一致。页面保存后保留维度配置，发布后禁用修改，并可新建另一份草稿；运行结果的图表使用该结果的定义，支持柱状图及可访问的数据表。

入口：

- `GET /api/v1/reports/catalog/`：返回当前用户可用的数据源和字段。
- `GET/POST/PATCH /api/v1/reports/definitions/`：查询、创建和修改草稿。
- `POST /api/v1/reports/definitions/{id}/publish/`：发布草稿；发布后不可直接修改。
- `GET /api/v1/reports/definitions/{id}/run/`：运行已发布定义。
- 前端 `/reports`：构建、发布和运行报表/大屏模板。

模块关闭时不注册入口但保留迁移和数据；启用前应为管理员授予 `report:*` 权限。专项 13 项覆盖白名单拒绝、总计/日期聚合、发布不可变、字段权限、数据范围、文件 ACL 撤销及查询预算，已在独立 PostgreSQL 18.6 通过。真实 Chromium 桌面/手机验证创建、保存后维度、发布禁用、运行数值、柱状图、图表数据表和刷新恢复；入口为 `python scripts/validate_p2_pages.py`。严格 OpenAPI、前端类型、lint 和生产构建通过；目标业务容量和复杂大屏视觉验收仍需部署环境执行。
