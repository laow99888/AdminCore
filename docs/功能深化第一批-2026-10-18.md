# 功能深化第一批

本批覆盖多项目源码升级闭环、业务字段权限登记、通用表格列配置。它不是整个功能深化路线图的完成声明。稳定发布标签、业务导入扩展、高级报表、共享查询方案等仍按路线图独立推进。

## 独立项目升级

`scripts/project.py` 增加 `upgrade-apply`、`upgrade-accept`、`upgrade-restore`。生成并保存的计划包含原基线、本地和目标摘要；应用前重新核对，冲突由操作者明确选择。应用不立即改变上游基线，只有操作者登记的验收命令全部成功且待验收源码未再次变化才推进基线，因此支持 A→B→C 连续升级。

源码备份、中断状态、验证日志保存在私有忽略目录，恢复拒绝覆盖升级后再次编辑的文件。`.env`、实例配置、媒体、数据库和数据卷不参与源码应用或恢复。具体命令、既有项目工具接入以及数据库迁移边界见 [底座版本与项目升级](底座版本与项目升级.md)。

## 业务字段权限

模块契约新增可选 `field_policies`，只声明自己的 `data_resources` 中的显式字段，不扫描数据库模型。示例：

```python
field_policies=(('orders', ('code', 'cost', 'lines', 'lines.product', 'lines.price')),),
```

资源和字段在启动时检查重复、命名和数量边界。V2 生成器自动生成这些声明，并为主表和明细序列化器登记资源与明细前缀。既有生成模块需重新预览并选择应用 `manifest.py` 与 `serializers.py` 才进入这套字段策略；旧模块保持兼容行为，不宣称它们已自动纳管。

角色编辑页提供字段策略配置，字段选项来自 `/modules/` 的 `field_policy_resources`。未声明某资源策略的旧角色保持原兼容行为；一旦用户任一有效角色声明该资源，按这些显式策略的字段并集授权。停用角色后下一次请求重新计算，不跨请求缓存字段权限。字段授权不能替代操作权限、租户和数据范围。

生成模块接入以下边界：

- 列表/详情过滤受限业务字段及 `display_labels`，关联选项及标签复核目标资源的字段读取权限。
- 直接筛选、全文搜索、指定排序先检查相关业务字段；默认排序含不可见业务字段时退回稳定的时间/ID排序。
- 普通写入在序列化和写事务中复核。主子表的明细按整组替换，提交一组时必须有分组及所有子字段写权限，避免隐式重置无权字段；省略明细组的 PATCH 保留原记录。
- 幂等写响应重放时再次过滤当前字段读取权限，并批量重建关联/附件/字典标签；关联名称按当前目标字段权限和行范围复核，避免沿用缓存中的旧名称。
- 生成报表源在查询前检查维度、指标和筛选字段；审批冻结快照和流程输入按查看者当前权限投影。
- 新业务审批持久化标题及通知不复制业务标题字段值；历史业务标题不参与审批中心的标题搜索，新通知也不沿用历史业务标题。有权限的页面标题从冻结快照投影，仍显示业务编码；业务记录按编码搜索使用业务列表。过去已经投递的通知不会被此改动追溯撤回。

生成列表响应额外带 `data.field_permissions`；通用业务页据此隐藏列和筛选项，禁用无权编辑的字段，并在保存时省略无权替换的明细。ID、版本、创建人、时间和审批状态等协议字段仍保留；角色配置针对显式业务字段。金额计算等可信服务端扩展可以生成只读字段，用户不能通过请求直接写入。

本批没有新增生成业务模块的通用导入/导出渠道；这部分能力仍列在路线图中。开发者自写的接口也必须调用公共授权函数，单纯登记字段不会自动拦截任意自定义代码。

## 列配置

`BaseTable` 增加可选 `preference-key`。不传时沿用原行为；用户列表和 V2 生成业务页面已接入。设置支持显示/隐藏、上移/下移、左右固定和恢复默认，保留至少一列。操作列、选择列和序号不参与自定义，原表格实例、选择和分页不因配置而重建。

偏好按浏览器、账号、当前租户和列表标识分别保存。只保存列标识/顺序/固定位置，不保存行、筛选值或凭据；读取时以当前调用方列集合重新归一，旧配置不能恢复已撤销列，新字段默认可见。存储失败时保留本页内配置并提示；同源标签及同页实例可同步。未登录时不持久化。

这是本浏览器的列偏好，尚不包含跨设备同步、个人/共享查询方案、跨页批量选择或业务全局搜索。列隐藏是显示偏好，不能代替服务端字段权限。
