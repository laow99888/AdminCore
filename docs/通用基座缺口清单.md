# AdminCore 通用基座缺口清单

**生成日期**：2026-10-13
**修订日期**：2026-10-13（GLM 原清单基础上，经用户确认补充机制、验收要求及当前状态）
**定位**：供多个独立项目复用的通用中后台基座，参考若依等项目的常用能力；不默认采用多租户。
**核心理念**：可以不用，但不能没有。底座提供完整能力，小项目按需启用；关闭的模块不增加业务入口、后台任务和不必要的运行依赖。

**范围约定**：P0 为共享机制与扩展契约，P1 为底座计划提供的通用功能，P2 为需要具体业务信号的架构扩展，P3 为持续工程建设。优先级表示实施顺序，不等于全部默认启用。P2 保留规划与扩展边界，不以接口占位宣称功能已完成。

**最新实施记录**：第 1 批基础能力与第 2 批幂等/可靠事件已通过本机测试、迁移校验和隔离 PostgreSQL 并发验收；第 2 批覆盖审批创建/决策、管理员站内通知发送、outbox 至少一次投递、消费去重、指数退避及失败事件管理员 API 重试；未勾选的功能继续待实施。

**状态约定**：`[x]` 仅表示注明范围已验收；`[ ]` 表示待实现或尚未完整验收；“部分”必须写明已有能力和剩余工作。功能列表齐全不能代替安全、集成和部署验收。模块关闭也有升级、迁移和安全维护成本，需通过模块边界控制。

## 新增：跨模块实施约束

以下为本次接受并补入的共同要求，适用于 P0/P1 全部相关模块，不能用增加页面或保留空接口代替。

### 模块启停与小项目成本

- [ ] 每个模块有唯一标识、契约版本、默认启用状态、依赖与冲突声明；由显式配置启用，避免扫描任意目录自动执行代码。
- [ ] 禁用后撤下路由/API、菜单及后台调度；后台消费者和信号不得继续处理该模块业务。权限定义与历史审计可保留，但不能继续获得业务入口。
- [ ] 缺失依赖在启动/构建时给出明确原因；关闭被依赖模块时先阻止或提示影响范围。
- [ ] 关闭不删除数据库表、业务文件或历史记录。重新启用和关闭期间的升级有明确迁移策略；不能因模块退出 INSTALLED_APPS 导致关联迁移损坏。
- [ ] 明确编译时能力裁剪与运行时启停的区别。运行时关闭不自动减少已安装依赖；精简构建和 Compose 预设才负责避免不必要的前端包、进程及外部服务。
- [ ] 验收精简/标准/演示预设：精简预设不要求未使用的邮件、对象存储、实时通道或后台任务服务；实际服务依赖以模块声明为准。
- [ ] 演示账号、演示数据和演示重置任务独立启用，生产配置拒绝误开启。提供本地可重复初始化及演示重置步骤。

### 配置、字典与品牌

- [ ] 配置声明类型、默认值、允许范围、作用域、管理权限、生效方式和是否敏感；敏感值不原文回显、不进入日志与导出。
- [ ] 系统参数、个人偏好、部署环境与密钥分别管理。明确环境变量和数据库配置的优先级，禁止绕过既定安全边界。
- [ ] 配置变更具有版本、审计、校验、缓存失效和回退方式；跨进程/worker 的最长生效时间可验证。
- [ ] 可配置业务字典与代码状态机枚举分开：审批/任务等状态机不能因为字典编辑而任意改变合法迁移。
- [ ] 品牌覆盖名称、Logo、登录文案及浏览器标题；提供默认品牌和配置缺失回退，上传资源遵守文件安全约束。

### 数据权限、并发与事件

- [ ] 同一权限策略覆盖列表、详情、写操作、关联选择、统计、导入导出、下载及后台任务。组织模块关闭时仍保留本人/授权范围/全部等不依赖部门的策略。
- [ ] 覆盖直接访问对象 ID、跨部门关联、批量混合权限、角色变更后重试等越权用例；后台任务记录执行身份并复核数据范围。
- [ ] 编辑版本冲突返回明确结果，前端保留用户输入并提供刷新/比较；禁止无提示覆盖他人修改。
- [ ] 幂等键绑定操作者/接口/请求摘要；同键不同请求拒绝，同键并发不重复执行业务；保存期限与失败后重试规则明确。
- [ ] 数据库回滚不发送成功通知。关键事件采用可靠持久化投递机制，支持重试、去重、失败可见和授权人工重放；消费者按至少一次投递设计。

### 数据生命周期与恢复

- [ ] 分别定义业务记录、会话、审计、文件、通知、任务结果、临时文件、导出文件的归属、保留期、删除方式和清理失败处理。
- [ ] 明确软删除后的唯一字段占用、关联可见性和恢复冲突；恢复后不能扩大原数据权限，关联对象已删除时有可理解的处理结果。
- [ ] 清理支持预览影响范围、分批执行、审计和失败重试；高风险不可逆操作受专门权限控制。生产数据不因模块禁用而自动清空。
- [ ] 本地和对象存储统一验收上传、鉴权下载、过期链接、预览、软删、最终清理及备份恢复，代码不依赖仅本地可用的 `.path`。
- [ ] 自动备份与清理使用统一的调度规则，避免多个调度器重复执行；有互斥、失败记录、告警和明确保留策略。
- [ ] 备份校验不替代恢复演练；记录可接受的数据丢失窗口、恢复时间和实际结果，验证数据库与媒体的一致性。

### 运维、会话与扩展安全

- [ ] 会话分别支持整体撤销和指定会话撤销，定义活动时间、绝对/空闲过期和权限更新时限；撤销后旧 access/refresh 按承诺时限失效。
- [ ] 定时任务只能选择已注册任务和允许参数；重试、超时、重叠、失联、取消及人工重放都有明确语义和权限。
- [ ] 缓存清理只能作用于允许命名空间；不可通过“清缓存”误清队列、分布式锁、会话或防爆破状态。
- [ ] Webhook/第三方对接定义目标地址校验、网络访问边界、超时、签名、重放防护和密钥轮换，不能成为任意内网访问入口。
- [ ] 服务/系统信息页按权限展示并脱敏；健康检查不向匿名访问者暴露凭据、完整环境变量或内部诊断详情。
- [ ] 日志串联 HTTP 请求、异步任务和通知记录；提供失败定位与队列指标。关闭诊断模块时，基础错误记录和安全审计仍可用。
- [ ] 代码生成器生成符合本项目权限、数据范围、审计和测试约定的代码；输出可预览、可比较、可选择覆盖，不能静默覆盖人工代码。

## 新增：每项能力的统一交付与验收模板

开展实现前，每项能力必须填以下六项；实施中使用“未开始/进行中/待验收/已验收/部分完成”，不能只标完成百分比。

| 字段 | 必须记录的内容 |
|---|---|
| 功能范围 | 用户能做什么、页面/API/后台处理、边界和本次不覆盖项；现有能力与待实现内容分别写明 |
| 默认是否启用 | 精简/标准/演示预设的选择，启用入口及重启/构建要求 |
| 外部依赖 | 依赖模块、运行进程、数据库/队列/存储/邮件等服务及失败处理；占位适配器不能计为实现 |
| 权限与数据范围 | 操作权限、对象/字段/数据范围、后台任务身份、审计与敏感信息处理 |
| 关闭后的行为 | 路由/菜单/任务/消费者是否停止，数据如何保留，依赖如何处理，重新启用及迁移行为 |
| 可重复执行的验收条件 | 命令/操作步骤、输入和预期结果、测试环境、证据路径、已知限制、验收提交及日期 |

**共同验收门槛**：

- 新空库初始化、已有数据升级、启用/关闭/重新启用均通过；不可逆迁移提前说明并有备份/恢复方案。
- 正常、空数据、加载、错误、禁用、越权、重复请求和并发冲突有对应验证；第三方依赖故障行为可验证。
- 涉及页面时验证桌面/窄屏、主题、语言和键盘可访问性；涉及外部渠道时至少验收一种真实可运行实现，模拟测试另行注明。
- 对新增模块运行针对性测试、类型检查、构建及迁移/schema 检查；更新真实远端 CI，不能只以本地通过计为远端成功。
- “已验收”记录代码提交及证据；一次性能基准、局部组件覆盖率和脚本存在不能替代持续压测、全站覆盖或自动调度验收。

## 落地路线建议（修订批次）

| 批次 | 内容 | 验收重点 |
|---|---|---|
| 第 1 批 | 数据权限/组织模型 + 模块契约/启停预设 → SysConfig/字典/品牌 | 统一鉴权覆盖完整链路；精简项目无需启用全部模块 |
| 第 2 批 | 并发/幂等 + 可靠事件/通知渠道 + 存储适配 + 数据生命周期/回收站 | 幂等与站内 outbox 已完成当前范围；存储适配、回收站、邮件/Webhook 渠道仍待实施 |
| 第 3 批 | 邮件/找回/首次改密/个人资料 + 会话设备 + 导航体验 + 基础预览 | 补齐原始需求；权限变更及会话撤销实际生效 |
| 第 4 批 | 定时任务 UI + 自动备份/告警/清理 + 诊断监控 + 实时通道 + 2FA | 注册任务边界、取消/重叠/失联语义、依赖故障及恢复演练 |
| 第 5 批 | 导入导出资源补齐 + 公告/富文本 + 代码生成器 + 完整二开示例/初始化模板 | 生成和扩展模块遵守权限、审计、测试契约；已有项目可同步升级 |
| 长期 | P2 按业务信号决策，P3 持续穿插，补齐 P1 剩余可选启用功能 | 每项有验收证据，不能以接口占位代替能力交付 |

**工作量说明**：原稿 P0+P1+手册模板约 5–6 人月、P2 再加 3–4 人月，为未经详细拆解的粗估。此次新增机制、兼容迁移与验收范围后，不沿用为承诺；每批设计明确后重新估算。组织权限、软删、会话和存储迁移均可能影响已有数据，不能作为低风险纯页面工作。
