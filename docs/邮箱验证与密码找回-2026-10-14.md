# 邮箱所有权验证与邮件找回密码

本批提供可选的认证邮件流程：本人在个人资料中验证已保存邮箱，登录页提供找回密码入口，用户凭邮件中的一次性代码设置新密码。已有账号的联系邮箱初始均未验证，不能直接用于找回密码。

## 行为与边界

- 邮箱验证申请要求当前登录会话和当前密码；确认代码必须由同一账号的有效会话提交。邮箱修改会撤销旧归属及待用代码，改回原地址仍需重新验证。一封邮箱最多归属于一个账号，比较采用去除首尾空白并统一大小写的规则。
- 匿名找回申请提交用户名及已验证邮箱。不存在、停用、未验证或邮箱不匹配的账号均返回相同的 202，回复不表示账号存在或邮件已经发送。申请仅事务内登记可靠事件，不同步调用 SMTP 或任务代理。
- 邮件包含手动粘贴的完整代码；代码不放入 URL、浏览器偏好或日志。服务端以随机挑战标识和密钥派生签名，数据库及 Outbox 不保存代码原文；Outbox 仅保存挑战标识。代码有效期 10 分钟，绑定用途、账号、邮箱、密码和凭据版本；新申请替代同用途旧代码，密钥轮换、邮箱变化、密码变化及整体撤销都会使旧代码失效。
- 密码重置检查密码强度、两次一致及不能与当前密码相同；成功后撤销全部旧 access/refresh，并清除首次改密标记。重置不会自动登录，用户需用新密码重新登录。
- 核心派发计划约每分钟领取邮件事件，SMTP 使用有限连接超时。失败保留脱敏异常类型并退避，最多自动尝试 5 次；达到上限后保留失败事件，用户重新申请。SMTP 已接收但数据库提交失败时，可能重复投递同一代码，代码仍只能成功消费一次。
- 过期、已消费、账号变化或已删除的挑战不再发送；领取和消费沿用账号行锁及挑战行锁。限流采用缓存原子计数，按 IP、申请身份或挑战限制频率；缓存故障返回通用 503，所有认证邮件接口禁止缓存。
- 失效挑战保留至少 30 天后，复用每日 03:45 核心会话清理计划分批清理；每次最多清理 1,000 个挑战。

## 配置与使用

默认 `AUTH_EMAIL_ENABLED=False`，正式环境继续关闭邮件入口。此开关不影响登录、个人资料编辑或管理员重置密码；缺少 SMTP 凭据时不能把邮件发送记为已完成。

在不入 Git 的 `.env` 中配置专用 SMTP 账号：

```dotenv
AUTH_EMAIL_ENABLED=True
EMAIL_HOST=smtp.example.com
EMAIL_PORT=587
EMAIL_HOST_USER=专用SMTP账号
EMAIL_HOST_PASSWORD=供应商提供的授权密码
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
EMAIL_TIMEOUT=10
DEFAULT_FROM_EMAIL=admin@example.com
```

主机、发件地址、端口及超时必须有效，TLS/SSL 选其一。供应商使用隐式 TLS 时，通常改为端口 465、`EMAIL_USE_TLS=False`、`EMAIL_USE_SSL=True`；实际以供应商配置为准。真实邮件密码、地址和域名按项目环境替换，示例不能直接发送邮件。

标准部署需要 backend、worker、beat 使用相同配置和服务端密钥，Redis 和 `core.dispatch_outbox` 定时计划正常运行；配置更新后重建或重新创建相关服务。精简预设默认没有后台派发服务，因此邮件入口不可用，也无需配置邮件凭据。认证邮件不依赖通知中心的启用状态。

管理员先在个人资料中保存实际邮箱，输入当前密码申请验证，再粘贴邮件代码确认。以后忘记密码时，在登录页选择“找回密码”，填写用户名和这个已验证邮箱；查收邮件后在恢复页面粘贴代码及新密码。未验证邮箱或邮件服务不可用时，由管理员使用已有重置密码入口处理。

本批只覆盖邮箱验证、找回密码两种固定认证邮件。业务通知的通用 Channel 接口、邮件模板管理、Webhook、短信、邮件回执及外部供应商投递验证仍待实施。

## API

| 方法与路径 | 请求及用途 |
| --- | --- |
| GET `/api/v1/auth/recovery/config/` | 匿名读取 `data.enabled` |
| POST `/api/v1/auth/email-verification/request/` | 当前会话，JSON `current_password` |
| POST `/api/v1/auth/email-verification/confirm/` | 当前会话，JSON `code`；返回最新个人资料 |
| POST `/api/v1/auth/recovery/request/` | 匿名 JSON `username`、`email`；统一 202 |
| POST `/api/v1/auth/recovery/reset/` | 匿名 JSON `code`、`new_password`、`new_password2` |

个人资料及当前用户新增只读 `email_verified`、`recovery_enabled`。写请求只接受声明字段和 JSON，限制请求体大小；代码和密码不会在错误响应中回显。

后续业务模块修改邮箱必须使用已锁定用户的 `save()`，不能用 `QuerySet.update(email=...)` 或批量更新绕过归属撤销逻辑。邮箱验证字段不得开放给普通编辑表单；成功验证返回资料版本，前端只接受本次预期的一次版本增长，否则保留草稿并提示重新载入。
