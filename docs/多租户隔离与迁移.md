# 多租户隔离与迁移

多租户默认关闭，通过 `ADMINCORE_MULTI_TENANT_ENABLED=true` 启用。关闭时现有单项目数据继续可见，历史记录的 `tenant` 可以为空；启用前应先为历史记录指定归属。

## 请求与成员

- 普通用户必须有一个 active 租户成员；只有一个成员时自动选中。
- 用户属于多个租户时，客户端必须在请求头发送 `X-AdminCore-Tenant: <tenant UUID>`。
- `staff`/`superuser` 没有请求头时保持全局运维视图；带请求头时按该租户读写。
- 租户状态为 `suspended` 或 `closed` 时不能建立上下文；关闭租户会停用成员，不删除业务记录。
- 租户和成员管理入口为 `/api/v1/organization/tenants/` 与 `/api/v1/organization/tenant-memberships/`，仅管理员可用。

## 数据范围

继承 `apps.core.models.BaseModel` 的基座业务模型统一增加可空租户外键。请求上下文存在时，默认管理器会过滤列表、详情和直接 ID 查询；保存时会自动填入当前租户并拒绝跨租户写入。后台任务或迁移脚本需要跨租户读取时使用模型的 `all_objects` 管理器，并自行传递租户边界。

当前租户字段覆盖基座业务记录、文件、任务记录、导入批次、通知、权限、审批、日志和示例业务。用户账号、会话等平台身份数据仍是全局资源；文件/任务/导入导出调用方必须在创建和读取时保留请求租户上下文。

## 旧库迁移

先执行预览：

```powershell
cd backend
python manage.py assign_legacy_tenant --tenant <租户 UUID 或 slug>
```

确认输出的模型和数量后显式执行：

```powershell
python manage.py assign_legacy_tenant --tenant <租户 UUID 或 slug> --apply
```

命令只处理 `tenant IS NULL` 的基座记录，使用事务写入，目标租户必须处于 active；不会覆盖已有归属，也不会删除数据。完成后再设置环境变量并重启服务。生产执行前应保留数据库备份，并核对每个模型的预览数量。
