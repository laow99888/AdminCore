# 组织任职与主管审批深化第四批

承接[功能深化路线图](功能深化评估与路线图-2026-10-18.md)第 6 项，补齐有效期主兼职任职、部门负责人和按组织推导审批人的能力。继续使用现有可选组织、审批模块，不增加运行依赖或常驻服务。本批不等于整个深化路线图完成。

## 任职与历史

组织管理新增“主兼职任职与历史”，管理员可以登记员工、部门、主职/兼职、生效日期、可选结束日期与原因，并按员工、部门、类型、取消状态、有效日期查询。列表分页，每页最多沿用公共分页上限，界面默认 20 项。

日期按服务端 Django 当前时区计算，任期为左闭右开：生效当天有效，结束当天无效。API 返回只读任职状态，前端使用服务端状态显示和禁用取消入口，避免浏览器时区不同而误判；跨日后需刷新列表。新增表单默认生效日期仍取浏览器当天，可以手动修改。主职不能重叠；同一员工在同一部门的任职也不能重叠，无论主职还是兼职。不同部门的兼职可以同时存在；原主职结束当天可以开始另一主职。API 在公共写授权和用户行锁内检查冲突，实际 PostgreSQL 验证了不同管理员并发登记时只有一笔成功。

创建后不能修改人员、部门、类型、生效日期，也不提供硬删除。只能带当前版本缩短结束日期，或取消尚未生效的计划；不能延长原期限、取消已生效记录、重复取消，或把结束日期设为生效当天。每次变更必填原因，版本递增，审计保存变更前后。记录页显示最后一次变更原因，原始原因与旧期限在审计中查询。没有实现专门的“修正错误历史”界面。

原 `OrganizationMembership` 人员归属保持原样，仍是现有数据范围计算及按部门人员查询的依据。新任职负责主管审批，不替换旧归属，也不会因兼职自动扩大列表、详情、导出或报表的数据权限。主职变更与原授权归属必须由管理员分别维护。

## 主管审批与快照

部门可以设置一个负责人。负责人必须是有效账号；启用租户时必须是当前有效租户成员。负责人不必在该部门拥有任职记录，便于集中负责人、兼管部门等组织形式。部门列表一次关联读取负责人，避免逐行查询。

V2 用户节点新增 `assignee: {source: "department_leader", levels: 1}`。设计器可以选择“部门主管”和 1～10 层：1 是员工当前主职部门，2 是其父部门，依此类推，按实际部门层级定位，不跳过空负责人、不按不同负责人数量计层，也不提供任意递归或自由表达式。

进入节点时按当天有效主职推导。若从未登记任何主职记录，可以回退旧人员归属；只要存在主职历史，包括未来、已结束或已取消的记录，就必须存在当前有效主职，不再回退。界面在创建任职时明确提示先补齐当前主职。只有兼职记录不会关闭旧归属回退。

目标部门无负责人、部门停用、组织链缺失或循环、负责人是申请人、账号停用、租户成员失效、组织模块关闭等情况均拒绝进入节点，不自动通过或跳过。若推进当前节点时发现下一节点无法解析，整次决策回滚并返回冲突；管理员修正后原审批人可以重试。没有额外实现超时升级或异常运营工作台。

节点进入时保存解析日期、任职 ID（旧归属回退为空）、来源部门、目标部门、层级、负责人 ID 与显示名称。待办继续使用已经确定的审批人；之后调岗或改负责人不会静默改派已有待办，后续尚未进入的节点按进入时组织状态解析。申请详情显示主管解析记录，历史部门名称也保持当时快照。现有转办、委托和失效账号检查继续沿用原规则，快照不授予额外审批权限。

## 接口与存量升级

- GET/POST `/api/v1/organization/appointments/`：列表与创建，创建版本必须为 0。
- GET `/api/v1/organization/appointments/{id}/`：单项历史。
- POST `/api/v1/organization/appointments/{id}/end/`：版本、结束日期、原因。
- POST `/api/v1/organization/appointments/{id}/cancel/`：版本与原因，只能取消未来计划。
- 部门接口增加可空 `leader` 和只读 `leader_name`；审批步骤增加只读 `assignment_context`。

新迁移是 `core.0013_department_leader_organizationappointment` 与 `approvals.0006_approvalstep_assignment_context`。升级不猜测负责人，不批量生成任职，不改变旧归属；旧审批步骤的上下文为 `{}`，既有审批人与状态保持不变。迁移回归实际从上一版表结构创建旧记录，再升级核对。更新了完整配置的 OpenAPI 与前端 SDK，共 205 条路径。

## 未包含的后续工作

流程同编码多版本发布与停用、退回指定节点、超时提醒/升级、异常流程处置仍待后续批次。连续上级会签需要显式配置多个主管节点；本批只提供每个节点的指定层级负责人，不自动生成整条主管链，也没有实现并行分支汇聚。任职日期按服务端时间运行，不承诺任意客户端时区切换或任意容量。
