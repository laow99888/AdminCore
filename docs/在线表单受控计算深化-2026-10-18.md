# 在线表单受控计算深化（2026-10-18）

本批在在线表单 V2 增加金额计算、逐行计算和明细合计，设计器、试填、提交及历史修改共用一份声明。它是受控的精确十进制计算，不接受表达式文本、函数、SQL、JavaScript 或任意代码。附件、授权关联选择和审批联动仍属于后续工作，不能据此记为整个在线表单深化完成。

## 声明与设计器

只有 `decimal` 字段允许 `computation`，计算字段不能同时声明 `default`。设计器可选择手动输入、加法、减法、乘法、除法或明细金额合计，并按声明顺序提供可引用的金额字段或明细金额列。切换为计算字段会移除原默认值。移动、删除或改名引用源后，保存和发布仍由服务端重新验证，失效的引用不能发布。

二元计算必须恰有两个来源，每个来源只能是先前同层级的金额字段，或精确十进制字符串常量。例如：

```json
{
  "key": "subtotal",
  "label": "小计",
  "type": "decimal",
  "scale": 2,
  "computation": {
    "op": "multiply",
    "operands": [{"field": "price"}, {"field": "quantity"}]
  }
}
```

其中 `price`、`quantity` 必须已声明为 `decimal`。既有 `number` 不会自动转成浮点金额；需要精确计算的数量也应使用金额精度协议，如 `scale: 0` 的 `decimal`。单字段可引用先前的计算金额，形成按顺序计算的链；不支持前向引用、自引用或循环。

明细子字段同样可计算行小计。顶层字段可对先前明细的一列金额求和，列可以是明细内的计算字段：

```json
{
  "key": "total",
  "label": "总额",
  "type": "decimal",
  "scale": 2,
  "required": true,
  "computation": {"op": "sum", "detail": "lines", "field": "subtotal"}
}
```

明细计算只引用同一行先前字段，不跨行、不引用父表字段；合计只遍历该明细的指定金额列。协议拒绝未登记属性和非金额来源。原有字段数量、明细行数和请求大小限制继续有效。

## 精度、缺值和校验

服务端使用 `Decimal`，前端预览使用 `BigInt` 有理数计算，不经过 JavaScript 浮点金额。结果按目标字段的 `scale`（0 至 8）采用 `ROUND_HALF_UP`，正负中点均向远离零的方向舍入，例如 `-1 / 8` 保留两位为 `-0.13`；零统一为正零。常量和结果最多 18 位十进制系数，不接受指数、NaN 或数值类型常量。

缺失或隐藏来源不会按零参与计算。空明细或任一行缺少该金额列时不产生合计，避免部分行被漏算而低估总额；业务要求完整金额时，应将来源与结果设为必填。除零、精度溢出返回目标字段错误，前端预览同步显示错误。结果继续经过必填、最小/最大值、条件显隐、条件必填及跨字段比较校验。

客户端计算输入只读，正常提交递归剔除计算结果，服务器独立复算。直接调用 API 即使伪造计算结果，也不能改变持久化值。试填使用同一个服务端计算入口。隐藏输入旧值不参与后续计算，也不参与提交。

## 发布、历史与兼容

计算声明随 `definition_snapshot` 冻结。新版修改公式不会改变旧记录的解释；旧记录修改仍使用其创建版本的公式复算，且保留既有本人、租户、记录权限及并发版本校验。本批不增加数据库字段或迁移，不修改权限范围，不依赖外部凭据。

旧版 V1 定义继续拒绝未登记的计算属性。未升级的客户端或集成仍由服务端得到可信计算结果；采用新设计器和渲染器后才有只读预览。公式或计算值变化都属于表单业务定义变化，应派生新版再发布，不应直接改已发布定义。
