# 快速开始

AI 先读 [AGENTS.md](../AGENTS.md) 和 [任务导航](ai/README.md)。固定运行时与安装方式见 [版本要求](../版本要求.md)。以下分为新业务项目和基座维护，选择一种路径即可。

## 创建独立业务项目（推荐）

在已克隆、已审核的基座根目录，用锁定 Python 执行：

```powershell
python scripts/create_project.py D:/Projects/my-admin --name my-admin --preset minimal --frontend-port 8080 --backend-port 8001 --start
```

目标必须是仓库外的新目录，端口须空闲；默认导出已提交 HEAD，正式基线用 `--ref v1.0.0`（仅在该标签已发布后使用）或已核验的完整 SHA。未提交改动不进入新项目。标准版改为 `--preset standard`。生成随机凭据，访问 http://127.0.0.1:8080；管理员密码仅在新项目 .env，首次登录须修改。

在新项目先读 PROJECT.md、AGENTS.md，再执行 `python scripts/project.py status` / `check` / `stop`。check 验证迁移，不代替完整业务健康验收。新项目可 git init 管理源码和 admincore.project.json，保留随机凭据和数据在 Git 外。详见 [初始化与升级](底座版本与项目升级.md)。

## 维护基座：Docker 启动

在克隆目录，PowerShell：

```powershell
Copy-Item .env.example .env
# 编辑 .env：独立强 DJANGO_SECRET_KEY、DB_PASSWORD、ADMINCORE_ADMIN_PASSWORD
# 核对端口与环境配置，再启动
docker compose up -d --build
docker compose ps
docker compose exec -T backend python manage.py migrate --check
```

已有 .env 时直接编辑，勿覆盖。完整默认六服务，前端通常 http://localhost；实际以 FRONTEND_PORT 为准。自动迁移后初始化权限、菜单和首次管理员；不会重置已有管理员密码。外部供应商与可选模块按需配置，生产不创建演示账号。

小项目的三服务和物理裁剪见 [精简构建](精简构建与完整恢复-2026-10-15.md)，不要用删除数据卷切换预设。公网 TLS、Cookie、可信代理与备份按 [部署指南](部署指南.md) 独立配置。

## 本地分进程开发

先在项目根目录准备 .env，把 DB_HOST/REDIS_URL 配成开发实例可达地址，选择空闲端口。数据库/队列由独立开发环境提供；正式 Gunicorn/Celery 在 Linux/容器运行。PowerShell 后端终端：

```powershell
cd backend
python -m venv venv
./venv/Scripts/python.exe -m pip install --require-hashes -r requirements.dev.lock
$env:DJANGO_ENV='development'
./venv/Scripts/python.exe manage.py migrate
./venv/Scripts/python.exe manage.py bootstrap_admincore
./venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000
```

独立前端终端：

```powershell
cd frontend
npm ci
npm run dev
```

通常访问 http://localhost:5173。Bash 环境变量写法为 `DJANGO_ENV=development python manage.py ...`，不要在同一命令混用语法。环境选择缺失/拼错将拒绝启动；只跑前端不等于后端已启动。

## 开始业务

使用 [业务开发流程](ai/业务开发流程.md)，在独立模块实现首条链路；验证按 [分层检查](ai/验证与交付.md)。排障先查实际配置、模块状态、日志和相关测试，不反复重建或清空数据库。
