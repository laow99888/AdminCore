# AdminCore 快速开始指南

## 项目概述

AdminCore 是一个现代化、专业级的中后台管理系统基座框架。包含完整的前后端架构、权限系统、文件管理、数据导入导出、任务调度等通用功能。

**技术栈：**
- 后端：Django 5.2.18 + Django REST Framework
- 前端：Vue 3 + TypeScript + Element Plus + Vite
- 数据库：PostgreSQL 18.6
- 缓存/消息队列：Redis 8.10.2
- 任务调度：Celery 5 + Celery Beat

实际验证状态见 [COMPATIBILITY.md](../COMPATIBILITY.md)。Docker 编排已提供（`docker-compose.yml`），修复后的验收结果与范围见兼容性记录。

## 开发环境设置

### 环境要求

- Python 3.13.15
- Node.js 24.21.0 / npm 11.19.0
- Docker 和 Docker Compose（可选，用于一键启动）
- PostgreSQL 18.6（或使用 Docker）
- Redis 8.10.2（或使用 Docker）

### 步骤 1：克隆项目

```bash
git clone <your-repo-url> AdminCore
cd AdminCore
```

### 步骤 2：环境变量配置

复制 `.env.example` 为 `.env`，根据需要修改：

```bash
cp .env.example .env
```

### 步骤 3：启动后端

#### 方式 A：本地运行

```bash
# 创建虚拟环境
cd backend
python -m venv venv

# 激活虚拟环境
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# 安装依赖
python -m pip install --require-hashes -r requirements.dev.lock

# 数据库迁移
python manage.py migrate

# 初始化权限、角色、菜单和管理员（需配置 ADMINCORE_ADMIN_PASSWORD）
python manage.py bootstrap_admincore

# 启动开发服务器
python manage.py runserver 0.0.0.0:8000
```

#### 方式 B：Docker Compose（推荐）

```bash
cp .env.example .env   # 修改 DJANGO_SECRET_KEY、DB_PASSWORD、ADMINCORE_ADMIN_PASSWORD
docker compose up -d --build
```

自动启动并初始化：
- PostgreSQL 18.6 + Redis 8.10.2（含健康检查）
- Django 后端 API（gunicorn，自动执行 migrate + 权限和管理员初始化）
- Celery Worker / Beat（任务调度）
- Nginx 前端（端口 80，反代 /api 到后端）

管理员使用明确设置的 ADMINCORE_ADMIN_USERNAME 与 ADMINCORE_ADMIN_PASSWORD。默认不创建演示用户。
健康检查：`bash scripts/health_check.sh`

### 步骤 4：启动前端

```bash
cd frontend

# 安装依赖
npm ci

# 启动开发服务器
npm run dev
```

访问 http://localhost:5173

### 步骤 5：登录系统

生产登录使用明确配置的管理员凭据，不提供公开默认密码。

本地演示环境可在 `.env` 设置 `DJANGO_ENV=development`、`DJANGO_DEBUG=True` 后执行 `python manage.py bootstrap_admincore --demo`，明确创建 `admin / Admin#12345` 与 `demo / Demo#12345`。生产环境拒绝该参数；重复初始化不会重置已有管理员密码。

## 常见问题

### Q: 如何修改主题色？

A: 编辑 `frontend/src/styles/design-tokens.css`，修改 `--color-primary-*` 系列变量。

```css
:root {
  --color-primary-500: #14b8a6; /* 修改这里 */
}
```

### Q: 如何添加新的 API 接口？

A: 后端参考 [API 规范](./API规范.md)，前端在 `src/api/` 下创建相应的请求模块。

### Q: 前端构建报错？

A: 清除依赖重新安装：

```bash

# 保留 package-lock.json，先核对运行时和安装错误
npm ci
npm run build
```

### Q: 后端数据库迁移失败？

A: 检查 PostgreSQL 连接：

```bash
python manage.py migrate --verbosity=2
```
