# 业务通知摘要与运营统计

本批完成显式登记业务提醒的“发送 → 个人立即/摘要偏好 → 到期合并 → 站内展开 → 原业务详情再鉴权”闭环，以及当前租户通知运营统计。它不会自动订阅所有业务表变更，也不把模板供应商接受响应解释为最终送达。

## 使用入口

通知中心新增“摘要与统计”；所有正常登录用户可看自己的等待条数、到期条数和最早到期时间，并合并本人已到期的提醒。管理员具备 `template:read` 时可查看运营统计，具备 `template:send` 时可通过“发送业务提醒”搜索已登记 V2 模块记录、选择有权限的收件人。发送 API 支持每批 1 至 100 位不重复收件人，界面本批提供单人选择。无任何新增外部发送渠道。

“通知偏好”新增业务提醒方式：默认立即入箱，可选择等待 1 小时或 24 小时后合并为摘要。等待时间从每条提醒创建时计算；后改偏好不会重排已有到期时间。刷新一次将同一用户、同一租户本次可处理的到期条目合成一封站内摘要，同一业务记录的多个事件展开时只显示一条引用。原有系统、审批和任务必须通知及模板投递规则保持不变。

## 授权、数据和幂等

业务引用只支持项目显式注册的 V2 生成模块。发送者和收件人都须具有模块读取权限，并通过原模块服务的 `visible()` 行级范围；链接只接受模块声明中的受信本地菜单路径。收件人必须有效、完成初始改密、属于当前正常租户。平台管理员身份不能绕过收件人租户成员检查。

`BusinessNotice` 只保存租户、收件人、资源、记录 UUID、事件键摘要、到期时间和状态，不复制业务名称、正文、字段值或任意客户端链接。站内通知正文为通用提示。到期刷新重新检查成员、租户、订阅、渠道、对象可见性和 7 天有效期；失败条目转为 `suppressed`，不会再次派发。模块停用时刷新不处理，恢复后再判断是否过期。展开摘要和点击引用均重新检查当前权限；原业务详情 API 继续独立鉴权。

事务内可信业务代码可调用 `enqueue_business_notice(recipient, resource, object_id, event_key)`；业务生产者需显式接入，不能用该函数替代原业务写入授权。相同租户、用户和稳定事件键仅保存一次；相同键更换业务引用返回冲突。HTTP 重试复用同一个 `event_id`，前端在结果未确认时保留选择和标识；整批发送和审计在同一事务，审计失败则回滚。已登记事件视为业务事实，后续刷新复核收件人权限；模板通知既有发送者会话撤销规则独立保留。

刷新先锁用户，再锁待发条目，重新读取 `pending` 状态；站内创建与状态推进在同一事务，可重复执行。此路径直接持久化站内通知，不调用外部供应商，不需要额外 Outbox 重试或常驻服务。PostgreSQL 并发实测由主任务统一整合；本子任务没有把 SQLite 测试作为真实并发保证。

## 接口

所有路径均位于 `/api/v1/notifications/`，只读和写响应均为私有、禁止缓存。

| 路径与方法 | 范围 |
| --- | --- |
| `GET/PUT preferences/` | 本人当前租户偏好；新增可选字段 `business_delivery_mode`、`digest_minutes`，旧客户端省略时保留原值，仍使用 `revision` 乐观锁 |
| `POST business-notices/` | 管理员及 `template:send`；请求 `resource/object_id/event_id/recipient_ids`，返回创建、重放及持久化状态条数 |
| `GET digests/status/` | 本人当前租户待发统计 |
| `POST digests/refresh/` | 仅本人当前租户，拒绝请求参数，只处理已经到期提醒 |
| `GET digests/<notification UUID>/` | 仅本人当前租户摘要，返回重新授权后的引用，无权对象不返回 |
| `GET operations/?days=7` | 管理员及 `template:read`，当前租户，默认 7 天，允许 1 至 90 天，拒绝其他及重复参数 |

## 调度与维护

迁移 `0011_business_notification_digest` 必须先于新服务和验收进程启动。旧浏览器夹具数据库需重新迁移；仅替换 Python 源码会因为缺列导致偏好读取失败。

运维入口：

```powershell
python manage.py refresh_notification_digests --limit 100 --all-tenants
```

`--limit` 默认 100，合法范围 1 至 500，限定本次最多处理条数。省略 `--all-tenants` 仅处理空租户的全局作用域；加上后在各个用户事务中恢复对应租户上下文。没有 `--force`、任意提前时间或客户端指定租户参数。命令关闭参数缩写，`--force` 不会被 Django 错识别为 `--force-color`。

应用调度可调用 `refresh_due(limit=100, all_tenants=True)`，返回 `processed/published/suppressed/summaries`。父任务负责接入既有 beat 和维护白名单；本模块不新增调度进程。任务中断只会留下尚未提交的条目，下轮仍可领取；重叠执行在用户锁后重查待发状态，不重复生成摘要。连续运行可能因每轮上限拆成多封摘要，这是明确的有界处理行为。

## 统计含义

统计按记录的创建时间限定窗口，显式过滤当前租户（空租户也只统计空租户），只返回聚合数量，不返回收件人、目的地址或通知正文。包括站内通知创建及当前已读数、模板按渠道的当前执行状态、两类通知 Outbox 当前状态、业务提醒当前状态及窗口内到期条数。

“已读数”是窗口内创建的通知当前已读数量，不是窗口内读取事件次数。`succeeded` 表示站内处理完成或供应商接口接受；`final_delivery_receipts_supported=false` 明确表示当前没有供应商最终送达/阅读回执。已删除或清理的记录不纳入统计；这不是不可变财务台账，也不是供应商送达率报表。
