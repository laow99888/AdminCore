## 资源与探针口径

- Docker/Kubernetes 标准容器标记下，CPU 读取 cgroup v2 `cpu.stat`，按可用 affinity 与 quota 的较小值归一化；约 120ms 单次短样本，百分比限制 0–100，不作为历史趋势或容量承诺。
- 容器内存读取 `memory.current` / `memory.max`；未设置硬上限时不借用宿主机总量，显示“未采集或未设置上限”，不伪造百分比。非容器 Linux 读取 `/proc/stat` 和 `/proc/meminfo` 的主机范围。非 Linux 或 cgroup v1 不支持的值显示未采集。
- 磁盘统计是应用、日志、本地媒体所在挂载文件系统的总量/已用/可用；同一文件系统可能重复显示，不可相加或当作目录占用。S3 不显示本地媒体容量；对象存储不在此统计。
- 进程来自当前可见 PID 命名空间，最多 128 项。仅显示 PID、固定 Python/其他类型、状态、累计 CPU 秒、RSS、存活秒。采集中退出的进程忽略，列表上限明确提示；RSS 含共享页，不可直接求和。
- Redis 使用固定部署配置，仅执行 PING 与 INFO server；连接/每次读取超时 350ms、重试关闭。没有任意 URL、键扫描、清理或控制入口。DNS 解析由系统解析器处理，无法把这个配置当作任意网络环境的总耗时保证；隔离验收验证本地连接拒绝在 3 秒内返回。
- PostgreSQL 在局部事务中给探针设置 500ms statement_timeout，事务结束恢复；已有 JWT 鉴权需要数据库，数据库整体不可用时无法保证已认证页面仍能打开。
- 本进程每用户 30 次/分钟，两接口共用计数；是采集负载保护，不是跨 worker 全局配额。限速与依赖状态不能替代公开健康检查、安全限流或生产观测平台。
- worker、beat、对象存储、邮件/外部渠道健康和队列积压仍待补齐。无历史图表、告警或宿主机 agent；本批不勾选 P3 完整端到端诊断。

口径参考：[Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)、[Redis INFO](https://redis.io/docs/latest/commands/info/)、[Python disk_usage](https://docs.python.org/3.13/library/shutil.html#shutil.disk_usage)。
