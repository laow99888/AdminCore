# 基础组件使用手册

本手册按当前 Vue 3 / Element Plus 实现编写。适用于应用内复用，组件本身不提供服务端授权。组件实现位于 `frontend/src/components/common/`，应用框架由现有 Pinia、Vue Router、Element Plus 和主题样式提供。版本以根目录版本要求及包锁为准。

基础组件可以从 `@/components` 导入；`DataImportButton`、`PersonPicker` 目前不在集中导出中，应使用各自文件路径。修改组件时同步本手册、示例和行为测试，避免文档描述超过实现范围。

## 可检查的组合示例

[BaseCompositionExample.vue](../frontend/docs/examples/BaseCompositionExample.vue) 演示表格、分页、表单校验、弹窗关闭确认和卡片组合，仅操作内存，不访问业务 API。示例不在 `src`，没有应用路由和生产入口引用，不增加首屏内容或生产菜单。它是可编译的用法文件，不是已经挂载的 Storybook/演示站点。

在 `frontend` 目录执行：

```powershell
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p docs/tsconfig.json
```

如需临时挂载示例，使用隔离测试应用，提供 Pinia、Element Plus 和项目主题；勿添加到正式路由。示例中文仅用于文档，正式业务页面使用 `uiText`/现有国际化。

## BaseTable

源码：[BaseTable.vue](../frontend/src/components/common/BaseTable.vue)。基于 Element Plus 普通表格，负责展示和分页事件，不自行请求、排序服务端数据或保存业务状态。

| Prop | 类型与默认值 | 说明 |
|---|---|---|
| `data` | 数组，必填 | 当前页行数据；服务端分页不要传全部记录 |
| `columns` | 列定义数组，必填 | 见下方列契约 |
| `loading` | boolean，false | 表格加载遮罩；不会禁用外部工具栏操作 |
| `total` | number，0 | 总记录数；为 0 时隐藏分页 |
| `currentPage` / `pageSize` | number，1 / 10 | 受控分页值；每页选项为 10、20、50、100 |
| `selectable` | boolean，false | 显示多选列 |
| `showIndex` | boolean，true | 每页序号，不是跨页业务编号 |
| `showActions` | boolean，true | 显示操作列，默认提供编辑/删除 |
| `showToolbar` | boolean，false | 显示 `toolbar` 插槽 |
| `showPagination` | boolean，true | 是否展示分页区域 |
| `actionWidth` | string 或 number，150 | 固定右侧操作列宽度 |
| `size` | small/default/large，可省略 | 省略时使用全局表格密度 |

列字段：`prop`、`label` 必填；可选 `width`、`align: left/center/right`、`showOverflow`（默认显示溢出提示）、`sortable: boolean | 'custom'`、`render(value, row)`。`render` 返回文本或数字，插值会转义，**不是 VNode、HTML 或任意单元格插槽**；复杂业务单元格应选用已有原生 `el-table` 或扩展后补测试。嵌套关联属性宜先平铺；`render` 实际取值是 `row[col.prop]`。

事件：`update:currentPage(number)`、`update:pageSize(number)`、`selection-change(rows)`、`edit(row)`、`delete(row)`。分页事件由父层更新状态并重新请求；改变 page size 时父层负责回到第一页。当前页为空时，不要将网络错误伪装成“暂无数据”，在表格外显示错误和重试入口。多选行为依 Element Plus，跨页保留不能仅依赖 `selectedRows`。

插槽：`toolbar`；`actions` 提供 `{ row }`。默认空状态固定为“暂无数据”，没有专用 `empty` 插槽。公开实例：`tableRef` 和 `selectedRows`，需要时通过 `tableRef?.clearSelection()` 清除选择。`row-key`、Element Plus 其他属性/事件通过 `$attrs` 传给表格，例如 `row-key="id"`、`@sort-change`；封装自身没有执行排序请求的逻辑。

```vue
<BaseTable
  :data="rows" :columns="columns" :loading="loading" :total="total"
  :current-page="page" :page-size="pageSize" row-key="id"
  @update:currentPage="changePage" @update:pageSize="changePageSize"
>
  <template #actions="{ row }">
    <el-button v-if="canUpdate" link :disabled="saving" @click="edit(row)">编辑</el-button>
  </template>
</BaseTable>
```

只读页面必须 `:show-actions="false"` 或提供权限控制后的 `actions` 插槽，避免无意露出默认编辑/删除。服务端排序使用 `sortable: 'custom'` 与显式映射的排序白名单；客户端 `sortable: true` 只会对当前页排序，不能代表整个数据库有序。

表格宽度为容器的 100%，窄屏横向滚动留在表格内部；父容器设置 `min-width: 0`，为长内容合理指定列宽。小屏分页会换行，操作和页码有触屏尺寸规则。可选大表格请阅读[虚拟表格](虚拟表格-2026-10-15.md)，不是给 BaseTable 添加未知的 `virtual` prop。

## BaseForm

源码：[BaseForm.vue](../frontend/src/components/common/BaseForm.vue)。以 schema 构建简单表单；复杂关联、上传或自定义编辑器使用现有 `el-form` 组合，不强行写入未知 field 类型。

| Prop | 类型与默认值 | 说明 |
|---|---|---|
| `modelValue` | 对象，必填 | 通过 `v-model` 接收更新后的新对象 |
| `fields` | 字段数组，必填 | `prop`、`label`、`type` 必填 |
| `rules` | Element Plus 规则对象，可省略 | 按字段名声明校验，复杂合法性仍由服务端裁定 |
| `loading` | boolean，false | 与内部校验状态共同形成 busy，禁用字段、提交和重置 |
| `submitText` / `resetText` | string，空字符串 | 空值使用当前语言“提交”/“重置” |

字段类型：`text`、`email`、`password`、`number`、`select`、`multiselect`、`date`、`datetime`、`switch`、`checkbox`、`textarea`。字段可选 `placeholder`、`required`、`disabled`、`clearable`（输入/选择默认 true）、`options: { label, value }[]`、`checkboxLabel`、`rows`（文本域默认 4）。目前没有 `field.min`、`max`、`date.valueFormat`、自定义字段插槽或通用字段透传。

事件仅有 `update:modelValue(value)` 和 `submit(value)`；插槽 `actions` **追加**到既有提交/重置按钮后，不替换它们。组件没有 `reset` 事件、公开 `validate()` 或公开表单实例。

提交先等待 `el-form.validate()`；失败由字段展示，不会向外发 submit。验证和 loading 期间防重复提交；异步保存仍须父层立即设置 saving 并在 finally 恢复，不能靠前端防重替代服务端幂等或版本检查。

重置恢复**组件创建时** `modelValue` 的深拷贝并清理校验，不是恢复最近一次接口刷新值。编辑另一个对象时使用不同 `key` 重建表单；异步加载完成后再 `v-if` 挂载。初始数据必须能被 `structuredClone` 克隆，传纯数据，不传函数或组件实例。密码不持久化到本地存储。

```vue
<BaseForm
  v-if="loaded" :key="recordId" v-model="draft" :fields="fields"
  :rules="rules" :loading="saving" @submit="save"
/>
```

`required` 负责字段展示语义，业务约束应明确放入 `rules` 与后端校验。`field.disabled` 只禁用相应字段；没有单独的整个表单 `disabled` prop。无编辑权限应隐藏编辑表单或展示只读内容，不能仅靠禁用按钮保证安全。下拉选项为空时提供文字说明，远程加载、保存错误、页级错误摘要由父层负责。复杂表单可使用 `useErrorSummary`。

## BaseDialog

源码：[BaseDialog.vue](../frontend/src/components/common/BaseDialog.vue)。受控弹窗，确认事件不会自动关闭，父层在成功后修改 `v-model`。

| Prop | 类型与默认值 | 说明 |
|---|---|---|
| `modelValue` | boolean，必填 | 控制显示 |
| `title` | string，空 | 空时使用“对话框”；业务提供可理解标题 |
| `width` | string/number，`'50%'` | 手机端自动替换为 `calc(100vw - 24px)` |
| `loading` | boolean，false | 锁住默认确认/取消、Esc 和受保护关闭 |
| `confirmDisabled` | boolean，false | 禁用默认确认按钮 |
| `confirmText` | string，空 | 空时使用“确认” |
| `showCancel` | boolean，true | 是否显示默认取消按钮 |
| `beforeClose` | `(done) => void` 或 `() => Promise<boolean>` | 回调调用 done 或 Promise 返回 true 才关闭 |

事件：`update:modelValue(boolean)`、`confirm()`、`cancel()`、`close()`。`cancel` 是默认取消按钮实际通过关闭检查时触发；右上角关闭不能当成业务取消事件，统一收尾使用 `close`。插槽：默认内容和 `footer`；自定义 footer 后须自行保留 loading/权限/关闭确认约束。

背景点击不会关闭；内容区最大高 60vh 并独立滚动。关闭检查拒绝/异常会保留弹窗及输入。父层直接设置 `open = false` 不经过 `beforeClose`，所以自定义关闭按钮应主动调用相同检查。安全撤权时可以直接关闭并清空草稿。

```vue
<BaseDialog
  v-model="open" title="编辑记录" :loading="saving"
  :confirm-disabled="!canUpdate" :before-close="guard.confirmDiscard" @confirm="save"
>
  <!-- fields and save error -->
</BaseDialog>
```

正式页面可接入 `useUnsavedChanges`，注意其依赖 Router、Auth Store、页面身份及可编辑条件；不要把弹窗自带关闭保护理解成所有页面都已自动接入草稿保护。表单和弹窗都有默认按钮时，使用弹窗 footer 插槽消除重复提交路径。保留 Element Plus 焦点管理和标题，键盘验证 Tab/Shift+Tab/Esc；没有完成全站读屏认证。

## DataImportButton

源码：[DataImportButton.vue](../frontend/src/components/common/DataImportButton.vue)。导入按钮是包含权限和异步生命周期的业务基础组件，并非任意资源上传控件。

| Prop | 类型与默认值 | 说明 |
|---|---|---|
| `resource` | `'roles' | 'posts'`，必填 | 当前仅角色、岗位；用户导入保留原入口 |
| `loading` | boolean，false | 父页面操作期间禁用两个按钮 |

没有自定义事件、插槽或公开方法；成功消息表示任务登记，不是导入全部完成，不发 `success`/`complete` 事件。到任务中心查看结果和接续，刷新列表由父页面自行安排。

```vue
<script setup lang="ts">
import DataImportButton from '@/components/common/DataImportButton.vue'
</script>
<template><DataImportButton resource="roles" :loading="saving" /></template>
```

组件只在已登录、无需改初始密码、staff/superuser、`data_io` 已开启且有 `data_io:import` 和相应 `role:update` / `post:update` 时显示；岗位另外要求 organization 开启。是否允许写入仍由后端在提交和每行处理时复核。

内置下载 XLSX 模板及选择 CSV/XLSX（非空、最多 10 MiB），确认说明“仅新增、默认停用、不分配权限或人员、最多 5000 行、逐行提交”。不接受 `.xls`。任务部分失败不会撤回已成功行；误提交不能靠取消浏览器请求撤销。取消确认不发送；重复文件事件在 busy 时忽略。用户、令牌、权限、模块、资源变更、组件失活或卸载会使旧响应作废并取消请求，**不等于服务端任务被取消**。

错误显示为 role=alert；模板下载释放 Blob URL。控件可换行、按钮高度至少 44px，长错误换行。上传入口由文字按钮触发隐藏文件 input；保留按钮文字和输入 aria-label，不把图标作为唯一含义。

## 其他常用基础组件

| 组件 | 实际契约 | 使用边界 |
|---|---|---|
| BaseButton | `variant: default/primary/ghost/danger`，`size: small/default/large`，`loading`、`disabled`、`icon`、`type`；默认插槽和 `$attrs` | variant 控制项目外观，type 控制 Element Plus 类型，二者不同；无权限自行隐藏，异步处理仍检查 busy |
| BaseCard | `title?`、`hoverable=false`；default/header/extra/footer 插槽 | 自定义 header 会替换默认标题及 extra 区，需自行保留标题语义；hoverable 不自动使卡片可点击 |
| PersonPicker | `v-model: Person|null`、`purpose: approval/post/message`、`disabled=false`；仅 update:modelValue 事件 | 服务器分页单选；按目的选择接口和可选范围，不能传任意 URL；提交时再次验证人员资格 |

PersonPicker 内含部门和人员加载/空/错/重试状态；部门失败仍允许人员搜索，组织关闭退化为搜索；切页清除候选，卸载和关闭取消请求。375px 时部门区堆叠。当前不提供多选、不公开所有联系方式；人员模型字段以 `api/personnel.ts` 为准。

BaseButton 图标使用已有 Lucide/Element Plus 方式，图标按钮额外提供 `aria-label`，装饰图标不重复朗读。不新增 Emoji 通用图标。颜色和留白优先设计令牌，复用当前主题密度，不建立第二套设计系统。

## 状态、权限与贡献验证

父页面统一负责请求取消、乱序响应、权限失效、未保存数据、保存错误及真正的数据刷新。通用组件不会替父页面证明服务端已写入。建议按以下状态逐项检查：

| 场景 | 必须核对 |
|---|---|
| 加载/保存 | 不重复提交、旧响应不覆盖新身份、切页有取消、按钮锁定正确 |
| 空/错误 | 空列表可理解；错误有说明与重试，不能清空后伪装成功 |
| 禁用/撤权 | 直接 URL/API 仍有后端授权；会话、模块变更后清空旧草稿/敏感响应 |
| 手机/长文本 | 375px 及桌面宽度，表内横滚、不造成页面水平溢出、弹窗可操作 |
| 键盘/无障碍 | 标签和标题、图标按钮名称、Tab 顺序、Esc、错误提示、禁用态和触屏目标 |
| 数据一致性 | 冲突状态、幂等键、部分成功解释、跨页选择和服务端排序语义 |

文档示例使用纯内存或隔离 API，测试不得访问正式账号/数据库。修改组件公共接口时先搜索调用方，更新这里的 API/默认值及示例，再补行为测试；不要只写实现镜像断言。命令在 `frontend` 目录执行：

```powershell
npm run lint
npm run test:typecheck
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p docs/tsconfig.json
npm run test -- tests/base-components.test.ts tests/data-imports.test.ts
npm run test:coverage
npm run build
npm run check:bundle
```

页面交互变化补充现有 Playwright 场景并执行 `npm run test:e2e`；测试配置自动管理独立预览服务，保留失败截图/trace，不连接真实数据。基础组件覆盖率门槛和 CI 说明见[前端开发指南](前端开发指南.md)。本手册选择轻量文档和类型检查示例，Storybook 仍是可选工具，未添加其依赖、部署服务或对外页面。
