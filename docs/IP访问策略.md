# IP 访问策略

P2-11 提供一个默认关闭的 `ip_policy` 可选模块，用于在应用入口按 IPv4、IPv6 或 CIDR 限制来源地址。模块关闭时不增加业务请求开销，也不删除已保存的策略；启用方式沿用项目的显式模块配置和 `check_modules` 预检。

## 规则

- 策略是数据库中的单例，初始值为关闭、允许列表为空、拒绝列表为空、版本为 1。
- 允许和拒绝列表各最多 100 项、总文本长度受限；地址会规范化并排序，重复网段和带 zone 的 IPv6 地址会被拒绝。
- 拒绝列表优先于允许列表。允许列表为空表示不限制来源；允许列表非空时必须命中允许网段。
- IPv4-mapped IPv6 地址同时按映射后的 IPv4 地址和 IPv6 地址判断，任何拒绝命中都优先。
- 数据库读取失败、策略缺失或策略内容无法解析时拒绝请求并返回 503；入口不会缓存跨请求的放行结果。

## 来源地址与入口

应用只在显式配置 `ADMINCORE_TRUSTED_PROXIES` 后信任代理链，并从右向左剥离可信代理；不在可信列表中的代理发送的 `X-Forwarded-For` 不会覆盖直连地址。实时通道使用相同边界并拒绝格式不合法的代理链。生产环境应把 Tunnel、反向代理和容器网段明确写入该配置，不能把任意公网地址配置为可信代理。

除精确的 `/api/v1/health/` 和 `/api/v1/health/live/` 存活/就绪探针外，API、认证、刷新令牌、后台和预检请求都经过策略。静态资源由前置静态安全中间件处理；健康探针不提供业务数据。

## 管理与恢复

读取策略需要 `ip_policy:read`，修改需要 `ip_policy:update`、最近密码验证和当前有效会话。修改采用版本号和行锁；服务端会拒绝把当前管理来源排除在外，所有成功修改写入审计。策略修改后页面应刷新最新版本，遇到 409 需重新读取再提交。

如果配置错误导致管理入口无法访问，只能在部署终端执行受保护的恢复命令：

```text
python manage.py disable_ip_policy --confirm-disable --reason "说明原因"
```

该命令要求明确确认和原因，使用同一单例行锁并写入审计，不提供 HTTP 恢复后门。恢复后应重新检查代理配置、策略版本和审计记录，再决定是否重新启用。

## 验收边界

后端专项覆盖列表规范化、IPv4/IPv6/CIDR、映射地址、拒绝优先、版本冲突、密码复核、管理员防锁死、缺失数据库失败关闭、代理来源、实时通道和恢复命令；全量后端回归与 OpenAPI 严格 schema 均通过。前端提供桌面/手机管理页和 API fixture 浏览器回归；该回归不替代生产 Tunnel、公网容量或真实多代理链路验收。精简构建仍保留模块代码和迁移，运行时默认关闭。
