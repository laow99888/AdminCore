# 编辑版本与冲突处理

本文对应 2026-10-16 本轮实现，说明实际保护范围和验收边界。版本检查与权限复核分别解决旧表单覆盖和旧身份越权，不能互相替代。

## 版本协议与兼容迁移

| 编辑资源 | 请求版本字段 | 持久化及更新语义 | 前端冲突入口 |
|---|---|---|---|
| 用户 | `version`，正整数 | 映射已有 `User.profile_version`；管理员编辑、本人资料更新、批量启停及密码重置会使既有管理草稿失效 | 用户管理 |
| 角色、菜单 | `version`，正整数 | 新增字段默认 1；校验锁后当前值，再修改字段、关联及版本 | 角色管理、菜单管理 |
| 字典 | `version` | 复用已有协议，包含字典项变更 | 字典管理 |
| 部门、人员归属、角色数据范围 | `version` | 复用已有协议 | 组织与数据权限三个页签 |
| 系统参数 | `version` | 复用逐参数版本协议 | 参数表单；只替换冲突参数，保留其他参数的未保存值 |
| 定时计划 | `revision`，不透明字符串 | 复用计划快照摘要；客户端不能把它当递增整数 | 计划编辑对话框 |
| 公告 | `version` | 复用内容、发布状态版本协议 | 公告管理；载入已发布记录后禁用内容编辑和保存 |
| 消息模板 | `revision`，整数 | 复用模板版本协议 | 消息模板编辑对话框 |
| 岗位、任职、示例工单 | 已有 `version` | 保持现有协议 | 已有“重新加载”加丢弃确认；本轮未换成双列比较面板 |

角色和菜单迁移为 `backend/apps/permissions/migrations/0003_menu_version_role_version.py`，既有记录初始化为 1；用户复用既有字段，不需要补字段迁移。更新用户、角色或菜单的 `PUT` 和 `PATCH` 都必须传读取时的 `version`：缺失或格式错误返回 400，过期返回 409，业务数据、关联关系、版本及成功审计均不提交。创建不要求客户端猜下一版本。

```json
{"first_name": "新的显示名", "version": 3}
```

成功后重新使用响应返回的版本。失败时不能直接拉取新版本、保留旧内容后自动重发，否则会重新引入无提示覆盖。批量启停属于显式状态命令，会更新用户资料版本，使其他已打开的编辑表单在下一次提交时冲突；批量接口没有逐项编辑草稿版本协议。

个人设置、密码修改、设备撤销、审批状态转换、任务取消、文件生命周期和导入执行分别沿用各自的资料版本、会话、状态机、生命周期版本或执行摘要契约；这些入口不等同于通用 CRUD 表单。新增业务模块仍必须明确自己的版本边界，框架不会自动给任意扩展加乐观锁。

## 草稿与服务器值的明确选择

`useEditConflict` 负责冲突状态及异步生命周期，`EditConflictPanel` 负责展示。收到编辑 409 后：

1. 保留当前输入及其原版本，暂停重复保存。
2. 用户点击“查看服务器最新值”才读取最新详情，原输入仍不变。
3. 在同一窗口显示版本和逐字段比较；模板正文、公告富文本源内容以普通文本转义，比较面板不渲染原始 HTML。
4. 用户明确点击“载入服务器最新值（替换当前输入）”，才替换字段和版本；此后可重新编辑并提交。
5. 获取最新值失败、权限变化或目标不可访问时显示错误并保留输入，允许再次查看；取消或关闭仍走既有未保存确认。

身份、令牌、权限、模块状态或编辑目标变化会取消比较请求并清空最新快照；即使网络层忽略取消，代次和当前页面检查也阻止迟到响应写回。应用最新值前同样复核当前上下文。新建请求的 409 没有可比较的既有目标，因此走普通“输入已保留”的失败恢复，不展示无法恢复的编辑冲突面板。

比较区使用带名称的 region、加载状态、错误 alert、表格 caption 与列/行标题；按钮支持键盘，最小高度 44px。按钮可换行，长字段在区内换行或横向滚动，不应把窄屏页面撑宽。文案注册在懒加载的 `editConflictMessages.ts`，避免加入登录首屏公共消息包。

## 用户写入与文件操作的授权点

用户创建、更新、删除、密码重置和批量命令均在事务内重新取得活跃操作者、真实 JWT 原设备会话、当前操作权限和数据范围。用户行按主键顺序统一锁定（包含操作者和所有目标），随后重建可见目标列表；角色选项在写入前重新读取并验证。混有不存在、重复或不可访问目标的用户批量请求整批拒绝，不继续使用锁前查询集。

文件操作与通用 Outbox 重试使用共享 `authorize_write`，先复核操作者和会话，再锁定并重新计算目标范围：

| 操作 | 实际契约 |
|---|---|
| 上传 | 入口和事务内都执行已有 `file:upload`；授权完成后才持久化上传 |
| 下载、普通预览 | 入口和事务内都执行已有 `file:download`，仍必须满足文件范围、用途及未删除状态 |
| 软删除 | 当前未登记 `file:delete`；维持活跃身份加文件范围的既有契约，不虚构新权限码 |
| 恢复、回收站逐项操作 | 每项重新检查当前 `file:restore` 或 `file:purge`、范围、生命周期版本；逐项返回成功或 401/403/404/409/503，不承诺整批原子性 |
| 单件彻底删除 | 当前管理员身份、`file:purge`、文件范围及生命周期版本 |
| 文件 PUT/PATCH | 返回 405；文件读取序列化器不是元数据编辑入口 |
| 通用 Outbox 人工重试 | 事务内复核当前管理员及设备会话，事件锁使用 NOWAIT；仅 PostgreSQL 55P03 映射为受控 409，其余数据库故障传播。锁后检查事件终态和有限重试边界；通知投递仍必须通过其专属授权重试入口 |

头像保持专属本人鉴权接口，不会因取得普通 `file:download` 而可从通用文件接口读取。普通用户获得上传或下载授权后仍不能访问范围外文件。授权判定是事务内的明确时点；不能承诺权限撤销会中断已经通过授权的在途事务或已经建立的下载流。

上传的对象存储不参与数据库回滚。本轮对新建记录写入失败、成功审计失败增加补偿：仅删除本次上传已经提交且已知的新对象键，不碰原件或用户既有对象。若外部存储在返回对象键前发生结果不确定故障，或补偿删除本身失败，仍需存储侧孤儿对象巡检；数据库事务不能提供跨对象存储的原子提交保证。

这里的后端专项使用测试数据库，不能代替真实 PostgreSQL 的多连接等待、锁顺序和数据范围竞争。新增 `scripts/validate_outbox_retry_concurrency.py` 仅允许配置库名和 SQL 实际库名均为 foundation：真实消费者锁事件后等待管理员行，真实 JWT 人工重试持有管理员行时通过 NOWAIT 返回 409、释放身份锁，消费者继续并仅投递一次；用 `pg_blocking_pids` 证明真实等待，不 mock 权限或消费业务。脚本禁止任务故障邮件，成功只清理其专属 UUID 夹具，失败保留标识；本子任务只编译，真实 PG 运行交主代理。

主代理另有真实写边界脚本并负责全量回归、构建预算及浏览器矩阵；以其最终集成报告为准。本子任务未启动 Docker、访问正式数据或读取实际环境凭据，未提交推送；没有遗留服务 PID，18411 未占用。失败诊断日志和测试框架保留的临时媒体不作未知范围批量删除。
