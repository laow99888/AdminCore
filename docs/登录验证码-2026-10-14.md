# 登录失败门槛与图形验证码

本批提供可选的登录验证码。默认关闭，通过部署环境启用；验证码是登录限流之外的附加门槛，不代替密码、双因素认证，也不能保证阻挡 OCR 或分布式攻击。

## 配置与用户流程

```dotenv
AUTH_LOGIN_CAPTCHA_ENABLED=True
AUTH_LOGIN_CAPTCHA_FAILURE_THRESHOLD=3
```

门槛可设置为 1 至 5，默认 3。同一来源 IP 与用户名组合在固定十五分钟窗口内失败达到门槛，或同一 IP 累计十次失败，即要求验证码。计数不查询账号是否存在；成功登录清零该组合，不清零 IP 聚合计数。正常的第二因素提示不算失败，错误的第二因素算失败。已有登录限流继续生效，验证码不会解除 429。

用户按原流程输入用户名和密码，服务端要求时才显示验证码。图片为本地生成的五位字母/数字，排除易混字符，有效期两分钟；刷新废止前一枚。每次校验都会消费当前绑定的验证码，答错、过期或登录结果不确定后须重新获取。验证码绑定来源与用户名，跨绑定请求不能使他人的验证码失效。完成验证码之后仍须通过密码及账号已启用的第二因素。

前端提供加载、刷新、过期及错误提示，用户名变化和页面离开清除旧挑战；答案与挑战不进入 URL 或浏览器持久化。无法识别时可刷新，仍不能完成时可联系管理员协助或等待失败窗口到期。图形文字识别仍有可访问性限制，本批没有提供独立的无认知测试认证路径，不能据此声称全面满足 WCAG 2.2 可访问认证要求；项目可关闭这一附加门槛。

## 服务与数据

匿名 `POST /api/v1/auth/login-captcha/` 接受 JSON `{username}`，仅返回是否需要挑战，必要时附 UUID、PNG data URI 和期限。接口不返回答案，不根据用户是否存在产生不同结果。登录在原字段之外接受 `captcha_id`、`captcha_code`；达到门槛的本次认证失败返回 401 与 `captcha_required`，提示立即获取图片；随后缺少必要证明返回 400 与 `captcha_required`，错误或失效证明返回 400 与 `captcha_invalid`。认证与挑战响应禁止缓存。

共享计数及挑战消费由数据库事务负责，标准 PostgreSQL 部署和没有 Redis 的精简部署使用相同机制；SQLite 单元测试不能证明 PostgreSQL 行锁与并发语义。挑战答案只保存服务端密钥参与计算的摘要，图片及明文答案不落库。数据库故障时拒绝签发认证结果并返回暂不可用，不退化为跳过验证码。

刷新另有每 IP/组合每分钟十次限制。过期挑战与计数在保留一天后接入已有会话清理任务，每类每轮最多一千条；关闭 worker/beat 的精简部署需运维定期执行该清理任务。关闭验证码不删除既有业务数据。密码、答案和认证令牌不写入新增审计内容。

## 验收记录

本机完整回归通过：658 项后端 pytest、211 项 Vitest、398 项 Playwright 桌面/手机回归，以及 lint、类型检查、生产构建、分包预算、基础组件覆盖率门槛、OpenAPI 严格校验和迁移遗漏检查。登录首屏 JavaScript gzip 174,849 字节，图表及 PDF 不进入登录首屏。覆盖率仅针对配置中登记的基础组件，浏览器用例包含模拟 API，不代表全站覆盖率或容量结论。

真实 PostgreSQL 验证在精简无 Redis与标准 Redis 环境各通过 88 项验证码专项，覆盖跨进程共享门槛、同挑战并发恰一次成功、成功后旧挑战重放拒绝、跨绑定保护、刷新限频、密码与第二因素串联，以及 SQL 故障时无令牌/会话/成功审计。答案只在测试的图片渲染边界捕获，不增加产品读取答案接口。

并发复核另发现旧计数记录首次无锁读取后可能被过期清理删除，导致后续锁查询返回 500；已改为首次查询即加行锁。两类实际 PostgreSQL 竞争用例确认清理等待行锁，使用方续期后清理重新检查并保留记录。专项固定分钟循环冻结测试窗口，避免跨分钟产生偶发误报；产品时钟不冻结。
