# 后端错误消息国际化

## 交付约定

| 项目 | 内容 |
|---|---|
| 范围 | API返回的系统message、DRF嵌套字段错误、模块门禁和独立SSE错误支持简体中文/英文；数值限制等动态提示使用固定模板。业务正文、字段名、reason/code、文件和持久审计不翻译 |
| 默认启用 | 无需外部开关或数据库迁移，缺省中文；Django语言协商支持en-US→en、zh-CN→zh-hans，不支持语言回退中文。客户端按当前界面偏好发送白名单Accept-Language |
| 外部依赖 | 复用Django语言上下文、DRF ErrorDetail和仓库内静态JSON目录，无翻译服务、网络调用或新增依赖 |
| 权限范围 | 语言不改变认证、状态码、数据范围、请求摘要、幂等键或重试语义；公开验证码/恢复使用独立无JWT传输，刷新和SSE也发送相同语言头 |
| 关闭/回退 | 请求中文即保持原中文行为。未知新业务消息原样回退，不伪造翻译；新增消息应登记目录并通过完整性检查。历史任务错误/审计/通知正文不被追溯改写 |
| 验收 | 后端目录/模板占位符/语言协商/字段及业务边界/幂等与并发SSE专项；全量pytest、前端单测/类型/构建/预算/桌面手机；真实导出项目验证Nginx后端返回中英文错误 |

## 实现与扩展

`backend/apps/core/error_messages.en.json` 按已有中文服务端消息映射英文。`error_i18n.py` 仅翻译顶层message和ErrorDetail叶子，保留ErrorDetail.code以及普通业务值；JsonResponse门禁仅处理固定message，流式响应不读取。返回Content-Language，并按Accept-Language区分缓存。

字段校验沿用Django/DRF现成语言目录；自定义动态值通过 `error_text('必须为 {minimum}–{maximum} 的整数', minimum=1, maximum=5)` 格式化，值不作为格式字符串。禁止用f-string拼完再试图替换用户内容。静态目录测试检查当前app中已知API异常继承链、message、default_detail和占位符一致性，阻止遗漏静态中文及动态中文拼接；该检查不替代新业务的请求测试。

幂等结果在本地化之前持久化；同一请求换语言重放不新增业务记录，不把业务标题中恰好相同的中文误翻译。SSE使用独立请求语言上下文，并在连接结束或异常退出后恢复，事件名称和数据契约保持不变。
