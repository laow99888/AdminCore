# 文件中心目录与标签深化：第八批

本批推进深化路线图第7项，完成个人目录、标签和文件筛选。它是个人整理能力；团队目录、文档历史版本、业务引用保护和容量配额仍未完成。不会因为本批交付把整个文件中心深化目标标记完成。

## 行为与边界

- 文件页支持新建目录、重命名、移动、删除，以及为可读文件设置个人目录和标签。共享同一文件的两个用户拥有独立整理信息，不能看到或修改对方的目录、标签。
- 目录和标签不授予文件访问权，也不改变现有ACL。撤销文件访问权后，文件不再出现在该用户的目录结果、标签候选或普通文件列表，整理写入也被拒绝。恢复原授权后，保留的个人整理信息可重新可见。
- 文件属于一个个人目录或未分类，可设置最多10个标签，每个32字。目录名称最多80字；名称进行NFC规范化和首尾空白清理，拒绝控制字符及路径分隔符，同级目录按大小写折叠检查重名。标签重复按同样方式检查；筛选按保存后的标签精确匹配。
- 每个用户、每个租户范围最多200个目录，最多8级。服务端检查循环、自身/后代移动，以及父目录移动后所有后代的深度。目录筛选只匹配选中目录，不隐式包含后代；可以与标签及原有文件关键词搜索组合。
- 删除目录仅移除分类，文件归入未分类，保留文件本体、标签和ACL。存在子目录时拒绝删除，须先处理子目录。删除目录不会操作存储对象。
- 候选标签只取当前仍可读文件上的个人标签，最多100项；超限提示仍可输入完整标签精确查询。不会返回其他用户的标签。
- 目录及整理记录有独立版本；初次整理提交版本0，已有记录必须提交当前版本。更新及删除目录都会校验版本；删除目录也递增受影响整理记录的版本，防止旧表单覆盖。它们不是文档内容版本，也不替代原有文件生命周期版本。
- 写入口在事务内先复核并锁定当前用户与会话，再锁文件，重新检查读取授权。ACL替换入口统一采用用户→文件顺序。真实PostgreSQL验证同名目录并发创建与同一文件首次并发整理只成功一次。
- 多租户启用时，个人整理按当前租户隔离；平台管理员未选择租户不能把其他租户的文件放入全局目录。旧文件没有整理记录时返回版本0、空目录和空标签。
- 新接口成功响应使用`private, no-store`。审计与写事务一起提交，记录结构标识、版本、操作和内容摘要，不记录原始目录名、标签；审计失败则回滚整理变更。

本批没有新增必需服务。文件模块继续可选，不改变精简项目的服务需求。目录数量和深度限制是功能预算，不代表已经通过任意数据量的性能压测。

## 页面与接口

复用现有Element Plus和主题变量，提供中英文消息、加载/读取失败重试、禁用、空目录和保存失败提示。普通失败保留输入；409冲突关闭旧编辑草稿并刷新，用户重新打开后编辑。切换用户、会话、租户、权限或模块状态时清空个人信息，取消读取；迟到响应不能覆盖新身份或卸载后的状态。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/files/library/` | 当前用户、当前租户的目录及可见标签候选 |
| `POST /api/v1/files/library/folders/` | 新建目录，必填名称及父目录，根目录传`null` |
| `PUT /api/v1/files/library/folders/{id}/` | 名称/父目录及当前版本 |
| `DELETE /api/v1/files/library/folders/{id}/` | 请求体带当前版本，删除个人分类 |
| `PUT /api/v1/files/{id}/organization/` | 替换该文件的个人目录、标签，必填整理版本 |
| `GET /api/v1/files/?folder=...&tag=...&search=...` | 授权结果内精确筛选，`folder=unfiled`表示未分类 |

新写入口拒绝非对象、未知字段、重复表单键和无效字段；旧文件元数据PUT/PATCH继续拒绝。前端SDK同步新增接口，目前全量契约为214条路径。

本页本地导出/打印使用已加载的筛选页；原有服务端全量文件导出仍按其已登记资源范围执行，**不继承这里的个人目录/标签筛选**。本批没有宣称新增异步文件导出能力。
