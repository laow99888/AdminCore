# 会话、设备管理与密码二次确认

本批覆盖本人设备会话、管理员在线用户及指定用户全部设备下线。会话属于认证核心，精简部署也保留；前端入口为系统设置的“管理设备”和管理员“在线用户”。

## 行为与边界

- 每次登录/注册登记独立 UUID 会话，JWT 强制带 `sid`。设备提示只保存清洁且截断的 User-Agent 与登录 IP，不能作为可信设备身份。“在线”表示近期使用过且仍有效的 API 会话，不是实时在线检测。
- 默认空闲期限 30 分钟、绝对期限 24 小时，活动时间最多每 60 秒写库一次。刷新延续同一会话，不能延长绝对期限。参数见 `.env.example`，配置要求登记间隔不大于空闲期限、空闲期限不大于绝对期限，绝对期限最多 30 天。
- `/auth/logout/` 现在只撤销当前设备。本人可查看分页会话列表并指定设备下线，包括当前设备；撤销当前设备后页面返回登录页。修改或重置密码仍使全部旧凭据失效。
- 管理目录仅开放给管理员并检查 `session:read`，下线需要 `session:revoke`。数据范围沿用统一 user 范围入口；当前仓库 staff/superuser 具有全范围。只对所选用户操作，禁止管理员从此入口撤销自己全部设备，无全库批量下线接口。
- 本人指定设备下线及管理员全部设备下线都在当前 JSON 请求提交 `current_password`。密码不存浏览器偏好、不缓存确认凭据、不写数据库/审计；提交后立即清空输入。错误密码按用户及操作分别限制，默认每分钟总计 10 次、单操作 5 次；缓存故障拒绝操作并返回通用 503。
- 用户行与会话行在同一事务内锁定和复核；管理员涉及两个用户时按 UUID 顺序锁定。密码、账号状态、设备撤销变化在等待后重新检查，个人资料/头像及公告敏感写也复核当前设备。撤销事务包含不含凭据的操作审计。
- Refresh 单次使用并轮换，同一 Refresh 并发只允许一次成功。数据库只保留 refresh JTI；新签发的 OutstandingToken 原文清空。升级前的旧 JWT 因没有登记 `sid` 必须重新登录；升级前既有黑名单历史记录不会被此迁移改写。
- 现代浏览器通过 Web Locks 协调同源多个标签页刷新，并防止退出/重新登录后的迟到响应覆盖新凭据。没有 Web Locks 的旧浏览器只提供已完成轮换复用，极端同时刷新仍可能需要重新登录；公网生产应使用 HTTPS。
- 会话与在线用户响应使用 `private, no-store`，目录只返回必要字段。失效会话保留至少 30 天后分批清理，每次最多 1,000 条；过期刷新登记同样清理。标准部署幂等登记每日 03:45 核心维护计划，保留已有计划调整。精简部署没有 worker/beat，需自行调度该任务。

## API

| 方法与路径 | 用途 |
| --- | --- |
| GET `/api/v1/auth/sessions/` | 本人有效设备分页 |
| DELETE `/api/v1/auth/sessions/{uuid}/` | 本人指定设备撤销，JSON 当前密码 |
| GET `/api/v1/auth/online-users/` | 管理员有效用户分页与姓名/用户名搜索 |
| POST `/api/v1/auth/online-users/{uuid}/revoke/` | 指定用户全部设备下线，JSON 管理员当前密码 |

分页沿用 `data.items` 和 `data.pagination`；撤销成功返回 `data.revoked_count`。已有角色升级只登记新权限，不自动扩大授权；新库默认管理员角色包含新权限。本人管理入口无需管理员权限。
