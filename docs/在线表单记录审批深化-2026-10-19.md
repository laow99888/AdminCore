# 在线表单记录审批深化（2026-10-19）

在线表单可选绑定审批流程，形成“记录保存→提交审批→终审回写”的闭环。不启用审批或不绑定流程的表单继续使用原记录协议。审批模块通过受信静态业务适配器调用本模块，不在通用引擎中写入表单专用逻辑。

## 定义与版本

设计器选择同租户已发布的 V2 流程编码。表单发布时服务端重新解析并冻结实际流程 ID、编辑版本；流程输入必须与表单顶层已登记字段类型一致，不允许附件、明细、任意 JSON 或未登记字段作为流程输入。后续同编码流程发布新版本，不改变旧表单、旧记录和已有审批的路由；旧流程归档仍可承接已冻结表单。

发布后的表单定义和流程关联不可原地修改。创建下一版只复制流程编码，下一次发布再显式冻结当时可用流程版本。迁移 `online_forms.0004_record_approval` 给存量表单增加可空的关联，存量记录默认未送审；不改写已有数据、冻结定义或版本号。

## 状态与权限

本人记录拥有独立的 `record_submit` 和 `record_withdraw` 权限。每次操作必须提交严格的正整数记录版本；重复送审、陈旧版本、修改审批中或已通过记录均返回冲突。未送审、已驳回、已撤回允许按原冻结定义修改后再次送审，每次送审新建申请并保留旧申请和快照。

送审重新计算并验证冻结字段、审批输入和附件 ACL，使用服务端记录构造快照，忽略客户端伪造快照。附件同时追加到表单历史引用和审批引用，删除受保护。审批中心通过、驳回或撤回时，在同一数据库事务内校验当前申请、租户、申请人和冻结流程并回写记录状态、增加记录版本、写审计。撤回与终审统一按“申请→记录”加锁；真实 PostgreSQL 并发测试验证仅一个操作成功。

## 快照展示边界

参与审批不自动授予表单数据读取权限。每次读取审批重新检查在线表单模块和当前 `record_read` 权限；不满足时隐藏动态业务快照。可展示的快照只按冻结定义逐层投影已知字段，顶层与明细中的所有附件、业务关联 UUID 及其敏感配置均剔除，流程 `extra_data` 也不直接返回。未知、畸形或校验失败的定义整体隐藏，不能借任意嵌套 JSON 扩大访问。附件和业务关联授权访问仍由具体表单/记录上下文接口完成。

前端记录显示审批状态和审批中心入口；送审、撤回带当前记录版本。已通过记录不显示修改/再送审，审批中只显示撤回。权限或租户切换使旧请求失效，迟到响应不能重新打开旧记录。错误保留上下文并提供可聚焦提示。
