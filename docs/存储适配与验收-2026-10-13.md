# 存储适配与验收

日期：2026-10-13。本批交付本地文件系统和 S3 协议存储，通过真实 MinIO 独立实例验收。AWS S3 的云端账号、IAM 和网络部署、阿里云 OSS 原生适配、基础在线预览仍待对应验收或实现。

## 交付范围

| 项目 | 实现与边界 |
|---|---|
| 功能范围 | 上传、原 API 鉴权下载、Excel 导入读取、软删除及过期物理清理；存储接口媒体归档、恢复、失败回滚；两种后端之间保留对象键的复制迁移 |
| 默认启用 | 所有预设默认 local，沿用媒体卷。s3 为部署配置选择，后端、worker、beat 必须使用同一配置并重启；不新增前端页面 |
| 外部依赖 | django-storages 1.14.6、boto3 1.43.112，传递依赖固定于哈希锁文件。仅 s3 模式需要预建私有桶和有效凭据；不自动创建正式桶或安装 MinIO 服务 |
| 权限与数据范围 | 文件原有用户/数据范围规则继续执行。API 返回鉴权下载地址，未向客户端分发存储签名地址。凭据和端点仅由部署管理，系统参数管理接口不能修改 |
| 关闭与迁移 | 改成 local 不删除远端对象，也不会自动搬迁文件。切换配置前必须停写、复制并校验；对象键和数据库引用保持不变。源文件保留，可回切 |
| 验收条件 | 后端全量回归、迁移/schema 检查及真实 MinIO 协议测试；本地和 Linux CI 分别记录结果。签名过期验收针对存储适配器，不表示已新增直接签名下载 API |

## 配置

默认不需要新增 `.env` 项，`ADMINCORE_STORAGE_BACKEND=local` 使用原媒体卷。对象模式参照 `.env.example`：

```dotenv
ADMINCORE_STORAGE_BACKEND=s3
S3_BUCKET_NAME=项目专用私有桶
S3_ACCESS_KEY_ID=实际部署凭据
S3_SECRET_ACCESS_KEY=实际部署凭据
S3_ENDPOINT_URL=https://实际对象服务地址
S3_REGION_NAME=us-east-1
S3_LOCATION=admincore
S3_ADDRESSING_STYLE=path
S3_ALLOW_INSECURE_HTTP=False
```

AWS S3 的端点可留空，区域使用实际桶所在区域。MinIO 使用服务 HTTPS 地址，容器里的 localhost 指向该容器，须填写容器可达地址。只在隔离开发环境明确设置 `S3_ALLOW_INSECURE_HTTP=True` 允许 HTTP。TLS 证书验证保持开启。

桶须关闭匿名访问；凭据只授权媒体专用前缀的列举、读取、写入、删除及必要的桶定位权限。`S3_LOCATION` 必须非空，避免备份恢复操作整个桶。管理此命名空间的其他服务也须参与停写，否则无法保证数据库与媒体的一致快照。桶版本控制/对象锁/生命周期由服务侧管理，版本保留与物理释放容量不能等同于删除当前对象键。

对象默认无 public ACL，适配器签名链接有效期 300 秒，关闭同名覆盖，内存缓冲阈值 8 MiB，连接/读取超时 5/30 秒，标准重试最多 3 次额外尝试。API 继续提供附件下载；S3 读取由存储库暂存到可溢写磁盘的文件后送入 FileResponse，不能把它当作无暂存代理或大文件断点下载。上传仍受现有文件大小与类型限制。

## 复制迁移与回切

先备份并停止 frontend、backend、worker、beat 及其他写入方。在原 `.env` 中填写目标 S3 参数，但暂不改变模式。以下命令通过显式入口运行，不启动应用服务：

```bash
docker compose stop frontend backend worker beat
docker compose run --rm --no-deps -T --entrypoint python backend manage.py copy_media --source local --destination s3
docker compose run --rm --no-deps -T --entrypoint python backend manage.py copy_media --source local --destination s3 --execute
```

默认只预览；执行时逐文件复制并验证 SHA-256。同名且内容一致则跳过，可重复执行；同名且内容不同在复制前拒绝，不覆盖源或目标。中途失败保留已经验证的副本，再次执行可续做。该命令复制活动媒体命名空间，不复制恢复隐藏副本，不修改数据库字段，不删除源文件。历史异常手工对象键须先检查，不支持符号链接媒体。

成功后将 `ADMINCORE_STORAGE_BACKEND` 改成 s3，执行 `docker compose up -d --wait`，验收现有文件下载和导入任务。回切使用 `--source s3 --destination local`，仍须停写；若本地已有不同内容同名文件，先人工确认冲突原因，不能强行覆盖。新安装环境构建使用 `docker compose build backend worker beat frontend`。

## 备份与恢复

`scripts/backup.sh` 停写后调用 `docker/media_backup.py`，媒体归档通过存储接口读取并以原对象键保存为 `media/...`；数据库 custom-format dump 与两个固定文件的 SHA-256 清单仍沿用原格式，已有安全媒体归档兼容。备份失败只保留 partial，不发布完整备份。

`scripts/restore.sh` 保留原数据库 staging、事务改名和失败回滚流程。媒体归档先验证路径再解压到媒体卷中的 staging；对象模式仍需要该卷的临时磁盘空间。切换时旧对象复制至配置媒体前缀下 `.admincore-restore-<标识>/old/...`，校验成功并记录日志后才删除活动键；新文件上传失败可依日志恢复旧对象。存储桶/前缀/端点/区域变化会阻止恢复，避免回滚时误操作另一命名空间。

旧数据库、旧媒体和恢复日志都保留，业务验收后由运维清理。回滚开始前会验证全部旧对象的已记录 SHA-256，副本缺失或损坏时保留当前文件并停止回滚。归档排除恢复隐藏副本。断网时回滚也可能失败，此时原脚本保持服务停止并保留现场；须恢复连接再人工复核。跨桶快照一致性、超大规模恢复、正式 AWS/OSS 环境和异地自动备份未在本批验收。

## 可重复验收与证据

```powershell

venv/Scripts/python.exe -m pytest
venv/Scripts/python.exe manage.py makemigrations --check --dry-run
venv/Scripts/python.exe manage.py spectacular --validate --fail-on-warn --file ../.codex-validation/storage-schema.yml
cd ..
backend/venv/Scripts/python.exe scripts/validate_storage.py
```

真实协议验收程序下载 [MinIO 官方固定发布](https://github.com/minio/minio/releases/tag/RELEASE.2025-09-07T16-13-09Z)，执行前验证 Windows/Linux 各自的官方 SHA-256。程序保留在忽略的 runtime 缓存，不分发进项目或生产镜像；MinIO 许可证见官方仓库。实例绑定随机本机端口、使用随机测试凭据和独立桶，测试后只停止记录的 PID。成功删除本次实例数据，保留 report.json、JUnit 和日志；失败保留数据及日志。

协议测试包括真实文件 API 与越权/匿名拒绝、私有对象、有效/过期签名、双向复制、正式媒体归档恢复入口及回滚、实际对象清理、Excel 导入、复制命令预览/重复执行/冲突拒绝。单元测试另覆盖配置拒绝、无 `.path` 后端、旧副本失败不删除原文件、新上传失败回滚、配置变化拒绝以及清理故障记录失败并保留数据库引用。
