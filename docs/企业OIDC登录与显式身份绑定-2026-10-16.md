# 企业 OIDC 登录与显式身份绑定

本能力属于可选模块 `sso`，默认关闭。实现标准 OIDC 授权码流程与 S256 PKCE，用于已显式绑定的现有本地账号。独立登录入口为 `/enterprise-login`，管理入口为 `/integrations/identities`，API 为 `/api/v1/sso/`。本地 `/login` 始终保留。

## 部署配置

启用 `ADMINCORE_MODULES` 中的 `sso`，完成迁移，并配置以下环境变量。配置只由部署者维护，不接受请求或业务表中的任意供应商 URL。

| 设置 | 约束 |
| --- | --- |
| `SSO_ISSUER` | 与 ID Token 的 `iss` 完全一致，区分路径和尾斜杠 |
| `SSO_AUTHORIZATION_ENDPOINT` | 供应商授权端点 |
| `SSO_TOKEN_ENDPOINT` | 供应商令牌端点 |
| `SSO_JWKS_URI` | 供应商公钥集合端点 |
| `SSO_CLIENT_ID` / `SSO_CLIENT_SECRET` | 固定机密客户端；令牌端点使用 client_secret_basic |
| `SSO_REDIRECT_URI` | 完整固定地址，路径必须为 `/api/v1/sso/callback/` |
| `SSO_FRONTEND_ORIGIN` | 同源前端 Origin，不含路径及尾斜杠 |
| `SSO_ENCRYPTION_KEY` | 独立 Fernet 密钥，用于短期 PKCE verifier 加密；代码拒绝复用 `SECRET_KEY`、`AUTH_TOTP_ENCRYPTION_KEY` 或 `ADMINCORE_FIELD_ENCRYPTION_KEY` |
| `SSO_LABEL` | 显示名称，默认企业身份登录 |
| `SSO_SESSION_SECONDS` | 300–3600 秒，默认 3600；不会延长既有会话绝对期限 |

生产配置使用可信 HTTPS、公网地址、443 端口。授权/token/JWKS 必须与 issuer 同源；callback 与前端必须同源。本版不自动 discovery、不跟随重定向、不使用环境代理、不支持私网 IdP/自签名证书或跨源多端点。管理员须先确认供应商支持 `response_type=code`、`response_mode=query`、S256、`scope=openid`、`prompt=login`、`max_age=300`、RS256 和含 `kid` 的公钥集合。

依赖固定为 `Authlib==1.9.1`、`joserfc==1.6.8`，复用已固定 Requests 与 cryptography。官方资料：[Authlib Requests OAuth 客户端](https://docs.authlib.org/en/stable/oauth2/client/http/requests.html)、[joserfc JWT](https://jose.authlib.org/en/guide/jwt/)、[OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html)、[OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)。

## 身份和会话边界

管理员从供应商控制台获取不可变、区分大小写的 `sub`，在管理页核对本地用户 UUID 后，以本人当前密码确认绑定。必须同时具备管理员身份和 `sso:bind` 权限；仅授予普通角色此权限不会允许绑定。目标本地账号必须启用、具备可用密码且完成初始改密。身份由 `(issuer, sub)` 唯一确定，绝不根据邮箱、用户名、供应商 role/group 声明自动绑定、创建用户或授予权限。供应商邮箱不会成为本地已验证的找回邮箱。

每个 issuer 的本地用户和 subject 都唯一。撤销记录作为防止身份误分配的持久记录保留，本首版不提供重新分配已撤销身份到另一账号或重新激活绑定的 UI。批量同步、SCIM、多个供应商及角色映射不属于本版。

state、nonce 和浏览器 Cookie 使用随机值，state/nonce/完成凭据在数据库仅保存不可逆摘要。state 最长 5 分钟，callback 在网络兑换前先提交单次消费；兑换失败必须重新发起，不重放授权码。PKCE verifier 加密保存，消费时清空。回调只跳转到固定前端结果页，不在前端网址中传递本地 JWT、IdP token 或可复用确认凭据。

供应商验证成功后，最长 2 分钟的 HttpOnly/SameSite=Lax 完成 Cookie 还需要本地安全校验。启用 TOTP 的账号必须提交本地动态码或一次性恢复码；现有验证码门槛、账号状态、强制改密、密码指纹、全局会话版本均继续检查。未完成本地校验不会签发 JWT。请求发起与完成必须为同源 JSON POST。供应商 MFA 声明不代替本地 TOTP。

企业会话复用现有设备会话、当前角色权限和数据范围，携带签名 `sso` 标记并关联身份记录。访问与刷新都检查绑定版本、供应商配置摘要和模块状态。撤销绑定立即撤销对应企业会话；修改密码/全局下线继续按原规则撤销。本地会话不受单个企业绑定撤销影响。配置变更（含密钥轮换）会使旧企业会话失效。

供应商故障阻止新的企业登录，不回退为未经验证的身份。已签发企业会话可在本地最长 1 小时内继续，受本地撤销规则限制；当前不实现供应商 back-channel logout、SCIM 或逐请求 IdP 查询，供应商单方面禁用账号不会被宣称为瞬时撤销。供应商撤权需同时停用本地账号/撤销绑定，或等待企业会话期限结束。管理员应保留至少两个本地应急账号及其 TOTP 恢复方式。

## 网络、日志和清理

token 与 JWKS 两次网络请求共用 15 秒硬预算；DNS 每次等待不超过 3 秒且仅允许最多 4 个在途解析。全部解析地址必须公网，并固定选定 IP 建立连接，TLS 仍以原 hostname 校验证书与 SNI。定时器对底层 socket 执行 shutdown/close，覆盖握手、慢响应头和不足读取块大小的慢正文；响应体最多 64 KiB。拒绝异常 Content-Type、压缩、重复 JSON 字段、错误算法/kid、私钥 JWK、错误 issuer/aud/azp/nonce、过期或过旧 auth_time。禁止记录对端错误文本、authorization code、state、token、client_secret、动态码和恢复码。

反向代理必须使用不含 query 的访问日志；禁止以 `$request`、`$request_uri` 或 `$args` 记录 callback 请求。应用只记录固定安全失败原因和必要账号事件。成功登录、绑定、解绑和会话写入同一事务；审计写入失败则回滚会话/绑定/TOTP 消费，不能无审计放行。

`core.cleanup_expired_sessions` 复用现有定时维护，按批清理过期至少 1 天的 `LoginFlow`，即使模块关闭仍清理，删除前复查期限。有效绑定和审计记录不由该瞬时数据清理删除。

## 验收范围

运行 `backend/venv/Scripts/python.exe -X utf8 scripts/validate_sso_contract.py`。脚本强制测试设置：内存 SQLite、进程内缓存、隔离媒体目录。测试自身启动并关闭 loopback OIDC HTTP 对端，执行真实授权码单次兑换、S256 验证、RSA 签名/JWKS；TLS 测试使用一次性测试证书，验证慢响应硬截止、自签名拒绝与原 hostname 校验。只在 `TESTING=True` 的测试 fixture 内允许 loopback；生产不提供私网跳过开关。

实际 PostgreSQL 验收脚本为 `scripts/validate_sso_postgres.py`，由隔离 foundation 验收器通过 `manage.py shell` 执行。脚本断言 PostgreSQL 和数据库名 `foundation`，创建临时本地账号、显式绑定及隔离 HTTP OIDC/RSA 对端；并发两个 callback 仅允许一次 code 兑换，并发两个完成请求仅签发一个企业会话，随后验证解绑使旧 access/refresh 失效但本地会话继续可用。脚本清理自身账号/绑定/流程/日志并关闭测试对端。这个验收使用实际 PostgreSQL 与真实隔离协议端点，仍不代表真实企业身份供应商已接通。

当前独立专项结果：后端 67 项通过（含真实 TLS 4 项），前端单测 11 项通过，SSO 前后端静态检查及全模块严格 OpenAPI 校验通过。实际 PostgreSQL 和浏览器桌面/移动验收由完整 foundation 集成流程执行，其结果以集成报告为准。

前端专项：`npm test -- tests/sso.test.ts tests/sso-views.test.ts tests/sso-session.test.ts`。桌面/移动 E2E：`npx playwright test e2e/sso.spec.ts`，使用 API mock 检查密码确认、动态码失败重试、本地应急入口、权限/模块门禁与页面溢出。前端 mock 测试不替代 OIDC 协议测试。

尚未接入真实企业供应商凭据。真实接入前需要在供应商测试租户登记固定 callback、核对 subject、配置可信证书/公网端点，并实测成功登录、本地 TOTP、供应商拒绝/断网、绑定撤销与本地应急登录。隔离协议与 TLS 测试通过不能声称某个实际供应商已完成验收。
