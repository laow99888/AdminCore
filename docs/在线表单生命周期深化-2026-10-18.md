# 在线表单生命周期深化（2026-10-18）

本轮交付同编码发布版本、历史定义冻结和本人记录管理。计算字段的后续增量见《在线表单受控计算深化-2026-10-18.md》。授权附件/关联选择、审批联动仍未完成。

## 版本和发布

- `release_number` 是编码内的发布序号，首版为 1。`version` 是每条表单/记录的并发修订号，两者含义不同。
- 现有编码不可修改。初次新建重复编码返回字段错误；为已有编码演进请使用 `POST forms/{id}/new-version/`，请求包含源版本的 `version`。
- 已发布或归档版本可以派生下一版草稿，复制当时的定义，序号取当前最大值加一。一个编码最多一个草稿和一个发布版本；已有草稿时返回 409，不覆盖草稿。
- 草稿发布前重新验证持久化定义；同一事务内归档旧发布版并切换当前发布版。失败保留旧发布版。
- 当前发布版仍可供用户提交，不受未发布草稿影响。归档全部版本后，不再接受新提交；旧记录仍允许本人读取、按原定义修改。
- 创建草稿、发布、归档、提交及修改记录按首版→操作版本→记录的顺序加锁，数据库唯一约束作最后防线。派生版和新记录显式继承源表单租户，避免无租户头的管理员控制面请求产生无租户派生数据。

## 提交和旧客户端

新客户端提交 `POST {code}/records/` 时携带 `{form_id, data}`，`form_id` 必须为页面加载的发布版本 ID。页面打开后切换了发布版则返回 409，并保留输入；不会把旧表单数据误交到新定义下。

为兼容现有集成，`form_id` 暂为可选。未传时按提交瞬间的当前发布定义验证：字段名变化通常会得到 400，但相同字段名对应不同语义时，服务器无法判断客户端是否过期。需要发布版本绑定的集成必须传 `form_id`，不能依赖此兼容路径检测旧页面。成功请求的幂等重放继续返回原记录，不会因新版本发布再创建记录；授权检查先于重放。

## 历史记录和权限

- 记录创建时冻结 `definition_snapshot`，包含布局、字段及校验规则。修改使用这一快照，不采用当前发布定义，也不接受客户端提供快照。
- 列表为当前用户本人记录，跨发布/归档版本查询；可按 `release_number` 筛选。详情返回冻结定义，列表不重复携带定义。
- 详情和修改仍按租户、本人及 `online_form:record_read` / `online_form:record_update` 授权；管理身份不自动获得他人记录。设计操作保持管理员和对应权限要求。
- 记录更新携带 `version`。并发冲突返回 409，前端保留编辑输入。保存成功后仍停留在详情，转为只读并刷新列表；关闭未保存编辑需要确认。
- 权限撤销或租户切换会清空页面上下文，已经发出的旧上下文请求不能恢复列表、旧详情、草稿或提交成功提示。

## 迁移和运维

`online_forms.0002_release_history` 为已有表单补首版序号，将所有存量记录按所属表单当时定义回填快照，包含已归档表单；保留既有表单/记录修订号和数据。添加 `(code, release_number)` 及单草稿/单发布条件唯一约束。

部署前备份数据库并先在副本验证迁移。存在同编码多版后，旧版本代码的单编码唯一约束不再兼容，不应直接反向迁移；回退应恢复匹配版本的备份。此前历史数据若在数据库外已被手工改坏，迁移不能重建其原始定义。

## 验证与浏览器接入

本轮定向测试：PostgreSQL 18.6 共 99 项通过（包含真实行锁并发、新版发布和旧页提交竞争、存量迁移）；前端相关 3 文件 26 项通过。测试 TypeScript 检查目前被其他增量中的 `tests/file-documents.test.ts` 未使用导入阻断，需由主任务合并后复核。后端测试只出现静态目录未生成警告。

独立浏览器函数位于 `scripts/online_form_lifecycle_browser.mjs`，导出 `validateOnlineFormLifecycle({page,context,headers,name,evidence,expect,checks})`，主验收在桌面/手机上下文分别调用。脚本仅允许 `http://127.0.0.1:18471` 独占夹具，自行通过 API 建表单，由真实 UI 保存草稿、发布、提交旧页、管理历史记录、创建下一版，保留最终草稿和记录供复核。

夹具要求：启用 `online_forms`，完整前端构建包含在线表单路由；已改初始密码的管理员，拥有 `online_form:read/create/update/publish/record_read/record_create/record_update`（或 `*`）；`page` 与 `headers` 同用户/同租户；每个运行的 `name` 唯一。无需邮件、附件或外部凭据。权限/租户迟到响应用例临时修改当前夹具的客户端 Pinia 状态并延迟真实详情响应，最后恢复状态；它验证客户端隔离，不能替代服务端租户/越权测试。
