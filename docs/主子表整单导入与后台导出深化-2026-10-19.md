# 主子表整单导入与后台导出

本批承接[单表业务导入导出深化](业务导入导出深化第二批-2026-10-18.md)。显式登记的 V2 普通单表和主子表模块具备整单导入、CSV/XLSX 后台分批导出；树结构导入不在本批范围。小项目仍可关闭 `data_io`，后台任务使用现有 worker 和可靠事件派发，不增加专用常驻服务。

## 单工作表的整单语义

主字段使用字段名，明细字段使用 `组名.字段名`，例如 `code`、`lines.product`、`lines.quantity`。同一业务键的多行构成一单，各行已映射的主字段必须完全相同；不采用“后行覆盖前行”。每一明细组按源文件顺序收集非空行，整组替换；空组明确代表清空，但仍受生成模块的最少行数和必填约束。多个明细组以同一工作表的行序号对齐，不做笛卡尔积。

整单导入要求主字段可读可写，并要求所有明细组及子字段可读可写，避免整组替换擦除不可见字段。关联和附件填写当前可访问对象 ID，不猜名称、不自动创建关联对象。预检会检查主值一致性、业务键、明细数量、必填值、引用与字段权限；真正写入时重新执行生成模块的序列化、权限、版本、引用、安全校验和业务扩展。

任务的一个回执对应一整单。主记录、全部明细和回执在同一事务中提交；一单失败不会留下半张单，也不回滚其他已提交单。预检后关联对象被删除、记录被修改或授权被收回时，实际执行必须失败。取消、失联和人工接续继续使用现有导入账本，只接续没有回执的整单，不重放未知外部副作用。

导入仍限制为 10 MiB、5000 源数据行、128 列。错误文件带原始行号和受控错误码，只输出当前可读、已映射的业务字段。全量导出的列遵循读取权限，可能不满足整单重新导入需要的全部写权限；导出文件应先核对映射及业务约束再用于重导入。

## 后台导出与一致性

生成列表提供“后台导出 CSV/XLSX”，创建返回 202 与任务 ID；通过“刷新导出结果”查看进度，在成功后下载。接口为 `POST /api/v1/data-io/business/exports/`、`GET .../{id}/` 和 `GET .../{id}/download/`。旧单表同步导出保留原有限额；主子表必须使用后台入口。

提交时冻结资源定义摘要、实际列表筛选、读取列以及主记录 ID/版本，不保存业务正文。执行按 250 单分批读取；提交后新增的数据不加入本次导出，版本变化、删除或数据范围收回会让任务失败。对于未经标准服务直接修改明细、没有递增主版本的情况，下载还会比较已选单元格摘要，拒绝过时文件。支持的生成模块服务以主记录行锁保护整单读写。

主字段在每个展开行重复；各明细组按 `position/id` 顺序排列，再按各组内序号横向对齐，较短组留空。展开行数为各组最大行数，至少一行，不产生跨组组合。表头只包含当前可读列，关联和附件输出 ID，日期采用 ISO 格式，金额保留文本精度；CSV 为 UTF-8 BOM。CSV/XLSX 的公式前缀均加保护引号，不执行公式。

后台上限为 10000 单、50000 展开行、50 MiB（内容预算和最终产物均检查），单元格最多 32767 字符。超限整项失败，不发布截断文件。每个发起人在当前租户最多三个未完成导出，产物有效期 24 小时。下载需在一次事务内持有当前身份、会话、租户、任务和所有目标主记录锁完成复核，故大范围下载具有额外数据库成本；本批是有界后台导出，不承诺任意规模的数据仓库导出。

## 当前授权与私有产物

创建、每个执行批次、最终发布、查询状态和下载均复核当前模块、账号状态、强制改密、会话版本和原始设备会话、资源读取及导出权限、字段权限、数据范围和租户有效成员身份。权限减少导致冻结列不再可读时拒绝整个文件，不静默泄漏旧列。只读业务角色可以导出，无须创建或导入权限。

快照和任务严格限定在提交租户；平台管理员未选择租户时只处理全局记录。其他发起者或其他租户查询此导出返回 404。产物使用私有存储字段，序列化不输出文件 URL 或存储路径，下载经过业务接口重新授权并设置 `private, no-store` 和 `nosniff`；不通过公开媒体地址提供访问。下载还检查文件摘要，损坏或篡改的文件不会返回。

任务派发复用可靠事件、有限派发次数和导入超时策略。重复投递只允许一个执行者领取；运行中取消采用协作停止，后续批次和最终发布都会检查任务状态，不发布部分文件。失联或排队过期后标记失败，用户重新提交；不会自动重放。现有事件派发维护会清理到期产物，删除任务历史也会清理其私有文件；存储故障可能延迟物理清理，到期下载仍立即拒绝。

## 验收

针对性前端覆盖等待、完成、失败、取消、过期、上下文切换和主子表入口；隔离浏览器使用真实 API 创建任务、真实任务函数执行、文件下载和版本变化失败，不伪造任务状态。后台验收覆盖 CSV/XLSX 对齐、只读角色、当前字段/数据范围/设备会话/租户成员回收、快照变化、预算、文件摘要、取消、重复投递、派发耗尽和失联恢复。并发验收必须在真实 PostgreSQL 中运行，SQLite 的跳过项不能替代行锁验证。

2026-10-19 证据：`.codex-validation/codegen-v2-58e0b5837e/integration.xml` 中 PostgreSQL 全量集成 **440 项通过、零跳过**。导出的真实 PostgreSQL 并发用例通过独立连接和线程执行真实任务函数，覆盖重复领取只发布一次，以及运行中取消、撤权、失联恢复后不发布产物；这不等同于独立 Celery broker/worker 进程的端到端验收。SQLite 针对性验收为 87 项通过、5 项跳过，前端组件为 17 项通过。

本轮 runner 最后的 OpenAPI 校验发现开放业务网关列表/详情 operationId 冲突，已显式区分两个 operationId 后另行检查。失败运行现场 `.codex-validation/codegen-v2-58e0b5837e/` 保留，容器 `admincore-cgv2-58e0b5837e` 已停止并保留；不得将此轮整体 runner 描述为通过。浏览器与最终 schema 结果以各自最终报告为准。
