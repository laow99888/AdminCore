# 全局业务搜索深化第七批

本批接续第六批，补齐路线图第5项的显式业务记录搜索。顶部菜单搜索继续负责找页面，新增“业务搜索”负责在当前授权的 V2 生成业务中找记录。文件中心、通知策略和表单生命周期等后续深化尚未完成。

## 实现与边界

- 新增 `GET /api/v1/business-search/?q=<关键词>`，可用 `source=<模块编码>` 限定一个来源。关键词去除首尾空白后为2至80字符；未知参数、重复参数和空来源均拒绝。不接受客户端指定模型、字段、关系路径或跳转地址。
- 来源必须在生成模块的 `manifest.py` 中显式声明 `BUSINESS_SEARCH`，并满足既有生成器契约、模块启用、读取权限和已登记菜单路径。缺失或错误声明关闭该来源；未授权来源与不存在来源使用相同404响应。
- 每来源登记1至3个主表文本字段，只支持 schema 已允许的 `eq` 或 `contains`；精确匹配字段不会自动扩大为模糊搜索。关系标签、正文、附件、主子表明细和任意SQL不自动参与搜索。
- 匹配字段和返回摘要同时按当前业务字段读取策略裁剪，隐藏字段既不能命中，也不进入摘要。标题字段不可读时使用模块标题，不回退到隐藏原值。
- 行范围复用 `service.visible(actor)`，多租户启用后再限定当前租户。平台管理员未选租户时返回空结果，不跨租户聚合。搜索后进入详情仍重新请求并校验权限。
- 一次最多8个来源，每个来源返回最近5条，用第6条判断是否还有结果，不执行总数查询。按创建时间与主键稳定排序；每项标题和字段值最多160字符，结果不包含整行。超过来源上限显示提示，可用API的 `source` 明确查询其他已授权来源。
- PostgreSQL 查询预算继续生效；成功结果使用 `Cache-Control: no-store`。当前是受限数据库查询，没有独立全文索引、拼音、相关性排名或大数据量性能承诺。现有普通索引不能直接证明 `contains` 查询在大表下足够快。

## 界面与兼容

业务搜索使用现有 Element Plus、Lucide 图标、主题变量和中英文消息。300毫秒防抖，支持明确提交、加载、空结果、失败重试、更多结果提示、键盘焦点和手机布局。展示使用文本插值，不执行摘要HTML。

输入变化、关闭、组件卸载、会话/租户/权限/模块状态变化会取消旧请求并清空旧摘要；即使旧响应迟到，也不能覆盖新上下文。客户端还会过滤当前不可访问的跳转路径，服务端仍负责最终授权。

点击结果进入已登记业务列表，通过一次性的 `record` 参数打开只读详情并移除该参数。同页已有未保存草稿时仍要求确认，取消保留草稿。本批浏览器验收发现原生成详情仅禁用保存，部分字段显式传入 `disabled=false`，覆盖了父表单的禁用状态；已为主字段、树父节点、明细字段和明细增删按钮显式传递只读/保存状态，并补充回归断言。

新生成模块会为最先出现的最多3个可搜索文本字段产生可审查声明；部署前应按业务审查并缩减敏感字段。已有生成模块不会自动加入全局搜索：需审核后在 manifest 显式添加声明，或审查重生成差异。示例：

```python
BUSINESS_SEARCH = {'fields': ['code', 'name'], 'title_field': 'name'}
```

移除该声明即可停止参与搜索。本批无新增数据库迁移；公共API和前端需同步升级，不能仅复制生成业务页面。SDK已包含新接口。

## 尚未覆盖

全局搜索只覆盖显式登记的 V2 业务主表。内置模块、附件正文、跨表搜索、独立全文检索、任意嵌套条件和大批量后台操作没有因此自动实现。第5项已有较完整常用工作台能力，仍不能将整份深化路线图标为全部完成。
