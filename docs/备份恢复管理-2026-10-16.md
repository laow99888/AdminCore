# 备份与恢复管理

P2-09 在既有宿主备份协议上增加 `/tasks/backups` 管理页。功能默认关闭，页面提供已校验的备份集、执行器状态、恢复预检、明确确认和恢复记录；“备份计划与手动备份”进入现有定时维护页。应用容器不挂载 Docker socket，不接受网页传入路径、命令或存储凭据。

## 使用与授权

部署更新后运行正常迁移及 `bootstrap_admincore`，登记 `backup:read`、`backup:restore` 和菜单。读取需要备份查看权限，恢复额外要求管理员身份和恢复权限。运行方式、独立副本和保留策略沿用[自动备份说明](自动备份与恢复目标-2026-10-14.md)。使用新版本宿主执行器 `python scripts/backup_runner.py --backup-dir <私有目录>`；旧执行器不会上报目录，页面显示离线并拒绝恢复。

1. 启用部署配置 `ADMINCORE_BACKUP_ENABLED=True`，准备可信执行器和独立备份目录。
2. 在定时维护中登记备份，等待执行器停写、导出、验证并发布完整集。页面不会提供 dump 下载。
3. 在业务维护窗口选择备份并运行预检。执行器须空闲且三分钟内有心跳，目录必须包含完整的数据库、媒体和校验清单。
4. 输入当前密码及中文确认文本 `恢复备份` 后登记。密码不持久保存；前端提交、关闭弹窗、身份变化和退出页面均清空输入。
5. 宿主领取、重新核对权限/会话/摘要后执行原恢复脚本：独立数据库校验、媒体 staging、停写切换、健康检查和失败回滚。恢复结束后核对宿主回执及实际业务。

## 并发与故障边界

预检绑定操作者、备份摘要和十五分钟期限，只能使用一次。数据库约束使等待或执行中的恢复全局最多一个；入口锁定执行器行，宿主继续使用统一文件锁。领取时重新检查账号、设备会话、权限、密码变更状态、排队期限和目录摘要；撤权后的请求不会执行。

执行器在调用恢复脚本**之前**原子持久化宿主意图回执。该回执或其未完成文件存在时禁止重放同一请求。恢复数据库可能使请求记录消失或回退为旧状态；宿主回执由心跳重新投影到页面，并将重新出现的旧请求收敛到终态。超过两小时的失联执行记为结果待核对，不自动重试。恢复失败的 `--once` 返回非零。宿主断电、数据库切换或外部依赖故障仍可能需要人工处理；回执显示未知时必须核对现场。

心跳目录最多一百组，页面显示最近二十条恢复记录。目录只展示摘要和固定文件名，拒绝路径注入、非法校验和、异常大小及不完整索引。首次及文件元数据变化时核对完整摘要，普通心跳缓存未变化的已验证目录，避免每三十秒重复读取全部备份；真正恢复前对所选集重新完整校验。回执、恢复前旧库及旧媒体保留供业务验收，不由页面删除。
