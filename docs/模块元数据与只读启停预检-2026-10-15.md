# 模块元数据与只读启停预检

所有显式登记的可选模块现在声明唯一标识、契约版本、默认启用状态、依赖与冲突。当前契约仅支持版本1；缺省冲突为空，不代表任意第三方插件兼容。声明仍由代码显式导入，不扫描目录或执行环境变量指定的代码。

启动校验拒绝未知/重复/自冲突声明、循环依赖、不受支持的版本和依赖闭包内的互斥。互斥允许单侧声明，两者同时启用即拒绝；合法的独立互斥模块可以分别启用。依赖闭包有缓存，最多128个登记模块，避免密集依赖图重复遍历。

## 变更前预检

在项目后端环境运行，或使用 `docker compose exec -T backend` 前缀：

```powershell
python manage.py check_modules
python manage.py check_modules --preset minimal
python manage.py check_modules --modules files,tasks,notifications,data_io,approvals,system,organization
```

无参数时检查当前进程的实际模块集合。有 `--preset` 且无 `--modules` 时检查预设默认集合；同时提供时以完整显式集合为准。Django `call_command('check_modules', modules='')` 可表达关闭全部可选模块。JSON返回目标集合、相对当前进程新增/关闭的模块、依赖、是否需要重启及保留表和数据的语义。命令不写环境文件、不改变当前设置、不操作数据库、不自动补依赖、不自动关闭被依赖的模块。缺少依赖或启用冲突以非零退出码失败。

修改部署配置并重新创建相关服务后才生效；Compose profiles 不会主动停止已经运行的旧服务。关闭模块继续保留 Django 应用、迁移、历史表和文件。升级仍需审核正向迁移与备份，不得用删除数据卷来切换预设。

模块查询接口在既有v1响应中补充可选 `contract_version`、`default_enabled`、`conflicts`，旧客户端可忽略。既有角色、权限种子、菜单初始化标记及默认模块集合不变。本批不等于旧模块权限/菜单/参数全部迁入独立 manifest，也不等于物理依赖包裁剪完成。
