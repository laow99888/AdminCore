# 报表时间比较与主子表聚合

本批在现有多指标、看板筛选/联动和下钻基础上，增加时间同比/环比及生成业务主子表聚合。没有新增数据库表或修改历史报表定义；旧 `metric` 与现有 `metrics` 仍可运行。

## 使用与统计口径

报表编辑器的“时间比较”可以选择环比或同比，并指定已登记的根记录日期字段和起止日期。日期区间采用应用当前时区，开始日期包含当天，结束日期不包含当天；区间跨度限制为 1～366 天。

- 环比：取本期开始日期之前、天数相同的区间。
- 同比：起止日期分别向前一年；闰日收敛到 2 月 28 日，收敛后至少保留一天。例如 2024-02-29～2024-03-01 对应 2023-02-28～2023-03-01。
- 当前版本按非日期分类维度对齐两期，支持总计或至多两类维度。日期趋势继续使用既有日期分桶，不与时间比较叠加；饼图不支持比较。
- 表格输出本期、基期、差额及变化率，图表仅绘制本期和基期，避免把百分比与原始单位放在同一轴。变化率为 `(本期 - 基期) / abs(基期) * 100`，保留四位小数，基期为零时留空。
- 某期不存在该分类时，计数为零，SUM/AVG 保持 SQL 空值；不把未知金额误报为零。分类取两期并集，按统一维度顺序应用结果上限，超限明确标记。
- 比较日期字段不能再接受固定筛选或看板统一筛选，以免只截断一侧期间。其他分类筛选会同时应用于两期。
- 比较结果的“查看明细”只查询本期，界面有明确说明。

定义示例：

```json
{
  "data_source": "cg_orders",
  "chart_type": "bar",
  "dimensions": [{"field": "category"}],
  "metrics": [
    {"key": "m_orders", "label": "订单数", "field": "id", "aggregation": "count"},
    {"key": "m_total", "label": "主表金额", "field": "amount", "aggregation": "sum"},
    {"key": "m_quantity", "label": "明细数量", "field": "lines.quantity", "aggregation": "sum"}
  ],
  "filters": [],
  "limit": 100,
  "comparison": {"field": "created_at", "mode": "previous_period", "start": "2026-03-01", "end": "2026-04-01"}
}
```

## 主子表与权限边界

只有源码显式登记、已启用且配置报表能力的生成模块可以提供明细指标。明细来自生成定义的整数/十进制字段，以 `明细节名.字段名` 展示，例如 `lines.quantity`；界面可直接选择 SUM/AVG。它不是客户端可自由指定的 ORM 路径，不开放任意表关联、SQL、附件内容或表达式。

主表先按原业务服务的可见范围得到当前用户可读记录，每个明细节单独通过这些主记录 ID 聚合。主表订单数和金额不会因明细条数膨胀，明细 AVG 对实际明细行计算，不对各订单均值求均值。没有明细的主表分类仍保留，明细汇总为 NULL。

明细指标同时要求业务读取权限、明细节权限和明细标量字段权限；每次运行、下钻与目录查询重新检查。主记录租户及行范围沿用业务服务，明细租户还必须与所属主记录一致，即使全局管理员查看跨租户总计，也排除租户归属异常的历史明细。下钻每行仍是一条主记录，明细指标为该单据的相关子查询汇总。

## 预算与限制

沿用每个组件最多两维度、四指标、一百个结果组及看板最多八组件的限制。每期一个根聚合，加至多四个明细节聚合；两期最多十条聚合 SQL，查询复用现有 PostgreSQL 语句超时和锁等待预算。下钻最多一百页、每页一百行。结果超限会显示不完整提示。

它适合受控的业务统计，不提供跨根业务表的自由联查、明细作为分类维度、多层关系链、原始明细逐行报表或跨请求快照。并发业务变更可能发生在多条聚合语句之间，报表不是财务结账快照。

## 验证

新增 `test_report_comparison.py` 与 `test_report_detail_aggregation.py`，结合原报表与看板测试验证真实 SQL。主子表测试必须在真实生成采购模块已登记的独立测试配置中执行，普通基座环境显式跳过，不伪造业务模型。

本批定向 SQLite、独立 PostgreSQL 18.6 各 78 项通过；前端构建器、看板与新增比较测试合计 23 项通过，测试类型检查、ESLint 与后端 Flake8 通过。PostgreSQL 结果见 `.codex-validation/reports-deepening/postgres-tests.log`。独立浏览器脚本 `scripts/report_deepening_browser.mjs` 已通过 Node 语法检查，由根任务统一集成实际执行；本文件不将静态检查视为已完成浏览器验收。

浏览器脚本复用生成采购模块的真实接口与页面，分别为桌面/手机创建两张多明细订单；经编辑器切换并保存环比与同比、刷新复核、发布运行，验证主表金额未被三条明细重复累计、明细数量/加权均价、零基期空变化率、当前期间主记录下钻，以及非法日期维度比较和非白名单关联被拒绝。该脚本会增加订单，应放在旧浏览器汇总基线断言之后执行。历史非零基期、边界时区与租户权限由上述真实 SQL 用例覆盖。

针对采购订单三张主记录与三条明细，真实 SQL 测试断言订单数 3、主表金额 350、明细数量 9、明细均价 40，并断言根聚合 SQL 不包含明细表。还覆盖日期半开边界、本地时区、闰日、零基期、缺失分类、两期统一上限、当前期间下钻、字段撤销、行范围和租户异常明细。
