# 通用通知与模板

| 交付项 | 本批设计 |
|---|---|
| 功能范围 | 显式站内/SMTP 渠道、模板及不可变版本、严格变量渲染、管理员预览/发送、可靠派发、逐收件人/渠道失败记录及有限重试；Webhook/短信在本批后继续实现，不能以空适配器记完成 |
| 默认是否启用 | notifications 开启时保留站内能力；通用邮件独立 NOTIFICATION_EMAIL_ENABLED=False，复用已有部署 SMTP 配置；邮件关闭不可新登记邮件发送 |
| 外部依赖 | 数据库、核心 Outbox 与原 worker/beat；实际 SMTP 通过独立本地服务器验收，正式供应商需部署配置；精简预设没有 notifications/worker，不需要邮件服务 |
| 权限与数据范围 | 新 template:read/update/send 权限仅登记，不扩大旧角色；管理员及对应权限，收件人沿用 user 范围并复核有效账号；邮件仅发已验证当前地址，不允许提交任意地址或 SMTP 凭据 |
| 关闭后的行为 | 模块/渠道关闭时拒绝新发送；待发记录明确标记 terminated 及原因，不自动转备用渠道；模板禁用阻止待发，历史版本及任务保留。Outbox succeeded 仅表示已处理该事件，实际发送结果以投递记录为准 |
| 可重复验收 | 单元及真实 PostgreSQL 并发/回滚、真实 SMTP 字节/故障/有限重试/旧版本保持、桌面手机与权限/语言/错误/加载检查、正式加法升级及远端 CI；完成后填写实际数量与证据 |

模板用 `${name}` 简单文本变量，不支持 Django/Jinja 表达式、属性访问、函数调用或 HTML 邮件。变量名白名单声明，渲染必须恰好提供全部变量；版本编辑创建新行，已登记投递固定引用旧版本及渲染快照。最多 20 个变量、100 位收件人、每变量 2,000 字符、正文 20,000 字符；显式规模限制，事务内逐人/渠道记录，Outbox payload 只含投递 UUID。

SMTP 属至少一次副作用，进程在供应商接收后但数据库提交前崩溃可能重复。固定 Message-ID 帮助诊断，不承诺供应商去重；站内通知以投递 UUID 去重。正文、变量和真实邮箱不进入审计/诊断列表。每次投递 24 小时有效期、最多五次尝试；失效身份/地址/模板终止，网络故障保留安全原因并退避。授权手动重试不重置次数，已成功/过期/次数用尽不可重放，必须新建明确发送请求。

## 已实现的契约

notifications 内显式渠道表 `CHANNELS` 当前只登记 inapp/email 两个真实实现，邮件支持与认证邮件独立启停。认证邮件关闭不阻止通用邮件；任意邮件开启都必须具有有效发件地址、SMTP 主机/端口、单选 TLS/SSL 及 1–30 秒配置超时，通用投递单次 socket 超时最多 20 秒。未实现的 Webhook/短信没有伪装为可用选项，后续单独验收。

模板与发送入口 `/api/v1/notifications/templates/`，投递只读和重试入口 `/api/v1/notifications/deliveries/`；所有响应 private/no-store。新页面 `/notifications/templates` 提供模板编辑、分页版本记录、变量输入/服务端纯文本预览、已有人员选择器逐人加入（最多100人）和显式渠道选择、发送确认、记录查询及失败重试。正文始终文本插值，用户文本不参与系统文案翻译。模板变量改变立即使旧预览失效；模板保存冲突保留输入，不以旧 revision 覆盖别人；退出/撤权/模块关闭/页面停用清除内存内容。未保存保护、提交锁和语言切换复用原机制，不持久化草稿或通知正文。

模板编辑 append 新版；接口不提供删除模板和修改旧版。投递记录绑定原版、渲染文本快照、发起者、设备会话 UUID/版本、过期时间和请求 ID。数据库约束状态/渠道及最多五次投递，父模板和版本删除保护；收件人/发起人被删则历史关联 SET_NULL。最终发送重查账号有效、管理员权限、强制改密、原设备会话撤销/期限/空闲期、收件人有效及数据范围、模板/模块/渠道开关、已验证当前邮箱与登记时绑定。24小时是最长有效期，原会话空闲/撤销可更早终止发送。

SMTP 失败保存固定 `channel_delivery_failed`，不把异常正文、主机、凭据或真实地址放进 Outbox/投递错误。每次失败次数与可靠事件事务提交；指数退避最多五次，人工重试不恢复次数，通用可靠事件重试页禁止绕过专门入口。已终止投递没有自动恢复：重新启用渠道或重新验证邮箱后，应由管理员重新预览并明确新发送。重试也在事务内重新验证当前请求的身份和设备会话。

事件先锁，用户按 UUID 固定排序，再锁已有投递；模板写入口/登记固定用户与会话在模板之前，不通过关联查询提前锁模板，降低互发和用户删除的反向锁风险。PostgreSQL 验证并发编辑只有一次成功、并发派发不重复接收、管理员互发无死锁；SMTP崩溃提交窗口仍属至少一次，不能声称恰好一次。

沿用现有系统管理员语义：is_staff/is_superuser 的功能权限和数据范围为全部，不新增管理员细粒度角色语义。三个 template 权限和菜单只登记，升级不向既有角色扩权；只有普通角色权限码不能跨过管理员入口。既有通知/公告、认证邮件和审批通知行为保留。

## 保留、升级和边界

模板/历史版本、投递记录及渲染正文默认持久保留，便于结果定位，模块关闭不删除。没有新增永久临时目录；Outbox 只包含投递 UUID。消息正文可能属于业务敏感数据，管理员列表仅展示状态/标识，模板/预览仅管理员访问；备份包含这些数据库表，按既有备份策略管理。本批不把投递正文套用日志清理期限，也未提供网页批量删除。具体项目需要更短正文保留期，应另行注册有界清理与权限/审计验收。

迁移 notifications/0005 只新增三表和约束；标准/精简都保留模型迁移，关闭接口不退出 INSTALLED_APPS。关闭后再次启用恢复原版本/投递；邮件开关默认False，正式环境没有配置外部供应商。升级前停写并保存完整数据库/媒体快照，旧用户、角色授权、公告、文件、日志和维护配置须一致。代码回退可以先关闭通用邮件和发送入口并保留新表；已经发出的 SMTP 邮件无法由数据库回退撤销，旧代码不能安全重放新增事件。不得清空整库或逆向删除带业务数据的新表。
