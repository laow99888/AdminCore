# 字段级权限

角色可以通过 `field_permissions` 声明资源的可读字段和可写字段。策略挂在角色上：对同一资源，合并所有显式声明策略的有效角色，按动作取字段并集；只有所有有效角色都未声明该资源时才沿用完整登记字段。一个未声明策略的旧角色不会覆盖另一个角色已经声明的限制。显式空数组表示该动作无字段权限；省略 read/write 按空数组规范化。算法真源见 [field_permissions.py](../backend/apps/permissions/field_permissions.py)。

## 配置格式

```json
{
  "user": {
    "read": ["id", "username", "first_name"],
    "write": ["first_name"]
  },
  "post": {
    "read": ["id", "code", "name"],
    "write": ["name"]
  }
}
```

资源和字段使用后端登记的白名单。未知资源、未知字段、重复字段以及除 `read`、`write` 外的策略键都会被拒绝。管理员和超级管理员保留完整字段访问。

## 生效边界

- 用户和岗位详情、列表响应会过滤不可读字段。
- 用户和岗位创建、修改会拒绝不可写字段；版本号、角色分配等控制字段仍按原有授权规则处理。
- 数据导入模板只生成当前角色可写字段；导入任务会再次校验列和必填字段，不能通过直接调用任务绕过。
- 数据导出只包含当前角色可读字段；没有可导字段时返回拒绝。

字段策略只负责字段边界，资源权限、数据范围、租户隔离和审计仍由原有机制独立执行。

上述用户/岗位为最初接入范围。当前还登记角色及导出资源，V2 生成业务通过 manifest 的 `field_policies` 显式接入；其列表、详情、导出、搜索、报表和审批快照须调用相应执行入口。资源与字段全集从 `/api/v1/modules/` 的 `field_policy_resources` 及源码注册表读取，不能据“模型字段存在”推断自动受保护。业务接入和解释入口见 [业务字段深化](功能深化第一批-2026-10-18.md)、[权限诊断](字段权限诊断深化-2026-10-18.md)。
