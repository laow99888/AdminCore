# 定时维护管理与可靠执行

## 本批范围

`/tasks/schedules` 管理软删除文件清理、过期已读通知清理两项注册维护任务：启停、五段 Cron、IANA 时区、白名单参数、最近执行、本人有效预览和手动执行。沿用已有 Beat 计划；初始化不覆盖原时间、参数和启停，不在升级时触发手动清理。

核心可靠事件派发、幂等记录清理保留原计划，本页面不开放其启停。不支持新增任意任务名、函数路径、脚本或命令；导入仍由导入模块发起。新增任务须在代码内声明、校验、实现，再扩展注册表。

## 编辑与权限

API 和页面同时要求管理员身份，分别检查 `schedule:read/update/run`。现有 staff/superuser 通配规则不变。升级只登记权限，不自动补入已有角色；新库系统管理员默认角色按完整声明初始化。新菜单只补录一次，此后保留管理员修改/删除。

更新携带配置指纹 `revision`，数据库行锁及唯一名称保护并发；配置变化返回 409，表单保留输入并提供明确重新载入。指纹包含原始 Beat 配置，排除执行计数/最近调度时间；它是配置比较，并非单调递增的业务版本号。修改周期/时区重置 `last_run_at`，保留执行总数。

Cron 按 Celery 解析/调度语义，字段只允许数字、`*`、范围、列表、步长，时区必须为有效 IANA 名称。文件参数只接受布尔 `dry_run`、整数 `batch_size`（1–100），通知只接受布尔 `dry_run`。未知字段、非对象请求及字符串布尔值均拒绝。已有不支持的任务/位置参数/关键字参数不会回显或被页面覆盖，需维护人员修复。

计划修改记录操作者及前后值，审计排除 Beat headers、队列凭据及未知参数。默认计划仍实际清理，可切为仅预览；关闭计划不撤销已开始/已手动提交的任务。tasks 关闭后 API/菜单/路由停用，files/notifications 依赖关闭后对应任务不可编辑/执行，重新启用保留原数据及配置。

## 手动执行与可靠登记

`POST /api/v1/tasks/schedules/{files|notifications}/run/` 必须提供 `Idempotency-Key`、`revision`、`options`。预览传 `dry_run: true`；实际清理另需本人 15 分钟内成功的 `preview_id` 及确认文字 `执行清理`。预览的保留期必须与当前配置相同，变化或过期需重新预览。预览不是删除集合的冻结快照，实际执行按运行时截止时间选择过期数据，页面明确提示该边界。

TaskRecord、MaintenanceRequest、审计、outbox 及幂等结果在同一事务登记。202 表示已登记；成功请求同键重放不新建任务，同键换内容返回 409。前端忙碌时禁用操作，网络失败重试复用原请求键，输入变化使用新键。

既有可靠事件派发器负责入队；broker 失败保留事件和待执行任务，指数退避及每分钟定时补偿，可在可靠事件页诊断/重试。手动提交要求核心补偿计划启用。事件完成代表入队成功，实际完成看任务记录；tasks 关闭时事件保留为失败待补偿。

worker 锁定待执行记录并再次检查用户存在/启用、管理员身份、功能权限、强制改密、会话版本及模块依赖；等待超过 24 小时拒绝。实际执行复核预览/保留期，固定本次保留期快照。文件在用保护、保留期、分批清理及存储失败记录沿用现有机制。

## 重叠、中断与取消

定时和手动清理共用每项任务的 PostgreSQL 会话 advisory lock。跨连接/worker 重叠的后来任务成功记录 `skipped: true, reason: overlap`，页面明确显示跳过；同一请求重复投递仅一位 worker 领取。两种清理各自排他，慢存储操作不被包在整个任务的数据库长事务中。

部署要求直接 PostgreSQL 或会话池，不支持用事务模式连接池维持会话锁。SQLite pytest 使用进程内可重入锁，仅作功能回归；跨 worker 保证由真实 PostgreSQL 验收，锁随会话终止释放。[PostgreSQL 官方说明](https://www.postgresql.org/docs/18/explicit-locking.html#ADVISORY-LOCKS)

生产 Linux prefork worker 设置 270 秒软超时、300 秒硬超时。手动任务延迟确认并在 worker 丢失时重新投递；领取状态防止已经开始的删除被直接重放。异常尽力记失败，核心补偿将超过 10 分钟且已无锁持有者的运行记录标记 `worker_lost_result_unknown`，不自动重放。文件已完成的删除不可回滚；硬终止可能留下无法确认的结果，必须核对记录/存储，新清理仍需新预览。[Celery 官方说明](https://docs.celeryq.dev/en/stable/userguide/tasks.html)

仅待执行维护任务可取消并审计；领取后返回 409，不杀死 worker。任务中心对运行中的维护任务显示结果入口；原导入任务协作取消语义不变。

## 验收与边界

复用现有 Vue/Element Plus、设计令牌、Lucide Clock（ISC，沿用包内许可证），支持加载/错误恢复、编辑冲突/未保存提示、提交禁用、中英/明暗、桌面/375px 弹窗及状态文字。语言切换保留编辑输入。

后端 364 项、Vitest 36 项、Playwright 桌面/手机 128 项通过，其中新增维护专项 16 项；Vitest 96.87% 语句覆盖率仅代表 BaseTable/BaseForm/BaseDialog。lint、应用/测试类型检查、构建、分包预算、Django check、迁移一致性、OpenAPI 零告警校验通过。

隔离 PostgreSQL 18.6/Nginx/Redis/Linux Celery 验证并发计划编辑、同键登记、跨连接排他与四次重复领取、真实预览、确认后只删除隔离过期通知、模块关闭/恢复保留配置；五项真实 MinIO 上传/预览/回收站/清理/备份恢复链路通过。正式部署先停写备份/校验 SHA256，再更新四服务，复核原账户、角色权限和维护计划。正式管理员人工登录仍未执行（用户选择暂不登录）；浏览器回归使用 fixture，真实队列链路使用独立验收项目。

失败证据保留，成功测试只清理自有临时资源，正式六服务继续运行。业务任务统一重试/超时配置、副作用补偿、失败邮件告警、自动备份等仍待实现；本批固定超时/失联处理只覆盖两项维护清理，不代表总清单完成。
