# 配置、字典与品牌约束复核

本批复核清单中尚未勾选、但已有实现的五项共同约束；范围为当前显式登记的配置、业务字典及品牌，不增加新的配置入口或改变在用值。

| 交付项 | 当前范围与边界 |
|---|---|
| 功能范围 | 全局业务参数、字典项目、名称/Logo/登录说明/浏览器标题；非多租户配置中心 |
| 依赖 | system管理入口、现有SQL及本地/Redis缓存；不依赖邮件、对象存储或实时服务 |
| 默认/启停 | 沿用system预设；关闭管理模块后取代码/环境默认值，已有数据库覆盖保留，重新开启恢复 |
| 安全 | 只读 `config:read`、修改 `config:update`；字典分别 `dictionary:read/update`。品牌匿名读取仅三个允许字段 |
| 数据/变更 | 白名单校验、当前版本提交、冲突409、事务内审计；旧值可按新版本重新提交，不提供自动撤销按钮 |
| 验收 | 当前后端全套1,181项、配置专项12项及真实PostgreSQL/Redis基础回归326项；浏览器部分由已有全套回归覆盖 |

## 五项约定

1. **声明与安全**：`ConfigDefinition` 登记键、展示名、类型、默认、长度/数值范围及可选环境设置来源。当前配置均为单部署全局、可管理的非密钥业务值，读取/修改权限统一由管理API约束。密钥不属于登记表，未知键返回404；Logo审计只保存摘要，不能把任意环境项注册成可回显配置。
2. **分层与优先级**：已启用system时，数据库覆盖优先；没有覆盖使用声明指定的环境设置或代码默认。关闭system时回到默认，数据库行保留。主题、表格密度等个人偏好由现有浏览器偏好管理；密钥与部署开关仍由部署环境管理，不进入业务配置API。品牌在页面重新加载时取数，不承诺实时广播。
3. **版本、审计与回退**：写入要求当前版本，并锁定配置行；并发首次创建冲突转409。每次业务读取先查SQL版本，再使用含版本的缓存键，API/worker下次读取可看到已提交新值，无需等待300秒旧缓存TTL。已登记任务在创建时固定的策略快照不随配置变化改写；回退按当前版本重新提交先前合法值，同样留下审计。
4. **字典与状态机分离**：字典项类型、数量、允许键、唯一值及排序有校验；编码建立后不可修改，停用保留数据及版本。当前审批/任务状态为代码枚举，保留编码 `approval_status/task_status` 不允许建立成业务字典；修改其他业务字典不会改变状态机合法迁移。
5. **品牌与回退**：名称、登录说明与Logo通过品牌store供登录/侧栏使用，加载后设置浏览器标题；默认名称AdminCore。Logo限制200KiB、输入最长边1024像素、输出最长边256像素，按像素重新编码PNG，排除SVG、外部地址和元数据。首次品牌请求失败不阻断登录，保持默认；system关闭明确返回默认品牌。页面刷新前已加载的品牌不承诺立即变化。

## 代码与证据

- 后端：`apps/core/system_config.py`、`system_views.py`、`system_serializers.py`；前端：`src/stores/brand.ts`、登录/侧栏与已有参数页面。
- `backend/tests/test_system_configuration.py` 覆盖非法值、权限/未知安全键、版本冲突、缓存、字典状态机隔离及Logo消毒、重复读取和删除；本批专项结果保存在 `.codex-validation/configuration-contract-audit.log`。
- `.codex-validation/admincore-foundation-0f3226fa/report.json` 的326项真实服务检查包括PostgreSQL首次配置/字典并发冲突、Redis命名空间隔离与数据库重建、精简/标准启停及参数覆盖保留。
- 前端本批322项Vitest与类型/lint/build通过；全套浏览器结果以本批代码CI为准。模拟浏览器回归不替代真实数据库/缓存检查，也不代表所有品牌资源的无障碍认证。

新增配置、字典状态消费者或租户作用域需显式设计并扩充验收；不以本批复核宣称任意模块的配置自动安全。
