# 第一个生成业务模块：供应商

这是一条最小接入路径：从 [供应商 v2 定义](../../examples/codegen-v2/suppliers.json) 生成真实 Django 模型和 Vue 页面，再由开发者登记、启用并验证。它不是安装已完成的采购系统。先完成 [快速开始](../快速开始.md) 的依赖安装；使用锁定 Python。以下命令均在 **backend 目录的 PowerShell** 执行。

## 1. 离线预览

使用独立终端，避免继承业务库、租户及供应商环境。此阶段明确使用测试配置；供应商 JSON 不引用已有数据库表，预览不需要业务数据库。

```powershell
$env:PYTHON_DOTENV_DISABLED='1'
$env:DJANGO_ENV='testing'
$env:DJANGO_SETTINGS_MODULE='config.settings.testing'
$env:PYTHONUTF8='1'
New-Item -ItemType Directory -Force ../.codex-validation/supplier-review | Out-Null
./venv/Scripts/python.exe manage.py generate_module --definition ../examples/codegen-v2/suppliers.json --output ../.codex-validation/supplier-review/output --plan ../.codex-validation/supplier-review/plan.json
```

Linux 使用已激活虚拟环境的 `python` 和对应 shell 环境变量语法。命令输出文件计划及 diff；只保存计划，不写业务源码。计划路径须尚不存在；重新预览使用新的计划文件名，不覆盖此前审阅依据。

审阅 `plan.json` 的每一项和终端差异，确认命名空间、字段、权限与页面符合需求。首次生成到空输出目录时全部为 `new`。应用时 `--output` 必须与预览相同，定义及目标文件不能在预览后悄悄改变。

## 2. 应用已审阅的文件

以下是该示例首次生成的完整文件选择；仅在已逐项审阅、输出目录尚无业务修改时执行。每个 `--select` 是相对于输出根目录的路径。

```powershell
$selected = @(
  'backend/apps/cg_suppliers/__init__.py',
  'backend/apps/cg_suppliers/apps.py',
  'backend/apps/cg_suppliers/extensions.py',
  'backend/apps/cg_suppliers/manifest.py',
  'backend/apps/cg_suppliers/migrations/__init__.py',
  'backend/apps/cg_suppliers/models.py',
  'backend/apps/cg_suppliers/schema.py',
  'backend/apps/cg_suppliers/serializers.py',
  'backend/apps/cg_suppliers/services.py',
  'backend/apps/cg_suppliers/urls.py',
  'backend/apps/cg_suppliers/views.py',
  'backend/tests/test_generated_cg_suppliers.py',
  'docs/generated/cg_suppliers.md',
  'frontend/src/views/cg_suppliers/GeneratedPage.vue',
  'frontend/src/views/cg_suppliers/RecordListView.vue'
)
$selectArgs = foreach ($path in $selected) { '--select'; $path }
./venv/Scripts/python.exe manage.py generate_module --definition ../examples/codegen-v2/suppliers.json --output ../.codex-validation/supplier-review/output --apply-plan ../.codex-validation/supplier-review/plan.json @selectArgs
```

成功返回 `written` 文件列表及 `backup` 备份位置。阅读输出中的 `docs/generated/cg_suppliers.md`，将上述文件按相对路径合入业务项目，检查 Git diff。不要把整个临时目录连同计划、备份复制进源码。此时仍未注册模块、建立数据库表或开放接口。

已有模块重生成必须针对实际项目目录重新预览，不能复用空目录计划覆盖业务代码。已有 `extensions.py` 和 `RecordListView.vue` 标记为 `preserved`，禁止再次选择；其他人工修改也要逐项合并。

## 3. 显式登记

按生成接入说明完成以下三处，名称均来自本示例；其他业务使用其定义中的名称。

| 位置 | 修改 |
|---|---|
| [settings/base.py](../../backend/config/settings/base.py) 的 INSTALLED_APPS | 增加 `apps.cg_suppliers` |
| [core/modules.py](../../backend/apps/core/modules.py) | 导入 `from apps.cg_suppliers.manifest import MODULE as CG_SUPPLIERS_MODULE`，将其加入 MODULES；必须在 PRESETS/维护任务映射计算之前 |
| [前端 registry](../../frontend/src/modules/registry.ts) 的 frontendExtensions | 增加 `{ key: 'cg_suppliers', path: '/cg-suppliers', permission: 'cg_suppliers:read', title: '供应商', component: () => import('../views/cg_suppliers/RecordListView.vue') }` |

本例的模块 key/app 名为 `cg_suppliers`，URL 前缀为 `cg-suppliers`，二者不可混用。模块 API 由后端注册表挂载到 `/api/v1/cg-suppliers/`，记录集合为 `/api/v1/cg-suppliers/records/`；具体 action 读取生成的 urls/views，不再另加重复的 config URL。菜单由 manifest 声明、bootstrap 初始化，不在侧栏写死。模块为默认关闭，登记不等于启用。

## 4. 在隔离开发库初始化

打开新的开发终端，按快速开始配置专属开发库和管理员密码；**不要继续使用上面的 testing 配置执行迁移**，因为测试库是进程内 SQLite。不要把本步骤指向在用业务库。

先配置模块列表，再运行迁移和 bootstrap。例如标准模块加供应商：

```powershell
$env:DJANGO_ENV='development'
$env:DJANGO_SETTINGS_MODULE='config.settings.development'
$env:ADMINCORE_MODULES='files,tasks,notifications,data_io,approvals,system,organization,cg_suppliers'
./venv/Scripts/python.exe manage.py check_modules
./venv/Scripts/python.exe manage.py makemigrations cg_suppliers core
# 停在这里审查生成迁移：字段、唯一约束、索引、租户与外键保护；通过后再执行下面两条。
./venv/Scripts/python.exe manage.py migrate
./venv/Scripts/python.exe manage.py bootstrap_admincore
```

显式列表会**覆盖**预设，示例不能直接替换已有项目的业务模块清单。新增扩展菜单只在模块已启用时初始化；先 bootstrap 后启用时须再执行 bootstrap。已有角色不会自动获得权限，明确分配 `cg_suppliers:read/create/update/delete` 并核验对象范围。

Compose 部署将相同模块清单写入目标项目的私有 `.env`，重建并重新创建读取它的服务；仅修改宿主终端环境不足以改变既有容器。若生成项目原来是 minimal，新增异步能力还需启动 Redis/worker/beat；只切换模块开关或 `project.py up` 不会把 minimal 元数据指定的服务集合自动变成 standard。选择完整构建及服务的方式见 [模块指南](../模块与基础能力.md)。不要手改底座 SHA 来绕过升级。

## 5. 验收与业务扩展

在独立测试终端，按 [分层验证](验证与交付.md) 设置 testing 环境后运行 `python -m pytest tests/test_generated_cg_suppliers.py`，再完成严格 OpenAPI/SDK、前端 lint/类型/构建。生成测试只验证接入契约，不能替代真实业务测试。

在隔离开发部署使用管理员和普通角色分别验证：创建与编码重复、查询、详情、版本冲突、越权更新/删除、本人/组织范围、模块关闭；多租户项目再验跨租户拒绝。实际按钮、请求 URL 与菜单一致后才能视为接入完成。

复杂规则放后端 `extensions.py`，页面业务交互放 `RecordListView.vue`。扩展钩子签名从生成文件读取，金额等类型保持现有 Decimal 契约；跨系统副作用走 outbox。后续先接供应商，再接 [分类与主子表定义](../../examples/codegen-v2/)，审批/报表按 [完整业务流程](业务开发流程.md) 增量启用。

把业务规则、实现路径、权限码、迁移、模块清单、测试及未验范围填入 [业务上下文](业务上下文模板.md)。检查与提交完成后按任务归属清理成功的临时输出；失败的计划、diff 与日志保留，不删除用户已有代码或数据。
