# 分层验证与交付

使用锁文件对应解释器；Windows 本仓库通常为 backend/venv/Scripts/python.exe，PATH 中的 Python 不一定正确。Linux 激活虚拟环境后以 python 替换。不要使用部署配置运行测试。

## 文档与依赖

仓库根目录，无需服务：

```powershell
git status --short
backend/venv/Scripts/python.exe scripts/check_dependency_locks.py
backend/venv/Scripts/python.exe scripts/check_ai_docs.py
```

只改说明文字时检查文档与差异即可；修改导航、创建器、版本或 SDK 需对应回归。

## 后端

独立终端、干净测试配置，backend 目录：

```powershell
$env:PYTHON_DOTENV_DISABLED='1'
$env:DJANGO_ENV='testing'
$env:DJANGO_SETTINGS_MODULE='config.settings.testing'
./venv/Scripts/python.exe -m pytest tests/test_example_module.py
./venv/Scripts/python.exe manage.py check
./venv/Scripts/python.exe manage.py makemigrations --check --dry-run
```

用本次行为测试替换示例；公共契约变更扩大到调用方及全量 pytest。确认终端未继承部署 ADMINCORE_* 或供应商变量；CI 从干净环境执行，不复制在用 .env。测试使用 SQLite、进程内缓存和同步任务，不证明 PostgreSQL 并发。

接口变更在 frontend 执行 npm run sdk:generate，再 npm run sdk:check；导出器严格校验 OpenAPI，隔离部署变量且不连接业务库。生成快照不手改。

涉及锁、撤权、租户切换、队列、扫描或主子表联动，从 [CI](../../.github/workflows/checks.yml) 找对应 validate_*.py；先读脚本的端口、独立数据和清理规则，再运行真实 PostgreSQL/Redis 验收。

## 前端

frontend 目录，使用锁定 Node/npm：

```powershell
npm run lint
npm run test:typecheck
npm test -- tests/token-storage.test.ts
npm run build
npm run check:bundle
```

测试路径替换为本次行为用例。共享表格/表单/对话框跑 npm run test:coverage；页面流程先完成上述 build，再跑 `npm run test:e2e -- e2e/<实际用例文件>.spec.ts`（用真实路径替换占位符）。首次执行 npx playwright install chromium。Playwright 在 18411 启动自己的生产构建预览，不复用已有服务；API 由 fixture 模拟，不访问真实业务库，不能当作公网端到端验收。检查窄屏与加载/空/错误/禁用/冲突和键盘行为。

## 创建器、升级与文档契约

根目录：

```powershell
$env:PYTHONUTF8='1'
backend/venv/Scripts/python.exe -m pytest -q scripts/tests/test_ai_docs.py scripts/tests/test_create_project.py scripts/tests/test_project_upgrade.py scripts/tests/test_validate_project_upgrades.py
```

创建器只导出已提交 Git 快照。未提交文档的导出测试用临时 Git 上游提交夹具，不能把旧 HEAD 的导出当作新文件验证。连续迁移测试见 [升级指南](../底座版本与项目升级.md)。

## 功能验收记录

新增或深化能力时，记录六项事实：功能范围、默认启停状态、运行依赖、权限与数据范围、关闭后的行为、可重复的验收步骤及结果。明确对应提交，区分源码存在、隔离测试通过与实际部署通过。

按变更选择新库初始化/已有库升级、启停切换、正常/空/加载/错误/禁止/重复/并发场景，以及桌面/窄屏、主题、语言和键盘操作。真实 PostgreSQL、队列、存储及供应商只在适用时验收；没有执行的部分明确列出。容量与 RPO/RTO 以具体项目实测签收，备份校验不等于恢复演练。

## 发布与收尾

按 [发布策略](../发布与版本策略.md) 核对准确提交的完整 CI、镜像、迁移和备份恢复。必要作业全部成功才称完整 CI 通过；数量据实记录。可选集成关闭时不宣称供应商生产验收。

报告修改、命令及结果、兼容风险、未跑检查和证据位置。任务完成只停止本任务记录的 PID/端口并清理本任务成功临时资源；保留失败证据、依赖缓存和已有共享服务。

## 项目投产边界

资源上限、预览并发峰值、导入导出规模、连接数与查询预算按项目负载实测；既有基准不能外推任意容量，不通过跨请求权限缓存牺牲及时撤权。公开注册启用前需制定账号创建预算与反自动化策略，生产 CORS、TLS 和可信代理按实际入口核验。

密钥与数据库凭据轮换须先查[部署指南](../部署指南.md)的安全配置及相关加密配置，并隔离演练；不能直接替换 Fernet/TOTP 密钥导致旧数据不可解，也不能为接受旧签名绕过会话撤销。镜像 digest、扫描与最小权限也按部署指南核验。

真实通知供应商、外部告警、企业组织同步、异地备份与设备风险识别按项目选配；未配置不计为已验收。备份停写窗口、失败归档和保留清理需纳入容量规划，失败现场不自动删除，真实快照清理须先授权。
