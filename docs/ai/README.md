## 查阅规则

- 依赖和运行时：以 [版本要求](../../版本要求.md) 指向的锁文件及运行时配置为准。
- 接口字段与状态码：以目标序列化器、视图和测试为准；[生成的 OpenAPI](../../frontend/src/api/generated/openapi.json) 是可校验快照，变更后重新生成。
- 模块默认值与依赖：以 [模块注册表](../../backend/apps/core/modules.py) 及各模块 manifest 为准，不能把“代码存在”理解成“当前部署启用”。
- 实际验收：从 [兼容性记录](../../COMPATIBILITY.md) 进入最新证据；日期报告是历史记录，不是重复维护的开发规范。
- 若文档与代码不一致，先核对测试和调用方，修正文档并补充缺失验证；不要默默扩大能力声明。

## 交给另一个 AI 的任务开头

```text
这是基于 AdminCore 的业务项目。先读 AGENTS.md、PROJECT.md（若有）和业务上下文，
按 docs/ai/README.md 定位相关能力与实现，不必通读历史报告。
本次业务需求：……
先列出可复用能力、需要新增的业务模型/状态/权限、尚不明确的业务规则。
沿用基座认证、授权、租户、审计和组件，在独立业务模块实现首条完整业务链路，
完成对应自动化与实际操作验收，并报告未验证范围。
```

索引帮助快速缩小查阅范围，仍需读被修改的实现及其测试；不能承诺任何 AI 都无需代码核对。
