# 从需求到业务模块

先看 [能力地图](能力地图.md) 和 [工程约束](工程约束.md)。推荐用一个真实业务闭环推动开发，扩展业务模块而非重新实现基座。

## 1. 固定业务契约

把实体、字段、唯一编码、关系、金额精度、状态迁移、角色动作、数据归属、租户规则、导入重复策略及通知时机记录在业务上下文，使用 [模板](业务上下文模板.md)。明确哪些规则已确认、哪些是假设。完成标准：每项写操作都有操作者、前置状态、授权范围及失败行为。

## 2. 选择实现路径

| 场景 | 路径 | 起点 |
|---|---|---|
| 固定模型、主子表、关联、审批、导出与报表 | 生成器 v2 产出独立业务模块，再加业务服务规则 | [采购订单定义](../../examples/business-integration/purchase-orders.json)、[生成器 v2 能力基线](../代码生成器2.0第一阶段-2026-10-18.md) |
| 可配置的数据收集、发布后保留历史定义 | 在线表单与发布版本，按需接入附件/关联/审批 | [差旅表单](../../examples/online-forms-v2/travel-request.json)、[在线表单 v2](../在线表单设计器2.0第二阶段-2026-10-18.md) |
| 复杂状态机、库存、财务、跨域一致性 | 独立 app，复用授权/审计/幂等/outbox，不强行塞进通用表单 | [示例服务](../../backend/apps/example/services.py)、[生成运行时](../../backend/apps/core/codegen/runtime.py) |

生成器当前有 v1 与 v2 两种定义；旧模板只支持较简单字段，选用 v2 示例与预览产物中的接入说明。生成器不在线安装插件，也不代替业务规则评审。在线表单不是任意数据库建模器，审批不等于完整 BPMN 引擎。

完成标准：明确本次新增模型与复用的能力；复杂业务规则有落点，不以“已生成页面”当作业务完成。

## 3. 显式接入

1. 审查生成差异和输出目录中的接入说明，保留人工扩展文件；业务 app/页面放自己的命名空间。
2. 在 Django INSTALLED_APPS 和后端 MODULES 注册 manifest（在预设计算之前）；在前端 extensions 注册懒加载页面，声明菜单与精确动作权限。当前模块路由由注册表接入，按生成说明核对实际 URL。
3. 审查并提交迁移，尤其 tenant、唯一约束、外键删除规则、索引和主子表约束；已有表模式另核验 DDL。
4. 在隔离环境迁移、bootstrap 权限/菜单，显式启用模块并为验收角色授权。初始化不自动给旧角色扩权。
5. 用非管理员完成列表、详情、创建、更新、删除和越权拒绝；检查组织/租户/字段范围与版本冲突。

完成标准：路由、菜单和权限三者匹配，普通用户的允许/拒绝路径均有验证，模块关闭不破坏数据。

## 4. 接通业务链路

以采购为例：先建供应商/分类，再接订单与明细；确认业务编码与金额规则。复用 [采购流程](../../examples/business-integration/purchase-flow.json) 和 [采购报表](../../examples/business-integration/purchase-report.json) 验证提交、审批、状态回写、报表与下钻。示例定义是接入材料，需在隔离生成模块中运行；不能据此宣称仓库默认已安装采购系统。

按需求选择以下分支，不需要的能力保持关闭：

- 导入：列映射/预检/业务编码更新/重复策略/关联解析；主子表按整单事务，错误行修正与重试不重复副作用。
- 审批：业务快照、当前字段权限、不可变流程版本、撤回/退回/超时及状态回写；覆盖并发审批与业务写入。
- 文件：附件选择鉴权、引用登记、版本与删除保护；关联替换或业务删除后释放引用按原有事务实现。
- 报表：显式登记数据源和白名单，与列表相同租户/范围/字段策略，金额与主子表聚合单独校验。
- 通知或外部操作：事务内 outbox，执行时复核，重试/幂等和失败记录可观察。

完成标准：一条真实业务从录入到结果可走通，重试、冲突、撤权和拒绝路径有测试，跨能力的权限没有缺口。

## 5. 验证并交接

执行 [验证与交付](验证与交付.md) 对应检查；记录业务上下文中的实现位置、权限码、迁移、测试、启用方式及外部依赖。若修改公共接口，重新生成 SDK；若修改接入点，更新能力地图并运行文档检查。交付时列出确实跑过的检查和仍需业务方决策的规则。
