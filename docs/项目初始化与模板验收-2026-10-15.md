# 项目初始化与模板验收

## 交付契约

| 项目 | 内容 |
|---|---|
| 功能范围 | 明确 Git 提交导出独立源码；生成环境/项目归属/摘要基线；一条命令启动，固定状态/迁移检查/保留停止入口；只读三方升级计划。不是自动覆盖升级器 |
| 默认启用 | 不改变现有项目；初始化默认 minimal，可显式 standard。可选外部邮件/备份/图片处理默认关闭；创建后无需复制底座 Git 历史 |
| 外部依赖 | Python/Git/Docker Compose；首次构建需镜像/依赖源；minimal 三服务，standard 六服务。未假装免网络或免 Docker |
| 权限范围 | CLI 是宿主运维权限；只写明确的新目标目录，随机独立凭据，仅本机端口；已有项目拒绝覆盖，Compose 同名异属容器/卷/网络拒绝接管 |
| 关闭行为 | stop 只停止本项目并保留卷；up 正向迁移、不重置既有管理员密码；失败保留日志与数据；不提供删除卷命令 |
| 可重复验收 | `python -m pytest -q scripts/tests/test_create_project.py` 与 `python scripts/validate_project_template.py`；后者必须从包含工具的提交执行，以真实新 PostgreSQL/Nginx 和标准 Redis/Celery 验证 |

## 版本与升级边界

唯一底座版本 `backend/config/base-version.json` 当前为 `0.1.0-dev.1`，是开发基线，不代表正式稳定发行。管理员系统信息与 OpenAPI 共用；模块契约独立维持1，API仍为v1。CHANGELOG 不追溯编造发布历史。

升级工具逐路径比较导出基线、当前业务副本、目标底座的 SHA256，标识上游变更、本地变更及真实冲突，不读取实际环境，不输出内容，不执行迁移/合并，也不自动推进基线。已有项目同步修复、兼容期、备份和回退流程见[升级方法](底座版本与项目升级.md)。复杂二开仍需人工解决冲突、验证新业务及迁移。
