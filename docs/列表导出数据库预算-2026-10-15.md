# 列表与导出的数据库预算

当前内置通用 ViewSet 列表及服务端 CSV/XLSX 导出增加 PostgreSQL 局部执行预算。慢查询和等锁过久会取消数据库语句，返回统一 HTTP 503，不把数据库错误内容交给客户端。

| 项目 | 当前契约 |
|---|---|
| 默认限制 | 单条 SQL 30,000ms，单次锁等待2,000ms；不是整个请求的累计耗时 |
| 部署配置 | `ADMINCORE_QUERY_STATEMENT_TIMEOUT_MS` 允许1–300,000；`ADMINCORE_QUERY_LOCK_TIMEOUT_MS` 允许1–30,000；单位毫秒，0、负值、非整数、超上限拒绝启动 |
| 范围 | 用户、角色/权限/菜单、组织/岗位、字典、文件、任务、三类日志、通知/公告/模板/投递、审批、可靠事件、本人设备/在线用户及示例工单的标准 `list`；服务端 `data-io/export` |
| 保持原约束 | 列表权限/范围/分页/筛选不变；导出白名单、5,000行及10MiB上限仍执行；模块关闭仍拒绝访问 |
| 超时响应 | `{code:503, message:"查询超时或等待锁过久，请缩小筛选范围后重试", data:null}`，支持英文协商；不返回 SQL 或部分导出文件 |
| OpenAPI | 标准列表保留原200分页结构并增加503；导出保留CSV/XLSX二进制200及新增503 |
| 成本/依赖 | 复用 Django/现有 PostgreSQL 驱动，无新增依赖或迁移；SQLite 单元测试不增加预算SQL或事务 |

## 事务与连接边界

在列表/导出处理函数内开启 `atomic`，使用 `set_config(..., true)` 设置当前事务的 `statement_timeout` 和 `lock_timeout`。正常退出时显式恢复先前值，避免内层 savepoint 成功释放后把设置留在外层事务；失败先回滚，再将 PostgreSQL `57014`/`55P03` 转换为503。已有非零、更严格的数据库限制优先保留，嵌套预算只能收紧。

导出生成后仍须成功写入审计才发送文件；该事务内 SQL 超时会回滚已写审计并拒绝下载。普通数据库错误保留原处理，不伪装成预算超时，也不自动重试。

这里不限制认证/权限检查、中间件、详情、自定义 action、人员目录等独立 APIView、迁移、备份、导入及后台任务。它们保留各自现有约束；新增业务 ViewSet 应继承 `QueryBudgetListMixin` 或现有 `EnvelopeResponseMixin`。现有后台任务和实时通道仍使用各自登记的预算。

这是每条数据库语句/每次锁获取的上限，不是累计 SQL、CPU、内存、文件生成或整个 HTTP 请求的截止时间。游标导出分批执行也不等于整个导出限时30秒。应用服务器或代理超时不能替代数据库取消；本批不据此宣称查询规范、大数据容量或全部 P0 第15项已完成。

PostgreSQL 的计时和事务局部语义见官方[客户端超时配置](https://www.postgresql.org/docs/18/runtime-config-client.html)及[SET LOCAL](https://www.postgresql.org/docs/18/sql-set.html)。
