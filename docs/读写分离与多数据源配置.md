# 读写分离与多数据源配置

## 交付范围

AdminCore 默认只使用 `default` 主库，保持小项目无需增加数据库服务。设置
`ADMINCORE_DB_READ_REPLICA_ENABLED=true` 后，启动配置会要求完整的
`DB_REPLICA_*` 连接参数，并拒绝与主库具有相同引擎、库名、用户、主机和端口的
配置。副本连接只用于读取，迁移和所有写入仍固定使用 `default`。

请求级路由由 `PrimaryReplicaRouter` 和 `DatabaseRoutingMiddleware` 共同完成：

- GET、HEAD、OPTIONS 等安全请求的普通读取使用 `replica`；后台任务、命令行和未建立请求上下文的读取使用 `default`。
- POST、PUT、PATCH、DELETE 的读取与写入使用 `default`。事务内读取和 `select_for_update()` 的锁定读取也使用 `default`。
- 成功的变更请求会签发 30 秒（可配置 1–300 秒）的签名 HttpOnly Cookie，后续安全读取在窗口内固定主库，覆盖写后读一致性；失败响应不会签发。
- 副本查询在安全请求中发生数据库错误时关闭副本连接并只重试一次主库，同时返回 `X-AdminCore-Read-Replica-Fallback: primary`。不安全请求不会自动重试，避免重复副作用。

## 部署配置

`.env` 只在确实有独立只读副本时设置：

```dotenv
ADMINCORE_DB_READ_REPLICA_ENABLED=False
ADMINCORE_DB_PRIMARY_STICKY_SECONDS=30
DB_REPLICA_ENGINE=django.db.backends.postgresql
DB_REPLICA_NAME=
DB_REPLICA_USER=
DB_REPLICA_PASSWORD=
DB_REPLICA_HOST=
DB_REPLICA_PORT=5432
```

启用前应由数据库平台提供复制拓扑、只读用户、TLS/证书和延迟监控。AdminCore
不会自动创建复制、把副本当作迁移目标或在副本错误时重放写请求。副本持续不可用时
应由运维关闭开关并重启服务，回到单主库模式；连接凭据不进入 Git。

## 验收

`backend/tests/test_database_routing.py` 覆盖缺参/同库拒绝、实际路由、事务主库、
写后粘滞 Cookie、副本安全读取失败回退和不安全请求不重试；默认 testing 配置保持
SQLite 单库。真实双 PostgreSQL 复制延迟、证书轮换和生产容量属于部署环境验收，
不以本地路由测试替代。
