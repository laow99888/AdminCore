# 幂等入口与重试契约

`Idempotency-Key` 只对已登录 JSON 写请求生效。键按用户、业务作用域和请求
内容摘要隔离，成功响应保存 24 小时；相同键重试会返回原响应并带
`Idempotency-Replayed: true`，同键提交不同请求返回 409。业务失败会回滚幂等
记录，客户端可以修正参数后用新键重试；处理中重复请求返回 409，避免并发重复写入。
实现层同时限制方法为 `POST`、`PUT`、`PATCH` 或 `DELETE`；带键的读取请求会直接拒绝，
避免把查询误当成可重放的业务写入。此约束仅作用于调用该 helper 的入口，其他 API
不会因携带该请求头就自动获得幂等保证。

## 当前入口策略

| 入口 | 策略 | 说明 |
| --- | --- | --- |
| 审批创建、审批动作、通知创建、公告操作、特性开关创建 | 支持幂等 | 前端写请求默认生成键；失败可重试 |
| 在线表单记录提交、示例工作项创建 | 支持幂等 | 同一用户和作用域内避免重复提交 |
| 维护任务手动执行、Office 预览提交 | 强制幂等 | 代码在业务入口直接拒绝缺少键的请求 |
| 文件分片上传 | 分片协议 | 同一上传标识、分片序号和 SHA-256 可重试，不同内容返回 409；合并结果沿用同一会话，不复用 JSON 幂等记录 |
| 导入文件首次提交（multipart） | 新建批次 | 每次提交创建独立批次，没有请求键去重保证；网络结果不明时先查询任务中心，不盲目再次上传。源摘要只校验批次内容，不跨用户或批次合并 |
| 导入执行/人工接续 | 任务领取/逐行账本 | 重复投递已领取任务直接跳过；接续沿用源摘要及已提交行/错误账本，只执行剩余行，同一旧执行不能派生并发接续，冲突返回 409 |
| 明确要求版本号的资料更新 | 乐观锁协议 | 依据接口版本契约处理冲突，不默认具有请求键重放能力 |
| 登录、刷新、登出、读取接口 | 不适用 | 不产生可重复业务写入 |

入口实现集中在 `apps.core.idempotency.with_idempotency`；新增会产生外部副作
用或不可逆状态变更的 POST 必须先选择“支持”或“强制”，并补成功重放、不同
请求冲突、失败接续三类测试。现有兼容入口不因清理代码而强制改协议。

## 导入失败与恢复

导入提交的任务 ID 在 outbox 发布前持久化。队列不可用时保留任务和失败事件，按登记策略有限补偿，DEBUG 和生产环境都不会同步降级导入；恢复发布继续使用同一任务 ID。行写入、审计与账本共用事务，崩溃未提交行回滚，已提交成功行和校验错误不重放。修正源文件需新批次；源摘要改变、原设备/权限撤销、超出次数或源文件不可用会拒绝执行/接续。详见[任务可靠性与接续](任务可靠性与接续-2026-10-15.md)。

旧 `dispatch_task` 仅剩测试引用，已删除其 DEBUG 同步回退；回归改为当前 HTTP 提交与 outbox 发布链路。真实清理/接续并发脚本也移除了不再作用的旧 helper 补丁，保留原来的文件锁等待与复核断言。
