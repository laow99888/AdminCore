# 代码生成器 2.0 第一阶段

本阶段把简单 CRUD 生成升级为显式的业务结构生成：单表、树表、带多组明细的主子表。原 V1 和已有表核验命令继续使用；V2 用 `schema_version: 2` 显式选择。可视化入口为「系统管理 → 代码生成器」，同时要求管理员身份、`codegen:generate` 权限以及 system 模块开启。

## 已实现能力

| 范围 | 契约 |
| --- | --- |
| 字段 | 单行/多行文本、整数、布尔、金额/定点数、日期、带时区时间、枚举、数据字典、业务关联、附件引用 |
| 结构 | 单表；父子树；1–5 组主从明细，每组最多 200 行 |
| 列表 | 显示列、包含/精确/区间筛选、可排序字段、默认排序、稳定分页；明细仅在详情读取 |
| 表单 | 控件、顺序、必填、默认值、长度、上下界、精度；不可编辑字段由服务端计算 |
| 数据模型 | 真实 Django 字段、外键、数据库检查约束、唯一约束、显式索引；迁移由开发者审查后创建 |
| 可视化配置 | 字段和明细组编辑、定义导入/导出、源码逐文件预览、ZIP 下载；配置变化使旧预览失效 |
| 二次开发 | 后端 `extensions.py` 和前端 `RecordListView.vue` 首次创建后保留；其余文件为生成器管理 |
| 继承基座 | 数据范围、租户隔离、创建幂等、整单版本号、事务审计、草稿离开保护、冲突保留输入和显式载入最新值 |

金额全链路使用十进制字符串和 Python `Decimal`，不经过 JavaScript 浮点运算。精度最多 18 位，小数位最多 8 位；例如 `"0.10"`，而非 `0.1`。唯一编码按租户约束；无租户时也约束唯一。明细唯一性以主记录为边界。

树表通过父节点筛选逐层分页浏览。移动时对同一树模型串行防环检查，拒绝自身/后代为父节点；有子节点或其他受保护引用时不能删除。该实现适合常见管理分类，不提供拖拽整树编辑或无限深度遍历。

## 关系和主子表规则

业务关联必须明确 `target.module/model/label`，运行时只允许已登记且启用的生成业务模块，显示字段必须为普通文本。查询选项和保存都重新检查目标读取权限、数据范围与租户边界；读权限撤销后不会继续返回关联名称。选项按 50 项分页。附件引用既有文件中心中有权读取的一般文件；不生成独立上传器，不允许引用头像或导入临时文件。

字典使用启用的字典及启用项；历史记录不会随字典停用被改写，再次提交停用项会拒绝。字典更名后的显示标签在读取时解析。

主子表由主记录 `version` 控制整单并发。POST 提交所有分组；PATCH 省略分组表示保留，提交某组表示完整替换该组。明细 ID 不属于编辑契约，替换后可变化，不应用作外部业务引用。主记录、明细、扩展钩子与审计在同一事务中提交，任意失败整体回滚。编辑页面先读取完整详情，避免把列表中未返回的明细误当空数组提交。

## 示例与接入

三个可执行定义位于 [examples/codegen-v2](../examples/codegen-v2)：先生成供应商，再生成分类与采购订单。采购订单覆盖九类业务字段、两组明细、关联标签和只读合计。

在 backend 目录使用现有 Python 环境预览，输出到待审目录：

```powershell
python manage.py generate_module --definition ../examples/codegen-v2/suppliers.json --output ../generated-review --plan ../suppliers-plan.json
```

审查计划和差异后逐文件添加 `--select`，例如：

```powershell
python manage.py generate_module --definition ../examples/codegen-v2/suppliers.json --output ../generated-review --apply-plan ../suppliers-plan.json --select backend/apps/cg_suppliers/models.py
```

首次完整接入应选择计划中的全部新文件，随后按生成的 `docs/generated/<module>.md` 显式配置 `INSTALLED_APPS`、`MODULES`、前端 registry，创建并审查迁移、执行初始化、分配权限，最后开启模块。关闭模块保留其表和迁移。生成产物并非独立项目，需要当前 AdminCore 基座中的 V2 公共运行时和组件。

源码下载与预览不修改服务器源码，也不执行安装或迁移。定义限 128 KB、源码限 2 MB，管理员接口限流每分钟 20 次。不接受动态脚本、自定义表达式或任意组件名称。

## 手写扩展与重生成

采购订单的合计需要项目实现自己的业务规则。以下放入生成模块的 `extensions.py`：

```python
from decimal import Decimal


def before_save(*, actor, instance, values, details):
    if 'lines' in details:
        values['amount'] = sum(
            (Decimal(line['price']) * line['quantity'] for line in details['lines']),
            Decimal('0'),
        )


def after_save(*, actor, instance, action):
    pass


def before_delete(*, actor, instance):
    pass
```

`before_save` 在写入前校验或计算；更新时 `instance` 为当前锁定记录，创建时为 None。`values` 使用序列化后的 Django 字段名称，例如关联为 `supplier_id`。`after_save` 和 `before_delete` 也在事务内。外部邮件/HTTP 等副作用应走基座 outbox，不在事务钩子中直接发送。必填只读字段需由钩子提供合法值。

重新预览时，已有 `extensions.py`、`RecordListView.vue` 标记为 `preserved`；应用计划禁止选择它们，避免覆盖手写逻辑。已有 V2 目录也拒绝使用 V1 定义意外降级。其他文件可选择应用，并继续执行原文件摘要校验、独占写锁和本地备份。不要解压 ZIP 直接覆盖既有模块。自定义模型方法等未提供独立扩展面的代码，仍需人工评审合并；已有 V1 模块升级 V2 也须人工评审迁移和前端入口。

## 验收方式

```powershell
python -m pytest tests/test_codegen.py tests/test_codegen_v2.py
python ../scripts/validate_codegen_v2.py --postgres --browser
```

第二条可在仓库根目录执行 `python scripts/validate_codegen_v2.py --postgres --browser`。脚本按真实 CLI 生成三个模块、实际创建迁移，在独占 PostgreSQL 中验证数据约束、事务、越权引用、租户、幂等、版本冲突和并发树移动，并严格验证 OpenAPI。浏览器部分创建独占 SQLite、前端副本和临时管理员，验证生成页面构建、桌面/手机登录、源码预览下载、单表/树/主子表操作、金额、关系标签、编辑明细载入、版本冲突与区间查询；占用 18471/18472，结束后按记录 PID 关闭。

成功后移除专属 PostgreSQL 和生成源码；保留依赖缓存、报告和日志。失败保留源码、日志及浏览器 trace；密码文件始终删除，证据统一在 Git 忽略的 `.codex-validation/codegen-v2-*`。CI 的 codegen 任务执行原 V1 接入验收及 V2 PostgreSQL/浏览器验收。

本阶段不含在线表单设计器 2.0、任意布局联动表达式、流程状态机自动生成、多对多与跨主单稳定明细引用、任意历史表复杂关系逆向、复杂项目一键完成。它提供可扩展的业务代码起点；领域规则、字段敏感策略和大型数据集的专用索引仍由具体项目设计。
