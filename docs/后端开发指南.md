# 后端开发指南

当前后端使用 Django LTS 与 DRF，精确版本以 [版本要求](../版本要求.md) 和锁文件为准。先从 [能力地图](ai/能力地图.md) 定位实现；结构见 [架构](../项目结构说明.md)。本文是现行规范，日期报告记录历史验收。

## 环境与启动

首次启动按 [快速开始](快速开始.md)，明确选择 `DJANGO_ENV`；依赖使用 `python -m pip install --require-hashes -r requirements.dev.lock`。PowerShell/Bash 使用各自环境变量语法。迁移后执行 `bootstrap_admincore` 初始化声明；新账号密码来自明确配置，初始化不重置已有密码、不自动给旧角色扩权。测试配置与业务库隔离。

## 新增业务

按 [业务开发流程](ai/业务开发流程.md) 建独立 app，优先使用生成器 v2。典型路径为 models / serializers / services / views / urls / manifest / migrations，测试放 backend/tests；参考 [示例服务](../backend/apps/example/services.py) 和 [生成运行时](../backend/apps/core/codegen/runtime.py)。

显式注册 INSTALLED_APPS、MODULES、前端 extensions 和模块权限/菜单；关闭模块保留模型、迁移与数据。声明结构读取 [契约定义](../backend/apps/core/contracts.py)，按生成包的接入说明核对，不复制历史报告的简化代码。

## 读写契约

- 读取同时执行功能权限、租户、数据范围和字段策略；详情、列表、导出、报表、关联标签和搜索一致。列表显式声明查询白名单与稳定排序，复用查询预算。
- 写入在事务内复核当前账户、原会话、动作权限和对象范围，按目标模块锁顺序锁定业务行，校验版本与状态，再写业务和审计。关联必须同租户。
- 序列化字段使用白名单，受保护字段由服务端生成；拒绝字段越权写入。不能用 `fields='__all__'` 暴露完整用户或业务模型。
- 后台任务从可信来源恢复租户，执行时重查授权；外部副作用使用已有任务/outbox，明确重试、幂等与失败状态。

完整约束及并发边界见 [工程约束](ai/工程约束.md)。只有 IsAuthenticated 的裸 ModelViewSet 不能作为生产业务模板。

## API、审计与迁移

响应、认证例外、分页及接口真源见 [API 规范](API规范.md)。使用现有异常与国际化消息，新增接口补 OpenAPI 并重新生成 SDK。

通过 `apps.logs.audit.write_audit` 在业务事务内记录声明字段/必要摘要。密码、令牌、完整联系方式和任意请求体不入日志；来源 IP 复用统一可信代理解析。不存在旧指南里的 log_action 装饰器。

模型变更提交迁移，隔离验证旧数据、外键、租户唯一约束及索引；金额用 Decimal。已有表模式不会自动建立 DDL。采用先扩展后移除的兼容迁移，反向删表不是常规回退。

## 验证

运行相关 pytest、Django check、迁移漂移、严格 OpenAPI/SDK。SQLite 只证明单元逻辑，锁与竞态另做独立 PostgreSQL 验收。命令与交付标准见 [验证与交付](ai/验证与交付.md)。
