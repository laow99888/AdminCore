# AdminCore 后端开发指南

运行时与依赖统一以 [版本要求.md](../版本要求.md) 为准；兼容性验证见 [COMPATIBILITY.md](../COMPATIBILITY.md)。

## 项目概览

AdminCore 后端是一个基于 **Django 4.2 + Django REST Framework** 的企业级 API 服务。

### 核心特性

- ✅ JWT 认证（Simple JWT）
- ✅ RBAC 权限管理系统
- ✅ 操作、登录、异常日志
- ✅ 自定义异常处理
- ✅ 标准分页、过滤、排序
- ✅ API 文档（Swagger/ReDoc）
- ✅ Celery 任务队列
- ✅ Redis 缓存

## 环境配置

### 1. 创建虚拟环境

```bash
cd backend
python -m venv venv

# 激活虚拟环境
# Windows
venv\Scripts\activate
# macOS/Linux
source venv/bin/activate
```

### 2. 安装依赖

```bash
python -m pip install --require-hashes -r requirements.lock
```

### 3. 配置环境变量

复制 `.env.example` 为 `.env`：

```bash
cp .env.example .env
```

编辑 `.env` 文件，设置：

```env
DJANGO_DEBUG=True
DJANGO_SECRET_KEY=your-secret-key
DB_NAME=admincore
DB_USER=postgres
DB_PASSWORD=postgres
DB_HOST=localhost
DB_PORT=5432
REDIS_URL=redis://localhost:6379/0
```

### 4. 数据库迁移

```bash
python manage.py migrate
```

### 5. 创建超级用户

```bash
python manage.py createsuperuser
```

### 6. 启动开发服务器

```bash
python manage.py runserver 0.0.0.0:8000
```

访问：
- API: http://localhost:8000/api/v1/
- 管理后台: http://localhost:8000/admin/
- API 文档: http://localhost:8000/api/v1/docs/

## API 约定

### 响应格式（统一）

```json
{
  "code": 200,
  "message": "success",
  "data": {
    // 实际数据
  }
}
```

### 错误响应

```json
{
  "code": 400,
  "message": "参数验证失败",
  "data": {
    "field": ["error message"]
  }
}
```

### 常见状态码

| 代码 | 含义 |
|------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 参数错误 |
| 401 | 未认证 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 500 | 服务器错误 |

## 认证系统

### JWT Token 获取

**POST** `/api/v1/auth/login/`

```json
{
  "username": "admin",
  "password": "<已配置的管理员强密码>"
}
```

**响应：** 登录端点沿用 JWT 顶层格式，不包统一业务响应：

```json
{"access": "<access_token>", "refresh": "<refresh_token>"}
```

随后请求 `GET /api/v1/auth/me/`，用户信息位于统一响应的 `data` 中。启用 TOTP 或登录验证码时，按认证挑战响应补交验证字段；初始密码策略可能要求登录后修改密码。

### 使用 Token

在请求头中添加：

```
Authorization: Bearer <access_token>
```

### 刷新 Token

**POST** `/api/v1/auth/refresh/`

```json
{
  "refresh": "<refresh_token>"
}
```

### 用户注册（生产默认关闭）

**POST** `/api/v1/auth/register/`

```json
{
  "username": "newuser",
  "email": "newuser@example.com",
  "password": "<符合密码策略的新密码>",
  "password2": "<再次填写相同密码>"
}
```

## 权限系统（RBAC）

### 角色管理

**GET** `/api/v1/permissions/roles/`

列出所有角色（管理员权限）

**POST** `/api/v1/permissions/roles/`

创建新角色（管理员权限）

```json
{
  "name": "编辑",
  "description": "可以编辑内容",
  "is_active": true,
  "permission_ids": ["perm-id-1", "perm-id-2"]
}
```

### 权限列表

**GET** `/api/v1/permissions/permissions/`

列出所有权限（认证用户可见）

### 菜单管理

**GET** `/api/v1/permissions/menus/`

获取用户可访问的菜单

**GET** `/api/v1/permissions/menus/my_menu/`

获取当前用户的菜单列表

## 创建新的 ViewSet

### 示例：用户管理

```python
# apps/users/serializers.py
from rest_framework import serializers
from django.contrib.auth import get_user_model

User = get_user_model()

class UserListSerializer(serializers.ModelSerializer):
    class Meta:
        model = User
        fields = ('id', 'username', 'email', 'is_active', 'created_at')

class UserDetailSerializer(serializers.ModelSerializer):
    class Meta:
        model = User
        fields = '__all__'
```

```python
# apps/users/views.py
from rest_framework import viewsets
from rest_framework.permissions import IsAuthenticated
from django.contrib.auth import get_user_model
from .serializers import UserListSerializer, UserDetailSerializer
from apps.permissions.permissions import IsAdmin

User = get_user_model()

class UserViewSet(viewsets.ModelViewSet):
    permission_classes = [IsAuthenticated, IsAdmin]
    filterset_fields = ['is_active']
    search_fields = ['username', 'email']
    ordering_fields = ['created_at', 'username']

    def get_queryset(self):
        return User.objects.all()

    def get_serializer_class(self):
        if self.action == 'list':
            return UserListSerializer
        return UserDetailSerializer
```

```python
# apps/users/urls.py
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from .views import UserViewSet

router = DefaultRouter()
router.register(r'', UserViewSet, basename='user')

urlpatterns = [
    path('', include(router.urls)),
]
```

## 记录操作日志

业务写入使用 `apps.logs.audit.write_audit`，在与业务相同的 `transaction.atomic` 内保存审计，不存在 `apps.logs.utils.log_action` 装饰器。

```python
from django.db import transaction
from apps.logs.audit import write_audit

with transaction.atomic():
    # 先按项目写入边界重新锁定并授权，再完成业务写入。
    user = create_authorized_user()
    write_audit(request=request, resource='user', identifier=user.pk,
                action='create', after={'id': str(user.pk), 'username': user.username})
```

不要把密码、完整联系方式、令牌或任意请求体放入审计。来源 IP 由统一可信代理解析器提供，不在各模块直接信任转发头。

## 最佳实践

### 1. 分离业务逻辑

```python
# services.py
class UserService:
    @staticmethod
    def create_user(username, email, password):
        # 业务逻辑
        pass

# views.py
from .services import UserService

class UserViewSet(viewsets.ModelViewSet):
    def perform_create(self, serializer):
        user = UserService.create_user(...)
        serializer.save()
```

### 2. 使用 select_related 和 prefetch_related

```python
def get_queryset(self):
    return User.objects.select_related(
        'profile'
    ).prefetch_related(
        'roles__permissions'
    )
```

### 3. 缓存查询结果

```python
from django.views.decorators.cache import cache_page

@cache_page(60 * 5)  # 缓存 5 分钟
def list_roles(request):
    pass
```

### 4. 使用事务

```python
from django.db import transaction

@transaction.atomic
def create_user_with_profile(user_data, profile_data):
    user = User.objects.create(**user_data)
    Profile.objects.create(user=user, **profile_data)
    return user
```

## 常见问题

### Q: 如何添加新的权限？

在 Django admin 中添加 Permission 记录：
- resource: 资源类型
- action: 操作类型
- code: 权限代码

### Q: 如何限制 API 访问频率？

在 REST_FRAMEWORK 配置中设置 throttle：

```python
'DEFAULT_THROTTLE_RATES': {
    'anon': '100/hour',
    'user': '1000/hour',
}
```

### Q: 如何自定义响应格式？

编辑 `apps/core/pagination.py` 中的响应格式
