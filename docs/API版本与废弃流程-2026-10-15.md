# API版本与废弃流程

状态：已验收（当前版本级通知与发布契约范围）。

| 契约 | 本批范围 |
|---|---|
| 功能范围 | 当前v1版本登记、只读公共版本说明、标准Deprecation/Sunset/Link响应头、OpenAPI生命周期声明及独立SSE一致响应；停用必须独立发布，不自动拒绝请求。 |
| 默认是否启用 | 默认v1 active，无弃用日期；全预设保留核心契约。环境配置需要重启Python服务。 |
| 外部依赖 | 复用Django/DRF/schema；无新库、网络调用、队列或后台计划。 |
| 权限与数据范围 | 公共说明只含已登记版本/日期/文档地址，无账号、对象或环境变量；原接口的认证/数据范围保持。迁移URL不携带凭据/查询参数，服务端不请求该URL。 |
| 关闭后的行为 | 将配置恢复为空对象并重启，撤回弃用标识，原接口与数据不变。已发布弃用计划需发布更正说明。 |
| 验收条件 | 配置反例、90天边界、默认/预告/弃用/到期、错误/下载/流响应、原Link保留、CORS及OpenAPI、真实隔离服务启停配置与旧账号/记录保留。 |

参考[RFC 9745](https://www.rfc-editor.org/rfc/rfc9745.html)：`Deprecation: @<Unix秒>`；参考[RFC 8594](https://www.rfc-editor.org/rfc/rfc8594.html)：`Sunset`使用HTTP-date。两个日期格式不同；弃用不改变资源行为，Sunset是预期停用通知，不是缓存期限或自动删除指令。

当前没有v2，没有安排正式v1停用。`GET /api/versions/`返回实际登记状态：active/scheduled/deprecated/sunset_due、最低90天兼容期、不会自动停用的约定。它不反射请求Host构造链接，也不宣称不存在的替代版本可用。版本级策略覆盖`/api/v1/`响应，包括认证失败、未知对象、下载和流；不会给管理后台或未知v2标为v1。单接口废弃未纳入本批，应结合路由独立发布。

配置`ADMINCORE_API_LIFECYCLE`为严格JSON，仅接受已登记v1和deprecated_at/sunset_at/migration_url字段，日期为UTC整秒Z格式；重复JSON键、未知版本/字段、缺弃用日期、缺迁移说明、早于90天的Sunset及不安全URL在启动时拒绝。迁移地址只允许HTTPS文档地址（无凭据、查询、片段及非443端口）或本机实际存在的`/api/versions/`。不会访问或自动验证外部文档是否写完，发布者必须人工审阅内容。不可把示例日期直接用于正式部署。

```sh
# 仅用于隔离验收的预告示例；正式发布前替换为已审阅的迁移文档。
ADMINCORE_API_LIFECYCLE='{"v1":{"deprecated_at":"2027-01-01T00:00:00Z","sunset_at":"2027-04-01T00:00:00Z","migration_url":"/api/versions/"}}'
```

发布流程：先提供可运行的新版本及迁移/鉴权/错误结构/兼容说明，完成调用方清点和回归，再公告弃用时间、至少90天兼容窗口与迁移URL；发布后核对旧/新版本及HTTP头、OpenAPI与调用方迁移。停用日期前复核调用方与回退方案；未完成则先延期并发布更正。到期只显示sunset_due，不自动410；确认停用另提删除路由的发布、备份与恢复边界，保留发布记录，不能只改日期模拟停用。紧急安全修复走独立安全发布，不绕过数据保护和验收。

配置回退仅撤回通知元数据，不回滚数据库或恢复已删除的路由。反向代理须透传上述响应头；跨源只对原CORS允许源公开这些头，不扩大允许源或凭据策略。
