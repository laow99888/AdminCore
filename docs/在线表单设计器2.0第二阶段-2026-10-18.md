# 在线表单设计器 2.0（第二阶段）

本阶段在第一阶段代码生成器之后，完善在线表单的配置、预览和运行能力。代码生成器产出可继续开发的 Django/Vue 业务源码；在线表单使用受限 JSON 定义运行，记录存入 `OnlineFormRecord.data`，不会创建业务表、自动安装源码或执行迁移。这两种路径各自保留，不能把在线表单当作复杂业务代码的替代品。

## 已实现范围

| 能力 | 本阶段行为 |
| --- | --- |
| 布局 | 最多 20 个分组；字段半行/整行；桌面两列、手机单列；字段上下移动 |
| 字段 | 原有文本、多行文本、数值、单选、日期、布尔，加精确金额、日期时间、多选、明细子表，共 10 类 |
| 属性 | 必填、默认值、选项、文本长度、数值/金额上下限、金额精度、帮助说明、占位提示 |
| 明细 | 最多 5 个明细组；每组最多 50 字段、100 行；配置最少/最多行数、默认值、行内联动与跨字段校验 |
| 显隐和必填 | 声明式条件，最多 5 条且全部满足；等于、不等于、属于候选值、为空、不为空、大小比较 |
| 跨字段校验 | 同类型数值/金额/日期/日期时间比较；支持自定义失败提示；主表和明细行分别校验 |
| 设计操作 | 新建、编辑、保存、发布、复制为新草稿、JSON 导入导出、服务端校验 |
| 预览 | 与实际填写共用组件；响应式布局、明细操作和联动立即生效；试填由服务端校验且不保存记录 |
| 运行 | 字段和明细行错误就地显示；失败保留输入；同内容重试沿用幂等键；成功恢复默认值；未保存离开提示和会话撤销清理 |
| 服务端 | 保存和发布校验定义；提交和修改记录校验数据；隐藏字段不落库；原有所有者隔离、版本冲突和幂等继续生效 |

界面复用 Vue、Element Plus 和现有组件，无新增生产依赖。配置操作按管理员身份与创建/修改/发布权限禁用；服务端仍是最终授权边界。

## 使用

`online_forms` 仍为可选模块，默认关闭。启用后显式赋予 `online_form:read/create/update/publish` 等所需权限。设计操作仍要求管理员身份。实际填写要求登录，提交还要求 `online_form:record_create`。读取和更新记录继续通过已有所有者范围 API。

设计入口 `/online-forms`，发布后填写入口 `/online-forms/<code>`。现有草稿在编辑器中转换成 V2，只有显式保存时才写入。旧版已发布定义和既有记录无需数据迁移，继续使用原有校验协议。

示例：[出差申请定义](../examples/online-forms-v2/travel-request.json)。新建草稿，导入该 JSON，设置名称与唯一编码，在“实时预览”试填，校验通过后保存和发布。它覆盖境外出差显示护照、预算达到 1000 时必填说明、行程日期比较、费用明细和精确金额。

## 协议与边界

顶层使用 `schema_version: 2`，只允许 `sections`、`fields`、`rules`。每个字段使用稳定的 `key`。字段数量为 1～50，字段标识拒绝原型污染保留名。配置和提交数据各限 128 KiB。客户端不能指定脚本、HTML 组件、远程 URL、SQL 或任意求值表达式。

条件形如：

```json
{"field": "budget", "op": "gte", "value": "1000.00"}
```

`visible_when` 和 `required_when` 都是条件数组，全部条件满足时生效。支持 `eq/ne/in/empty/not_empty/lt/lte/gt/gte`。`in` 的候选值为 1～20 个同类型值；空值操作不带 `value`。大小比较只适用于数值、金额、日期和日期时间。布尔 `true` 与数字 `1` 不相等。

条件只能引用同一作用域中声明在前的普通字段，不能引用明细组、多选字段、后面的字段或其他明细行。这样求值顺序明确且没有环。明细条件仅看当前行。调序、改名或更改类型后，旧引用不会偷偷重写，保存/校验会拒绝失效引用；按实际业务修改规则后再保存。

隐藏字段的提交值、旧值和默认值均不保存，也不参与后续条件。默认值在字段缺省时使用；显式空值在 V2 视为未填，必填会报错。已隐藏的字段不参与必填和跨字段比较。跨字段比较遇到任一空值或类型错误会跳过该比较，独立的类型/必填错误仍返回。明细空行不会自动删除，须填写或显式移除。

金额通过 JSON 字符串传递，服务端用 `Decimal`，前端用定点 `BigInt` 比较，支持最多 18 位有效数字、小数位 0～8；金额精度不符直接报错，不做静默舍入。日期为 `YYYY-MM-DD`，日期时间为带秒和时区的 ISO 文本，例如 `2026-10-18T12:00:00+08:00`。时间比较按实际时间点处理。

`POST /api/v1/online-forms/validate/` 接受 `{definition, data?}`，返回规范化定义和可选的规范化数据。它只用于管理员设计验收，不写库，响应禁止缓存，每用户每分钟最多 60 次。实际记录提交仍走原有记录接口，不能通过此接口绕过权限。

本阶段提供两列布局和单层明细，不提供任意嵌套容器、拖拽栅格、任意 JavaScript、自动计算公式、数据库关系/文件访问选择器、在线业务表建模、流程状态机或同编码多版发布。复杂业务的领域规则、关系约束、事务和专用列表仍应落在第一阶段生成的业务模块及手写扩展中。
