# 交叉审查修复与在用环境升级验收

日期：2026-10-13。修复依据：[交叉审查核对](交叉审查核对-2026-10-13.md)。本报告区分代码修复、实际部署与仍需业务决定的增强项。

**结果：本次确认的生产密钥、代理限流、API 契约、SPA CSP 和依赖就绪检查问题已修复；旧容器已经更新。GLM 的五条部署事项已执行，并补齐备份、数据库凭据轮换和 beat 构建。当前仍是本机 HTTP 环境，不宣称公网 HTTPS 上线完成。**

## 修复与部署

- 生产配置拒绝缺失、过短、低字符多样性、开发默认和已知示例密钥；构建 collectstatic 改用进程内临时随机密钥，避免绕过运行时要求。
- 保留既有 API 限流，新增登录的来源/用户名固定时间窗原子计数；Nginx 覆盖不可信的地址头，只信任明确网关；8000 默认绑定本机。
- 默认关闭公开注册，保留管理员创建用户和显式配置开启的能力。
- API schema 补齐自定义 JWT 声明、响应包、分页、关键请求/响应和下载类型；处理 schema 模拟查询，消除严格生成诊断；文档入口限管理员。
- SPA 与静态资源发送实际 CSP、安全响应头；HTML 禁用缓存，保留哈希资源长缓存。允许组件动态内联样式，拒绝内联脚本/eval。文档/admin 未强套用 SPA 的脚本限制。
- 健康 API 查询 PostgreSQL 并 ping Redis，故障返回 503；worker 独立验收，避免启动循环。
- 新增 13 项后端回归与 GitHub Actions 配置，固定既有运行时，执行后端/契约和前端检查。
- 在维护窗口执行数据库及媒体备份，备份时间戳 `20261013-084142`，两份文件的 SHA-256 校验通过；保留数据卷。
- 轮换 admin 密码、Django 密钥和 PostgreSQL 角色密码，同步 `.env`；禁用 demo，保留账号和关联数据。
- 构建 backend、worker、beat、frontend，执行迁移与更新；所有应用环境同步最后一次管理员密码。

本地管理员凭据保存在项目根目录 `.env.admin-access.txt`；该文件与 `.env`、备份、诊断目录已由 Git 忽略，并将访问限制为当前管理员和 SYSTEM。不要把它加入 Git 或分享。

浏览器验收脚本曾因处理换行不当，导致输入接口把第一次新密码写进错误输出。发现后已再次生成强密码、撤销所有旧会话、更新本地文件并重新创建应用容器；最后一次密码通过 API 和浏览器验收。该事件不涉及最终密码，不能继续使用第一次生成的密码。

## 边界与资源

- 未安装公网域名证书或外置 TLS 网关，未启用 HSTS；当前 4 项部署警告对应这一事实。数据库仍在本机 Compose 网络内，未强行配置不具备证书支持的 PostgreSQL TLS。
- 未增加前端单元测试框架、全面类型检查、Flower/CDN、分片上传、病毒扫描或 Cookie 认证迁移；这些是后续增强，本次未直接套用 Claude 示例。
- GitHub Actions 已配置；远端是否实际通过必须另行读取运行结果，不能用本地通过代替。
- 构建曾因旧构建密钥过短失败，修复 Dockerfile 后成功；保留首次失败日志和诊断。权限设置曾将目录继承参数误用于凭据文件，已改用文件权限并核验可读。
- 验收空 CSV 和异步任务按确切记录的文件/任务 UUID 清理，不删除用户业务数据。成功 pytest/冒烟的媒体临时目录由现有清理逻辑删除。
- 数据库、媒体备份和升级前配置保留，供恢复使用；恢复数据库备份不会自动回滚数据库角色密码，应配合当前有效连接凭据。保留依赖、镜像和构建缓存。
- 没有启动临时开发服务器或 watcher，也没有新占用端口。用户要求更新的正式六个服务保持运行；本轮浏览器验收标签页在结束时关闭，不按进程名终止共享服务。
