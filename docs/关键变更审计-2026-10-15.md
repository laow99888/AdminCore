# 关键变更审计

本批把现有业务 API 的关键管理写入接到显式、安全的前后值投影，并在操作日志页提供详情。既有描述和旧记录保留，新增八个字段只做加法迁移，不把缺少证据的旧日志补成结构化记录。

| 交付项 | 范围与边界 |
|---|---|
| 功能范围 | 用户管理与管理员改密、角色授权、菜单、部门/成员/数据范围、岗位/任职、登记参数/字典、维护计划及发起、审批状态、公告、文件生命周期和历史清理的关键变更；操作者、请求/任务关联；用户/文件批量逐项结果；日志详情 |
| 默认是否启用 | 日志及审计基础能力始终启用；没有新增外部服务、计划或权限，不打开可选业务模块 |
| 外部依赖 | 原数据库及存储；异步执行沿用 Celery、TaskRecord、MaintenanceRequest；不依赖实时通道、邮件或 system 诊断页面 |
| 权限与数据范围 | 沿用 log:read 与 log 数据范围；三类日志 API 只读、private/no-store；Django admin 禁止新增、修改和删除，查看需对应权限；参数与清理保留权限仍沿用 config:update、schedule:run 等既有授权 |
| 关闭后的行为 | 可选模块关停时没有业务写入入口，已有日志继续按权限查看；关闭 system 不停止审计；tasks 关闭后不消费该模块任务，已存审计不清空 |
| 可重复验收 | 下述自动测试、独立 PostgreSQL/Nginx 事务验收、正式加法升级与旧数据摘要核对；远端五项 CI 在提交后单独记录 |

## 投影与敏感信息

`apps.logs.audit` 只接受已登记资源和白名单字段。新增模型字段不会自动落日志；禁止把 request.data 或完整模型序列化传入。单个前值/后值上限 32 KiB，批量最多 1,000 项、每项只保留 UUID 与 HTTP 状态。新业务接入须登记字段并在同一事务内调用 write_audit。

密码、密码哈希、JWT、OTP/恢复码、密钥、原邮箱/电话不进入新投影。公告不复制正文，只登记长度和 SHA-256，可辨识等长修改；字典只登记配置状态和项目数量，不复制所有字典值；Logo 仅摘要。上传文件名及操作说明仍沿用原文件生命周期描述；不会写存储路径、访问密钥或二进制内容。

用户和角色投影包含权限关联 ID，用户改密只记录会话版本与首次改密要求等状态。个人资料及登录安全等既有日志仍保留自己的安全描述，audit_version=0；本批不宣称所有 ORM、SQL、管理脚本写入均自动产生完整前后值。三类日志的 admin 入口只读。新增扩展业务需显式接入。文件上传/下载等非生命周期记录同样不伪装成完整变更快照。

## 关联与一致性

HTTP 请求接受既有合法 X-Request-ID 或生成 UUID，日志保存相同关联值；请求结束恢复 ContextVar，防止下一请求串号。Celery 日志补 task_id；本批维护发起与清理审计额外保存 task_record_id，并从 MaintenanceRequest 取原始请求 ID。任务关联是保留的 UUID，不会随 TaskRecord 级联删除。

操作者保留 actor_identifier；删除用户后 user 外键置空，标识仍在。新结构化记录 audit_version=1，旧日志为 0，前端明确提示“未登记结构化前后值”。详情保留直接对象响应格式；分页列表按需排除 before_values、after_values、batch_results，避免重复传输。

关键数据库写入与审计同事务；角色/用户、审批和菜单在取前值前锁定当前记录，避免把并发修改前的陈旧对象作为前值。审计失败回滚业务与同事务可靠事件，HTTP 不返回成功。用户批量是整批事务，拒绝混合越权/缺失 ID 并审计拒绝结果。文件批量沿用逐项成功/失败语义，每项生命周期审计与该项事务一致，另有汇总；汇总失败不能撤销已完成的其他项。

只读 API/admin 是应用访问约束，不是数据库级不可篡改存储。受信任数据库管理员仍可直接写表；旧日志未追溯补造证据。原日志外键在用户删除时置空也属既有行为。若具体项目需要合规级不可篡改归档，需单独部署和验收外部归档。

## Django 管理后台续批

当前注册的用户、角色与内联授权、权限定义、用户角色绑定、菜单、旧资料、普通文件、站内通知及任务记录后台写入口已接入同一显式投影。用户额外登记 Django group/permission ID；联系方式仍排除，通知只登记正文长度/摘要。Django 自身 LogEntry 保留，同时产生统一 OperationLog；不复制 Django 的自由文本表单变更消息。

写表单先锁定记录取前值，在所有内联/m2m 保存后读取后值；单项删除以及批量 action 整个 POST 均包含于事务。批量最多 1,000 项，逐项审计和汇总结果；第二条审计失败时第一条审计也回滚。后台用户密码表单扩展外层事务，原密码、会话版本、Django 日志均一起回滚。没有真实 request 的手工调用不是后台访问契约；原资料保护测试改用请求对象并核对锁内版本。

files/notifications/tasks 关闭时，对应后台模型入口隐藏、查看和写入权限拒绝，数据保留。审计自身后台仍只读。复用现有 Django 管理权限，不给既有角色新增授权。

Nginx 的 /admin/ 原转发 Host 会丢弃非标准端口，使浏览器 Origin 与 Django 看到的地址不一致；改为保留原 Host 端口，Django ALLOWED_HOSTS 与 CSRF 检查继续执行。独立验收使用真实反向代理、Cookie/CSRF 与 Origin：管理员登录/角色创建、跨源请求拒绝和统一日志关联；不关闭 CSRF 或绕过证书检查。
