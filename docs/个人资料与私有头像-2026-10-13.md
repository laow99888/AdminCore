# 个人资料与私有头像验收

本批补齐设置页的姓名、邮箱、电话、简介编辑，以及头像上传、更换和删除。复用 Vue / Element Plus、JWT、现有文件存储和保留期清理，不新增依赖。完整缺口清单仍有待办。

## 接口与权限

- `GET/PATCH /api/v1/auth/profile/` 只操作当前登录用户。PATCH 必填 `profile_version`，仅允许 `first_name`、`last_name`、`email`、`phone`、`bio`；未知字段整次拒绝，不能修改账号、密码、权限、状态或头像绑定。
- `GET/POST/DELETE /api/v1/auth/avatar/` 只读写本人托管头像。POST 为 multipart，DELETE 为 JSON，均必填资料版本。无需赋予普通用户一般文件管理权限。
- 保存资料、上传前登记、头像绑定和删除均在用户行锁内复核资料版本、账号状态、密码及会话版本。并发同版本写入只允许一次成功，其余 409。上传期间重置密码或删除账号不能完成绑定。
- 管理员用户 API 编辑个人字段会递增资料版本；Django 用户后台保存未编辑字段时保留当前数据库值，防止旧表单覆盖新头像或改密状态。
- 首次登录待改密账号仍受统一服务端业务门禁限制，不能通过个人中心绕过。

## 图片与生命周期

支持 PNG、JPEG、WebP，最大 5 MiB、400 万像素；校验真实格式及扩展名、完整解码、EXIF 方向处理，居中裁剪并重编码为 256×256 PNG，清除原图元数据和附加内容。原始上传不保存在媒体库。

头像存储在随机对象键下。文件记录标记 `purpose=avatar`，普通文件 API、回收站、仪表盘文件总数和 Django 文件后台排除头像。托管绑定字段在用户后台只读；旧的外部头像 URL 保留兼容数据，当前界面不加载该 URL。

读取经 JWT 鉴权，返回 PNG、`private, no-store`、`nosniff` 和限制性 CSP。前端通过共享请求获取 Blob，不在 URL 中放令牌；顶部和个人中心共用一次图片读取。更换、删除、登出和取消请求时回收旧 Object URL，迟到的请求不能恢复已撤销头像。

更换、删除以及删除用户会把旧头像软删除，记录删除时间，复用 `files.retention_days`（默认 30 天）与 `tasks.cleanup_soft_deleted_files`，存储清理失败保留记录并产生失败任务记录。当前仍被用户引用的文件禁止物理删除；历史头像不能通过一般回收站恢复，需重新上传。用户删除信号重新锁定当前用户绑定，覆盖陈旧实例与并发上传场景。

上传前先在短事务中校验用户并登记待清理记录，再写存储，最后在独立事务中绑定。存储或绑定失败尝试补偿清理；补偿失败保留待清理记录，避免把无元数据文件遗留给清理任务。数据库与对象存储不构成分布式事务，故障重试与保留期是恢复机制。

## 页面行为与可选模块

资料和头像各有加载、失败、重试、禁用状态。上传和删除不会覆盖尚未保存的文字；提交期间阻止重复操作。资料冲突保留输入，重新加载或撤销须确认；离开页面和关闭窗口提示未保存内容。凭据撤销、权限拒绝和强制改密重定向优先，不被未保存提示阻断。支持中英即时切换、明暗主题及手机宽度。

- `files` 关闭时，个人资料仍可编辑，头像 API 返回 404、前端禁用头像操作并隐藏图片；重新启用保留历史绑定。
- `tasks` 关闭时，退休头像不自动清理；重新启用后按原保留期补清理。仅启用 files 的项目应监测存储增长，不能把删除按钮等同于即时物理清除。
- 邮箱只是未验证的联系资料，本批未实现邮件验证、邮件发送或找回密码。未来找回密码必须先接入验证机制。
- 未保存提示本批只验收个人资料，不宣称全站编辑页面均已覆盖。

## 验收

- 后端全量 331 项 pytest，其中个人资料与头像 48 项；涵盖越权字段、非法请求、版本冲突、管理员编辑、图片格式/尺寸/元数据、私有读取、存储失败、补偿清理、旧头像保留、账号删除、改密撤销及模块关闭。
- Vitest 36 项；新增 API 契约、共享头像请求、取消、Object URL 回收、错误重试及陈旧账户快照保护。覆盖率统计仍仅针对既有 BaseForm / BaseTable / BaseDialog，不是全站覆盖率。
- Playwright 桌面/手机原有 96 项加本批 16 项；生产构建和生产 CSP 下运行，包含资料/头像完整流程、冲突保留、未保存确认、撤销凭据、语言切换及窄屏无横向溢出。
- 独立 PostgreSQL 18.6 / Nginx / 本地存储 93 项检查；本人资料并发、真实 multipart 图片读写、安全响应头，以及头像绑定/陈旧用户删除、删除/上传的双向行锁竞争通过。
- 真实 MinIO 5 条链路通过，头像读取、私有对象禁止匿名读取、备份枚举、替换/删除和过期清理实际经过 S3 协议。
- Django 检查、无遗漏迁移、OpenAPI 无警告校验；前端 ESLint、生产/测试类型检查、构建及 bundle 预算通过。登录初始 JS 约 140 KiB gzip，图表与 PDF 保持按需加载。

正式容器升级前执行停写数据库/媒体快照并生成 SHA-256 校验单；升级核对既有账户字段、权限、密码和会话状态保持一致，新增绑定默认为空、资料版本为 1。正式管理员人工浏览器重新登录仍未执行，按此前用户选择保留为未验证。

本机隔离测试证据保留在 `.codex-validation/profile-*` 和本批 `admincore-foundation-*`、`admincore-storage-*` 报告中；凭据、快照和私有验收目录不提交 Git。成功测试进程及测试容器按记录关闭，正式六服务保留运行。
