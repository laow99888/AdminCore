# 高级审批与流程设计

P2-05 为 `approvals` 模块增加了可发布的流程定义和运行时审批节点，同时保留原有“提交后指定一名审批人”的兼容入口。流程能力默认跟随审批模块启用，不新增队列或外部服务。

管理员也可以通过前端“审批流程设计器”页面编辑节点、审批人和连线并保存/发布；API 图定义接口继续保留给受信配置工具使用。配置只接受受校验的 JSON 图，不执行任意 SQL、脚本或表达式。

## 流程定义

管理员通过 `/api/v1/approvals/flows/` 创建草稿，并使用 `publish` 发布。定义是 JSON 图：

```json
{
  "nodes": [
    {"id": "start", "type": "start"},
    {"id": "review", "type": "parallel", "name": "部门会签", "mode": "all", "assignee_ids": ["用户 UUID"]},
    {"id": "end", "type": "end"}
  ],
  "edges": [{"from": "start", "to": "review"}, {"from": "review", "to": "end"}]
}
```

节点类型为 `start`、`user`、`parallel`、`or`、`end`。`parallel` 或 `mode=all` 表示会签，所有待处理人通过后进入下一节点；`or` 或 `mode=any` 表示或签，第一名通过后其余节点标记为跳过。任一审批人驳回会驳回申请。发布前会检查节点标识、端点、唯一开始/结束节点、可达性、环路、审批人和未知字段。

已发布版本不可直接修改；需要以新的草稿编码发布新流程。运行中的申请保存流程版本和当前节点，后续流程定义变更不会改变历史申请。

## 申请和操作 API

- `POST /api/v1/approvals/`：增加 `flow_id` 后按已发布流程实例化运行时节点；未填写时保持旧单级审批行为。
- `POST /api/v1/approvals/{id}/approve/`、`reject/`：处理当前流程节点，使用数据库行锁保证会签并发下只有一次状态迁移。
- `POST /api/v1/approvals/{id}/add-sign/`：当前审批人或管理员加签。
- `POST /api/v1/approvals/{id}/transfer/`：当前审批人转办，原审批人立即失去待办权限。
- `POST /api/v1/approvals/{id}/delegate/`：当前审批人委托，受托人可以处理当前节点，原审批人仍可查看。
- `POST /api/v1/approvals/{id}/cc/`：增加抄送人；重复抄送通过唯一约束幂等，所有动作写入 `ApprovalAction`。

流程设计、发布、归档只允许管理员或超级管理员。申请的列表、详情和操作会沿用申请人、当前审批人、待处理节点和委托人的数据边界。`ApprovalStep` 保存版本号、行动人和时间，`ApprovalAction` 保存追加式操作记录，便于审计和追踪。

## 验收

专项测试覆盖流程定义校验、发布不可修改、发布流程实例化、会签并发推进、或签跳过、加签、转办、委托、抄送和旧单级接口兼容。运行项目的严格 OpenAPI 生成和迁移检查时，应以实际命令输出为准；文档不把未执行的浏览器或生产环境验证标记为已完成。
