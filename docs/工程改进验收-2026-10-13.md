## 独立 PostgreSQL 基准

使用本任务单独创建的 PostgreSQL 18.6 容器和空库，装载 50,001 个用户、100,000 条操作日志、50,000 条任务、50,000 条文件元数据。正式业务库未注入压测数据。列表覆盖首页、每页 100 条、用户第 400 页、状态过滤和关键词查询，并保存 EXPLAIN ANALYZE/BUFFERS。

| 场景 | 修复前 p50 | 最终 p50 | 最终查询数 |
|---|---:|---:|---:|
| 用户首页 | 44.47ms | 14.72ms | 2 |
| 用户第 400 页 | 51.28ms | 25.13ms | 2 |
| 用户状态过滤 | 44.37ms | 16.70ms | 2 |
| 用户关键词 | 143.10ms | 141.31ms | 2 |
| 操作日志首页 | 155.14ms（102 查询） | 18.84ms | 2 |
| 任务首页 | 69.82ms | 17.68ms | 2 |
| 任务状态过滤 | 17.51ms | 17.20ms | 2 |
| 文件首页 | 24.30ms | 23.29ms | 2 |

新增用户/任务创建时间索引，实际查询计划命中对应迁移索引。操作日志与异常日志使用 select_related('user')，防止 N+1；查询上限纳入五个分页回归测试。8 并发、200 请求全部 200，约 63.39 请求/秒，p50 100.14ms、p95 233.69ms。两个并发互相改父节点请求结果为 200/400，无循环。

这是本机 Django APIClient + PostgreSQL 基准，排除了网络/TLS/JWT 验签，在独立测试进程中关闭限流；不能据此推断公网吞吐、长期稳定性或容量上限。关键词包含查询仍为顺序扫描，深分页仍有 OFFSET 成本。百万级数据、持续负载或更复杂搜索需求需要单独验收。

可复用脚本为 `backend/benchmarks/list_api.py`：仅连接 127.0.0.1、固定库名 admincore_benchmark_quality，从专用 ADMINCORE_BENCHMARK_PASSWORD 读取密码；默认拒绝已有用户的库。创建自己的空 PostgreSQL 容器后，在 backend 运行：

```powershell
python benchmarks/list_api.py --port 18432 --rows 50000 --output benchmark-report.json
```

`--verify-existing-fixtures` 仅允许重验本脚本创建的 benchmark_ 用户库。脚本不清空任何数据库；用完停止自己创建的容器。
